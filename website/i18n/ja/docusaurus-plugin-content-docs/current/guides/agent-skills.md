# エージェントスキル

エージェントスキルは、エージェントができることを Git リポジトリにまとめたものです。A2Flow はその目録を持ちます。レコードごとにリポジトリを指定すると、A2Flow がそれをクローンし、最新に保ちます。

管理サイドバーの**エージェントスキル**を開くと目録を管理できます。

![エージェントスキルの状態遷移図。登録するとバックグラウンドでクローンされ、「準備完了」か「失敗」になる。どちらの状態からもプルでやり直せ、「準備完了」のスキルから新しいワークフローを生成できる。](./img/agent-skills-lifecycle-dark.svg#gh-dark-mode-only)

スキルが使えるようになるのは、リビジョンが公開されてからです。それまでは、そのスキルからのワークフロー生成も実行も拒否されます。

## スキルのレコードが持つもの {#what-a-skill-record-holds}

| 項目 | 説明 |
|---|---|
| **名前** | ほかの画面でこのスキルを指す名前です。 |
| **リポジトリの URL** | クローンするリポジトリ。 |
| **リポジトリのパス** | スキルがリポジトリのルートにない場合の、その中での位置。 |
| **参照** | 任意。クローンとプルを固定するブランチ名かタグ名。空ならリポジトリの既定ブランチが使われます。 |
| **説明** | 自由入力。 |
| **認証ユーザー名** / **認証パスワード** | プライベートリポジトリ用。後述します。 |
| **タグ** | スキルを分類する[タグ](./tags.md)。 |

## ステータスとリビジョン {#status-and-revision}

一覧と詳細ページには 2 つの状態が出ます。意味は別々です。

| 列 | 何を表すか |
|---|---|
| **ステータス** | *直近*のクローンまたはプルの結果。`クローン中`、`準備完了`、あるいは理由つきの `失敗`。 |
| **リビジョン** | 現在公開されているリビジョン。これが入って初めてスキルは実行できます。 |

この 2 つは意図的に独立しています。プルが失敗しても公開済みのリビジョンは**消えません**。動いていたスキルは、それまでのリビジョンのまま動き続けます。変わるのはステータスとエラーだけです。

## プルする {#pulling}

**プル**は、設定された**参照**(なければ既定ブランチ)でリポジトリをクローンし直します。上流の変更を取り込む操作であり、URL や認証情報を直したあとに失敗した登録をやり直す操作でもあります。ブランチの先端が進んだり、タグの指す先が変わったりした場合は、次にプルしたときに反映されます。

ツリーのどこかに**シンボリックリンク**を含むリポジトリは受け付けません。クローンやプルはそのリンクを示す理由つきで失敗し、そこからリビジョンは公開されません。リンクは、指している先のファイルのコピーに置き換えてください。

公開されたリビジョンは、必要としているものがある限り残ります。ワークフロー実行は開始時のリビジョンに固定されるので、プルが進行中の実行の参照先を変えることはありません。保存場所と保持期間は[設定リファレンス](../operations/configuration.md#agent-skill-store)で扱います。

## プライベートリポジトリ {#private-repositories}

認証情報をスキルのフォームに直接入力することはありません。[シークレット](./secrets.md)として一度登録し、スキルからはその 1 エントリを指します。

1. **認証ユーザー名**を設定します。既定は `x-access-token` で、GitHub のパーソナルアクセストークン向けです。実際のアカウント名が必要なホストでは、それを設定します。
2. **認証パスワード**の 1 つ目のドロップダウンで**シークレット**を選び、2 つ目でその中の**エントリキー**を選びます。そのエントリの値が、クローン時のパスワードとして使われます。

**認証パスワード**を使うには、**リポジトリの URL**が `https://` で始まっている必要があります。`http://` だとパスワードが暗号化されずにネットワークを流れるので、保存は拒否されます。

どちらの種類のシークレットも選べます。Vault のシークレットは、エントリキーがローカルに保存されていないため、Vault から直接読み出されます。

参照は名前とキーとして保存され、クローンのときに解決されます。そのためシークレットをあとから削除したり改名したりしても、その場では失敗しません。次のプルが失敗し、理由がスキルに記録されます。詳細ページは、解決できなくなった参照を黙って落としたりはしません。選ばれたまま `(見つかりません)` と示され、警告が出ます。消すかどうかは利用者が決めます。

## スキルからワークフローを生成する {#generating-a-workflow-from-a-skill}

各行の操作列に**ワークフローを生成**があり、スキルの詳細ページのヘッダーにも同じ操作のアイコンボタンがあります。どちらも同じダイアログを開き、どちらもスキルがリビジョンを公開するまでは押せません。[ワークフローを生成する](./workflows.md#generating-a-workflow)を参照してください。

## SKILL.md を見る {#viewing-skillmd}

スキルの詳細ページのヘッダーには**SKILL.md を表示**アイコンボタンもあります。押すと、リポジトリに書かれたそのスキルの指示ファイルをダイアログで表示します。ワークフローを生成と同じく、スキルがリビジョンを公開するまでは押せません。クローンが成功して初めてファイルが存在するためです。上記の書き込み系の操作と違い、これは開発者ロールを持たない閲覧者にも表示されます。
