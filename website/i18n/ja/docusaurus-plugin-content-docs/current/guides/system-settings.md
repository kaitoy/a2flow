# システム設定

システム設定では、[通知メール](./notifications.md#email-delivery)を送るメールサーバーと、グローバルな HashiCorp Vault を設定します。設定のレコードはデプロイ全体でちょうど 1 つで、初回起動時にメール配信が**無効**の状態で投入されます。入れたばかりの環境では、運用者が有効にするまで通知はアプリ内だけに留まります。利用者が A2Flow を開くアドレスは、ここでは設定しません。運用者がデプロイ時に設定します。[サーバーの設定](../operations/configuration.md#server-settings)を参照してください。

管理サイドバーの**システム設定**を開きます。[テナント](./users-and-groups.md#tenants)と同じく、このセクションは**上位管理者**専用です。設定がテナント単位ではなくプラットフォーム全体のものなので、テナント管理者向けの例外はありません。ほかのロールからは読み取りも拒否されます。

## 設定項目 {#the-settings}

| 項目 | 用途 |
|---|---|
| **通知をメールで送信** | 全体のスイッチ。無効の間、通知はアプリ内だけに留まり、何も送られません。 |
| **SMTP ホスト** / **SMTP ポート** | メッセージを渡すリレー。 |
| **セキュリティ** | **STARTTLS**(既定)、**SSL/TLS**(暗黙の TLS)、**なし**のいずれか。 |
| **SMTP ユーザー名** / **SMTP パスワード** | SMTP AUTH の認証情報。認証の要らないリレーではユーザー名を空にします。 |
| **送信元アドレス** / **送信者名** | 送信者のアドレスと、その横に表示される任意の表示名。 |

ホストや送信者アドレスがないまま配信を有効にすることはできません。あとで黙って失敗する状態でフォームを保存することはできない、ということです。

ここにある項目はすべて環境変数からも設定できます。メールの設定を手作業の手順ではなくデプロイ設定として持てる、ということです([通知メール](../operations/configuration.md#notification-email))。これらの変数は毎回の起動で再適用されるので、そちらで設定した値はここで入力した内容を上書きします。

パスワードは**書き込み専用**です。[シークレット](./secrets.md)やユーザーのパスワードと同じ扱いで、表示されることはありません。保存済みのパスワードがある場合、この項目は空欄に「保存済み — 維持するには空欄のままにしてください」のプレースホルダーが出る形になり、空のまま保存すると、消えるのではなく保存済みの値が保たれます。

## グローバル Vault {#global-vault}

グローバル Vault は、**自分専用の Vault を持たない**テナントすべてが [Vault 型シークレット](./secrets.md)を読む HashiCorp Vault(KV v2 のみ)です。テナントの管理者は [テナント設定](./users-and-groups.md#tenant-vault) でテナント専用の Vault に接続でき、その場合は常にそちらが優先されます。

| 項目 | 用途 |
|---|---|
| **グローバル Vault のアドレス** | Vault のアドレス。`http://` か `https://` で始めます。テナント専用の Vault と違い、プライベートネットワーク上にあってもかまいません。空にして保存すると、グローバル Vault の接続を外します。 |

ここで設定するのはアドレスだけです。全テナント共用の認証情報はありません。各テナントは**テナントごとの認証情報**でログインし、その認証情報は上位管理者がテナントのページで登録します([グローバル Vault の認証情報](./users-and-groups.md#global-vault-credential)を参照)。認証情報のないテナントは、グローバル Vault をまったく読めません。

テナント間の分離は **Vault 自身**が行います。シークレットは、そのシークレットが指定した**Vault のマウント**と**Vault のパス**から読まれ、その読み取りを許すかどうかはテナントの認証情報に付いたポリシーが決めます。テナントごとに、そのテナントのデータだけを対象にしたポリシーの認証情報を発行してください。たとえばテナントごとに AppRole を作り、`acme` テナントには次のようなポリシーを付けます。

```hcl
path "secret/data/tenants/acme/*" {
  capabilities = ["read"]
}
```

## 設定を確認する {#checking-the-configuration}

**テストメールを送信**は、*保存済み*の設定を使ってテストメールを送ります。設定の誤りが、次にワークフローが通知を出すときではなく、その場で分かります。

1. 先に設定を保存します。テストが使うのは画面の内容ではなく保存済みの内容です。
2. **テストメールを送信**を押します。
3. 自分の受信箱を確認します。宛先はログインしている上位管理者自身のアドレスに固定されていて、ほかへは向けられません。

リレーが失敗した場合はページ上にエラーが出ます。原因はサーバー側のログに記録されます。
