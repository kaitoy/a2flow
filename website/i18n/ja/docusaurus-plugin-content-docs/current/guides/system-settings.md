# システム設定

システム設定では、[通知メール](./notifications.md#email-delivery)を送るメールサーバーを設定します。設定のレコードはデプロイ全体でちょうど 1 つで、初回起動時にメール配信が**無効**の状態で投入されます。入れたばかりの環境では、運用者が有効にするまで通知はアプリ内だけに留まります。

管理サイドバーの **System Settings** を開きます。[テナント](./users-and-groups.md#tenants)と同じく、このセクションは **Super Admin** 専用です。設定がテナント単位ではなくプラットフォーム全体のものなので、テナント管理者向けの例外はありません。ほかのロールからは読み取りも拒否されます。

## 設定項目 {#the-settings}

| 項目 | 用途 |
|---|---|
| **Application Base URL** | 通知メールのリンク先。たとえば `https://a2flow.example.com`。空ならリンクなしで送られます。 |
| **Send notifications by email** | 全体のスイッチ。無効の間、通知はアプリ内だけに留まり、何も送られません。 |
| **SMTP Host** / **SMTP Port** | メッセージを渡すリレー。 |
| **Security** | **STARTTLS**(既定)、**SSL/TLS**(暗黙の TLS)、**None** のいずれか。 |
| **SMTP Username** / **SMTP Password** | SMTP AUTH の資格情報。認証の要らないリレーではユーザー名を空にします。 |
| **From Address** / **From Name** | 送信者のアドレスと、その横に表示される任意の表示名。 |

ホストや送信者アドレスがないまま配信を有効にすることはできません。あとで黙って失敗する状態でフォームを保存することはできない、ということです。

ここにある項目はすべて環境変数からも設定できます。メールの設定を手作業の手順ではなくデプロイ設定として持てる、ということです([通知メール](../operations/configuration.md#notification-email))。これらの変数は毎回の起動で再適用されるので、そちらで設定した値はここで入力した内容を上書きします。

パスワードは**書き込み専用**です。[シークレット](./secrets.md)やユーザーのパスワードと同じ扱いで、表示されることはありません。保存済みのパスワードがある場合、この項目は空欄に「Saved」のプレースホルダーが出る形になり、空のまま保存すると、消えるのではなく保存済みの値が保たれます。

## 設定を確認する {#checking-the-configuration}

**Send test email** は、*保存済み*の設定を使ってテストメールを送ります。設定の誤りが、次にワークフローが通知を出すときではなく、その場で分かります。

1. 先に設定を保存します。テストが使うのは画面の内容ではなく保存済みの内容です。
2. **Send test email** を押します。
3. 自分の受信箱を確認します。宛先はサインインしている Super Admin 自身のアドレスに固定されていて、ほかへは向けられません。

リレーが失敗した場合はページ上にエラーが出ます。原因はサーバー側のログに記録されます。
