# システム設定

[http://localhost:3000/admin/system-settings](http://localhost:3000/admin/system-settings) で、[通知メール](./notifications.md#email-delivery)を送るメールサーバーを設定します。[テナント](./users-and-groups.md#tenants)と同じく、このセクションは**スーパー管理者**に限定されます。設定がテナント単位ではなくプラットフォーム全体のものなので、テナント管理者向けの例外はありません。バックエンドは書き込みだけでなく読み取りも、他者からのものを HTTP 403(`FORBIDDEN`)で拒否します。

設定レコードはデプロイ全体でちょうど 1 件です。初回起動時にメール配信が**オフ**の状態で投入されるので、入れたばかりの環境では、運用者が有効にするまで通知はアプリ内に留まります。

| フィールド | 用途 |
|---|---|
| `appBaseUrl` | 通知メールのリンク先。たとえば `https://a2flow.example.com`。空にするとリンクなしで送信します。 |
| `smtpEnabled` | 全体のスイッチ。オフのあいだ、通知はアプリ内に留まり何も送信されません。 |
| `smtpHost` / `smtpPort` | メッセージを渡すリレー先。 |
| `smtpSecurity` | `starttls`(既定)、`ssl`(暗黙の TLS)、`none` のいずれか。 |
| `smtpUsername` / `smtpPassword` | SMTP AUTH の認証情報。認証の要らないリレーではユーザー名を空にします。 |
| `smtpFromEmail` / `smtpFromName` | 送信元アドレスと、その横に表示する任意の表示名。 |

パスワードは**書き込み専用**です。[シークレット](./secrets.md)やユーザーのパスワードと同じ扱いで、Fernet の暗号文として保存され、API から返ることはありません。そのためフォームでは、保存済みのパスワードがあると欄が空になり「Saved」のプレースホルダーが出ます。空のまま保存すれば、消えるのではなく保存済みの値が保たれます。ホストや送信元アドレスがない状態で配信を有効にしようとすると HTTP 422(`INVALID_SYSTEM_SETTINGS`)で拒否されます。

**テストメールを送信**ボタンは、*保存済みの*設定で決まったテストメッセージを配信します。設定の誤りが、次にワークフローが通知を上げたときではなくその場で分かります。宛先はサインイン中のスーパー管理者自身のアドレスにサーバー側で固定されていて、ほかへ向けることはできません。リレーが失敗した場合は HTTP 502(`EMAIL_SEND_FAILED`)が返り、原因はサーバー側のログにだけ記録されます。

`appBaseUrl` と `smtpHost` は、[エージェントスキル](./agent-skills.md)のリポジトリ URL や [MCP サーバー](./mcp-servers.md)の URL が通る SSRF のホストチェックを意図的に通しません。どちらもデプロイ自身のネットワーク内のホストを正当に指しますし、呼び出し元の代わりに取得しにいくものでもないからです。
