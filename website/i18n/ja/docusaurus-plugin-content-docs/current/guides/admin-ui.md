# 管理画面

管理エリアは [http://localhost:3000/admin](http://localhost:3000/admin) にあります。

## ウェルカムページ {#welcome-page}

[http://localhost:3000/admin](http://localhost:3000/admin) がウェルカムページです。管理画面のシェル(サイドバーとアプリバー)の中に描画され、新規チャット(スーパー管理者のみ。[チャットセッションへのアクセス](../concepts/authorization.md)を参照)と、そのユーザーのロールで開ける管理セクションへのクイックアクションカードが並びます。サイトのルート(`/`)を開いたとき、サインインした直後、どの画面からでもアプリバーの **A2Flow** ロゴを押したときに、ここに着きます。

管理画面の一覧テーブルには共通の機能があります。**列ごとの並べ替えと絞り込み**(一覧 API の `s` と `q` クエリパラメータでサーバー側に適用するので、現在のページだけでなくデータ全体が対象になります)、**ドラッグによる列幅の変更**(セッション中は保たれますが、永続化はしません)、列幅で切り詰められたセルの全文を出す**ホバー時のツールチップ**です。

レコードに**詳細ページ**がある場合、一覧の識別子列からそこへリンクします。詳細ページはそのレコードのための唯一の画面で、属性に加えて、そのレコードが持つすべての操作(編集の保存、削除、そしてレコード種別ごとの操作。ワークフローの公開やスキルのリポジトリの pull など)が置かれます。詳細ページのタイトルは操作名ではなく**レコード自身の名前**で、その上のパンくずも同じ名前で終わります。つまり `Admin › Workflows › my-workflow` と読め、最後より前のパンくずはすべて上位へのリンクになります。[ワークフロー実行](./workflow-executions.md)だけは例外です。実行は編集するレコードではなく履歴なので、行からはワークフローセッションか、読み取り専用のタスク一覧が開きます。

各テーブルには**列ピッカー**もあります。更新ボタンの隣にある ▥ ボタンで、そのテーブルが出せる列がすべて並び、「すべて表示」「すべて非表示」の一括切り替えと「既定に戻す」があります。パネルは必ず画面に収まります。下に余地がなければボタンの上に開き、一括切り替えと既定に戻す操作を画面内に留めたまま列の一覧だけを内部でスクロールし、切り替え可能な列が 8 を超えると 2 列に分かれます。おかげで一番幅の広い一覧(17 列あるエージェントスキル)でも、縦の狭いノート PC の画面から全部に手が届きます。テーブルごとに既定のセットがあり、一部の列(MCP サーバーのトランスポート、シークレットの参照、エージェントスキルの ref とリビジョン、ユーザーのメールアドレスと確認済みフラグ)は最初から隠れています。重要な列に幅を回すためです。識別子列と操作列は常に表示され、一覧には出てきません。選択はテーブルごとにブラウザのローカルストレージへ記憶されるので、再読み込みしても残ります。保存するのは既定からのずれだけなので、あとから増えた列はきちんと既定の状態で現れます。並べ替えや絞り込みに使っている列を隠すと、その並べ替えや絞り込みは解除されます。画面に出ていない基準で行が並んだり絞られたりしないようにするためです。

## 一覧のクエリパラメータ {#list-query-parameters}

コレクションのエンドポイントは共通の `limit` と `offset`、並べ替え(`s`)、絞り込み(`q`)のクエリパラメータを受け取ります。フィールド名は camelCase です。詳細は [.claude/rules/api-conventions.md](https://github.com/kaitoy/a2flow/blob/master/.claude/rules/api-conventions.md) にあります。
