# タグ

[http://localhost:3000/admin/tags](http://localhost:3000/admin/tags) でテナントの**タグ**を整えます。[シークレット](./secrets.md)、[MCP サーバー](./mcp-servers.md)、[エージェントスキル](./agent-skills.md)、[ワークフロー](./workflows.md)の分類に使うラベルです。タグの集合は 4 つで 1 つを共有するので、`aws` というタグはシークレットも MCP サーバーも同じように絞り込みます。

| 操作 | パス |
|-----------|------|
| タグの一覧 | `GET /admin/tags` |
| タグの新規作成 | `GET /admin/tags/new` |
| タグの詳細ページ(名前の変更・色の変更・削除) | `GET /admin/tags/{id}` |

タグは**名前**(テナント内で一意)と、8 スロットの固定パレットから選んだ**色**([DESIGN.md](https://github.com/kaitoy/a2flow/blob/master/DESIGN.md#colors) を参照)を持ちます。任意の色の値は拒否されます。書き込みには `admin` **または** `developer` が必要です。タグを付けられる 4 つのリソースのいずれかに書き込めるロールの和集合にそろえてあるので、タグが必要になった人がその場で作れます。読み取りはほかのセクションと同じく開いています。

**名前の変更はいつでも安全です。** レコードはタグを名前ではなく ID で参照するので、そのタグを持つすべてのレコードが新しい名前に追従し、再同期は要りません。レコードごとに自由入力させず、タグを先に登録する仕組みにしている理由がこれです。逆に、タグを**削除**するとそのタグを持っていたすべてのレコードから外れます。参照があることで削除がブロックされるわけではありません。確認ダイアログにもそう書いてあります。

**タグを付ける。** タグを付けられるリソースの作成フォームと詳細ページには**タグ**のピッカーがあり、形は[ユーザーグループ](./users-and-groups.md#user-groups)のピッカーと同じです。現在の選択が削除できる色付きチップとして**タグを選択…** ボタンの上に並ぶので、このフィールドの高さは語彙の量ではなく選択の量で決まります。ボタンを押すと、語彙全体を折り返しの色付きチップのグリッドとして持つダイアログが開きます。各チップはトグルで、押された状態では塗りが濃くなり*かつ*先頭にチェックが付くので、状態が色だけに依存しません。グリッドを絞る 2 つのフィルタは組み合わせて効きます。名前の入力欄と、8 色の色見本の並びです。色見本はいくつでも同時に押せます(すべて解除した状態がクリアです)。選択は**選択**で確定するまで下書きで、**キャンセル**で破棄されます。いったん選んだタグは、そのあとフィルタで見えなくなっても選択されたままです。

タグの付与はレコードのサブリソースです(`PUT /api/v1/{resource}/{id}/tags` に `{"tagIds": [...]}` を送り、集合をまるごと置き換えます)。ゲートはそのリソース自身の書き込みロールで、タグを作るのに必要なロールとは独立です。したがってタグ付きのレコードの作成は、作成のあとにこの呼び出しを続けることになります。編集時は選択が実際に変わったときだけ書き込みます。

**タグで絞り込む。** タグを付けられる一覧にはすべて**タグ**列があり、各レコードのチップが出ます。列ヘッダーのメニューから複数選択できます。選択は**論理積**です。レコードは選んだ*すべて*のタグを持っていなければならないので、追加するほど結果は狭まります。メニューにも「Filter (all of)」と出ます。繰り返し可能な `?tag=<id>` クエリパラメータでサーバー側に適用されるので([.claude/rules/api-conventions.md](https://github.com/kaitoy/a2flow/blob/master/.claude/rules/api-conventions.md) を参照)、現在のページだけでなくデータ全体が対象です。タグはほかの列フィルタとは別の軸です。列ピッカーでタグ列を隠すとタグの絞り込みも解除されます。ほかの列を隠すとその列の絞り込みが解除されるのと同じです。
