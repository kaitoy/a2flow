# 監査ログ

監査ログは、A2Flow があなたの代わりに何をしたかの記録を 4 種類まとめて見る場所です。エージェントが呼んだツール、ある人が別の人として操作したセッション、承認が与えた権限、送ったメール。どれも追記専用で、この画面から記録を書き換えたり消したりはできません。それが証跡たりうる理由です。

管理サイドバーの**監査ログ**を開きます。表の上に 4 つのタブが並びます。

| タブ | 1 行の意味 |
|---|---|
| **ツールの呼び出し** | MCP ゲートウェイがツール呼び出し 1 件について下した判断 |
| **代理ログイン** | 管理者が別のユーザーとして操作したセッション 1 件 |
| **証明書** | 各タスクのツール呼び出しを支えている権限 |
| **メール** | 配信待ちに積まれた通知メール 1 通 |

どの一覧も他の管理画面の表と同じで、並べ替え、絞り込み、列の選択、ページ送りが使えます([管理 UI](./admin-ui.md#the-list-screen))。行の最初のセルを押すと読み取り専用の詳細ページが開き、表のセルでは切れてしまう長い値を確認できます。

## 誰が見られるか {#who-sees-it}

このセクションが表示されるのは**管理者**と**上位管理者**だけです。それ以外の人にはアクセス拒否の画面が出ますし、サイドバーにも現れません。

ほとんどのセクションは読み取りだけなら誰でもできますが、ここはそれより厳しくしています。この一覧はテナント内のすべての実行・アカウント・メッセージにまたがるので、「自分が関わった実行の記録が見える」という参加者向けの権限では足りないためです。狭い範囲の画面はこれまでどおり残っています。実行 1 件のツール呼び出しはその実行の [ツールの呼び出し](./workflow-executions.md#tool-invocations) のページに、承認の証明書はその[承認](./approvals.md)のページにあります。ただし、誰にも承認を求めなかったタスクに出た証明書まで見えるのは、この一覧だけです。

上位管理者にはテナント切り替えで選んでいるテナントの分が見えます。**すべてのテナント**を選べば全テナントを横断して見られ、そのときは各一覧の一番左に**テナント**列が増えます。

## ツールの呼び出し {#tool-invocations}

MCP ゲートウェイまで届いたツール呼び出しと、それぞれについて下した判断です。上流に流れた `許可` と、規則が止めた `拒否` があります。

| 列 | 説明 |
|---|---|
| **ツール** / **サーバー** | 何を呼んだか、どこへ呼んだか |
| **判断** | `許可` か `拒否` |
| **拒否の理由** | 拒否された呼び出しについて、規則が述べた理由そのもの |
| **ワークフロー実行** | その呼び出しが属する実行(リンクします) |
| **承認** / **証明書** | その呼び出しが提示した証明書と、承認が出したものならその承認 |
| **引数のダイジェスト** | 呼び出しが何を要求したかの指紋 |

引数そのものは保存しません。残すのは、提示された署名が覆っている指紋だけです。おかげで、呼び出しが何を運んだかを保持しないまま、記録された呼び出しをあとから検証できます。詳細ページでは指紋の全体、署名、署名された時刻を確認できます。

[モック](./tool-mocks.md)されたツールへの呼び出しは、結果がどうであれここには出ません。差し替えられた呼び出しはどのサーバーにも届かないからです。それらを確認する場所は実行のチャットの記録です。

## 代理ログイン {#impersonations}

管理者が別のユーザーとして操作したセッションが 1 行ずつ並びます。開始から終了までが 1 件です。**終了日時**が空の行はまだ続いているセッションで、**有効**と表示されます。

| 列 | 説明 |
|---|---|
| **代理ログインした人** | 操作した人(アカウントにリンクします) |
| **対象ユーザー** | 誰として操作したか(アカウントにリンクします) |
| **状態** | セッション中は**有効**、終わると**終了** |
| **開始日時** / **終了日時** | 始まった時刻と終わった時刻 |

行の絞り込みは、操作した人ではなく**代理ログインされた**アカウントのテナントで行います。これは意図的です。上位管理者はどのテナントにも属さないので、操作した人で絞るとその人のセッションがどのテナントからも見えなくなってしまいます。管理者が最も見たいのはまさにそれです。詳しくは[代理ログイン](../concepts/impersonation.md)を参照してください。

## 証明書 {#certificates}

タスク 1 件が実際に何を呼んでよかったかの記録です。ツール呼び出しはどれも証明書を提示するので、この一覧は、ツールを呼ぶ権限が与えられ、そして使い切られた記録のすべてです。誰にも承認を求めなかったタスクの分も含みます。

タスクが証明書を受け取る瞬間は 2 つのうちのどちらかで、**権限**の列がそれを示します。

| 権限 | 発行されるとき | 付与者 |
|---|---|---|
| **承認者** | そのタスクの[承認](./approvals.md)が許可されたとき | 許可した承認者 |
| **実行の開始者** | 承認を求めないまま、そのタスクが**進行中**にされたとき | その実行を始めた人 |

| 列 | 説明 |
|---|---|
| **シリアル** | 証明書を識別する値。ツールの呼び出しの一覧で、それを提示した呼び出しに表示される値と同じです |
| **権限** | **承認者**か**実行の開始者**か。許可がどこから来たかです |
| **付与者** | その許可を出した人 |
| **承認** | 発行のもとになった承認(リンクします)。実行を始めた人の許可には承認が無いので空欄です |
| **状態** | **進行中**、権限を使い切ると**失効済み** |
| **許可されたツール** | この証明書が認めるツール |
| **有効期間の開始** / **有効期間の終了** | 有効な期間 |
| **失効日時** / **失効理由** | いつ、なぜ有効でなくなったか |

**許可されたツール**は別に保存した控えではなく、発行された証明書そのものから読み直して表示します。そのため、実行中にタスクの結びつきが書き換えられたとしても、この画面が示す内容と実際に認められた内容が食い違うことはありません。鍵は一切表示されませんし、取り出すこともできません。

## メール {#emails}

A2Flow が配信待ちに積んだ通知メールと、その結果です。

| 列 | 説明 |
|---|---|
| **宛先** / **件名** | 宛先と件名 |
| **ステータス** | `保留中`、`送信中`、`送信済み`、`失敗` |
| **試行回数** | これまでの送信試行回数 |
| **送信日時** | 送信された時刻 |
| **最後のエラー** | 直近の試行が失敗した理由 |

配信できなかったメッセージは `失敗` になり、削除されず**残ります**。届かなかった通知が理由つきで見え続けるようにするためです。本文は送信時ではなく通知が作られた時点で確定するので、詳細ページには実際に配信されたとおりの本文が全文表示されます。

`送信済み` か `失敗` の行は上位管理者なら削除できます。管理者にはできません。まだ `保留中` や `送信中` の行はどちらでも拒否されます。メール送信の処理が掴んでいる最中かもしれないからです。メールが積まれるまでの流れは[通知](./notifications.md)を、経由するメールサーバーについては[システム設定](./system-settings.md)を参照してください。
