# 監査ログ

監査ログは、A2Flow があなたの代わりに何をしたかの記録を 4 種類まとめて見る場所です。エージェントが呼んだツール、ある人が別の人として操作したセッション、承認が与えた権限、送ったメール。どれも追記専用で、この画面から記録を書き換えたり消したりはできません。それが証跡たりうる理由です。

管理サイドバーの **Audit Logs** を開きます。表の上に 4 つのタブが並びます。

| タブ | 1 行の意味 |
|---|---|
| **Tool Invocations** | ツールプロキシがツール呼び出し 1 件について下した判断 |
| **Impersonations** | 管理者が別のユーザーとして操作したセッション 1 件 |
| **Certificates** | 各タスクのツール呼び出しを支えている権限 |
| **Emails** | 配信待ちに積まれた通知メール 1 通 |

どの一覧も他の管理画面の表と同じで、並べ替え、絞り込み、列の選択、ページ送りが使えます([管理 UI](./admin-ui.md#the-list-screen))。行の最初のセルを押すと読み取り専用の詳細ページが開き、表のセルでは切れてしまう長い値を確認できます。

## 誰が見られるか {#who-sees-it}

このセクションが表示されるのは **Admin** と **Super Admin** だけです。それ以外の人にはアクセス拒否の画面が出ますし、サイドバーにも現れません。

ほとんどのセクションは読み取りだけなら誰でもできますが、ここはそれより厳しくしています。この一覧はテナント内のすべての実行・アカウント・メッセージにまたがるので、「自分が関わった実行の記録が見える」という参加者向けの権限では足りないためです。狭い範囲の画面はこれまでどおり残っています。実行 1 件のツール呼び出しはその実行の [Tool Invocations](./workflow-executions.md#tool-invocations) のページに、承認の証明書はその[承認](./approvals.md)のページにあります。ただし、誰にも承認を求めなかったタスクに出た証明書まで見えるのは、この一覧だけです。

Super Admin にはテナント切り替えで選んでいるテナントの分が見えます。**All tenants** を選べば全テナントを横断して見られ、そのときは各一覧の一番左に **Tenant** 列が増えます。

## Tool Invocations {#tool-invocations}

プロキシまで届いたツール呼び出しと、それぞれについて下した判断です。上流に流れた `allowed` と、規則が止めた `denied` があります。

| 列 | 説明 |
|---|---|
| **Tool** / **Server** | 何を呼んだか、どこへ呼んだか |
| **Decision** | `allowed` か `denied` |
| **Denial Reason** | 拒否された呼び出しについて、規則が述べた理由そのもの |
| **Workflow Execution** | その呼び出しが属する実行(リンクします) |
| **Approval** / **Certificate** | その呼び出しが提示した証明書と、承認が出したものならその承認 |
| **Arguments Digest** | 呼び出しが何を要求したかの指紋 |

引数そのものは保存しません。残すのは、提示された署名が覆っている指紋だけです。おかげで、呼び出しが何を運んだかを保持しないまま、記録された呼び出しをあとから検証できます。詳細ページでは指紋の全体、署名、署名された時刻を確認できます。

[モック](./tool-mocks.md)されたツールへの呼び出しは、結果がどうであれここには出ません。差し替えられた呼び出しはどのサーバーにも届かないからです。それらを確認する場所は実行のチャットの記録です。

## Impersonations {#impersonations}

管理者が別のユーザーとして操作したセッションが 1 行ずつ並びます。開始から終了までが 1 件です。**Ended At** が空の行はまだ続いているセッションで、**Active** と表示されます。

| 列 | 説明 |
|---|---|
| **Impersonator** | 操作した人(アカウントにリンクします) |
| **Target User** | 誰として操作したか(アカウントにリンクします) |
| **State** | セッション中は **Active**、終わると **Ended** |
| **Started At** / **Ended At** | 始まった時刻と終わった時刻 |

行の絞り込みは、操作した人ではなく**なりすまされた**アカウントのテナントで行います。これは意図的です。Super Admin はどのテナントにも属さないので、操作した人で絞るとその人のセッションがどのテナントからも見えなくなってしまいます。管理者が最も見たいのはまさにそれです。詳しくは[なりすまし](../concepts/impersonation.md)を参照してください。

## Certificates {#certificates}

タスク 1 件が実際に何を呼んでよかったかの記録です。ツール呼び出しはどれも証明書を提示するので、この一覧は、ツールを呼ぶ権限が与えられ、そして使い切られた記録のすべてです。誰にも承認を求めなかったタスクの分も含みます。

タスクが証明書を受け取る瞬間は 2 つのうちのどちらかで、**Authority** の列がそれを示します。

| Authority | 発行されるとき | Granted By |
|---|---|---|
| **Approver** | そのタスクの[承認](./approvals.md)が許可されたとき | 許可した承認者 |
| **Run initiator** | 承認を求めないまま、そのタスクが**進行中**にされたとき | その実行を始めた人 |

| 列 | 説明 |
|---|---|
| **Serial** | 証明書を識別する値。Tool Invocations の一覧で、それを提示した呼び出しに表示される値と同じです |
| **Authority** | **Approver** か **Run initiator** か。許可がどこから来たかです |
| **Granted By** | その許可を出した人 |
| **Approval** | 発行のもとになった承認(リンクします)。実行を始めた人の許可には承認が無いので空欄です |
| **State** | **Live**、権限を使い切ると **Revoked** |
| **Allowed Tools** | この証明書が認めるツール |
| **Not Before** / **Not After** | 有効な期間 |
| **Revoked At** / **Revocation Reason** | いつ、なぜ有効でなくなったか |

**Allowed Tools** は別に保存した控えではなく、発行された証明書そのものから読み直して表示します。そのため、実行中にタスクの結びつきが書き換えられたとしても、この画面が示す内容と実際に認められた内容が食い違うことはありません。鍵は一切表示されませんし、取り出すこともできません。

## Emails {#emails}

A2Flow が配信待ちに積んだ通知メールと、その結果です。

| 列 | 説明 |
|---|---|
| **To** / **Subject** | 宛先と件名 |
| **Status** | `pending`、`sending`、`sent`、`failed` |
| **Attempts** | これまでの送信試行回数 |
| **Sent At** | 送信された時刻 |
| **Last Error** | 直近の試行が失敗した理由 |

配信できなかったメッセージは `failed` になり、削除されず**残ります**。届かなかった通知が理由つきで見え続けるようにするためです。本文は送信時ではなく通知が作られた時点で確定するので、詳細ページには実際に配信されたとおりの本文が全文表示されます。

`sent` か `failed` の行は Super Admin なら削除できます。Admin にはできません。まだ `pending` や `sending` の行はどちらでも拒否されます。メール送信の処理が掴んでいる最中かもしれないからです。メールが積まれるまでの流れは[通知](./notifications.md)を、経由するメールサーバーについては[システム設定](./system-settings.md)を参照してください。
