# 따라 하기

이 페이지에서는 [데모](./demo-data.md) 워크플로 하나를 처음부터 끝까지 진행합니다. 에이전트 스킬에서 생성하고, 게시하고, 실행하고, 도중에 올라오는 요청을 승인하고, 결과를 확인하기까지 한 번도 로그아웃하지 않습니다. `root`로 로그인한 뒤 [대리 로그인](../concepts/impersonation.md)으로 각 데모 계정을 차례로 맡으므로, 전체 과정이 브라우저 탭 하나로 끝납니다.

여기에서 제공자를 선택하세요. 이 페이지의 제공자별 블록은 모두 이 선택을 따릅니다.

<Tabs groupId="provider" queryString>
  <TabItem value="aws" label="AWS">

  `Demo AWS EC2 Launch` 스킬로 EC2 인스턴스를 시작합니다.

  </TabItem>
  <TabItem value="gcp" label="Google Cloud">

  `Demo GKE Pod Restart` 스킬로 GKE 클러스터의 워크로드를 롤링 재시작합니다.

  </TabItem>
  <TabItem value="azure" label="Azure">

  `Demo Azure Key Vault Secret Rotation` 스킬로 Azure Key Vault의 시크릿을 교체합니다.

  </TabItem>
</Tabs>

## 시작하기 전에 \{#before-you-start\}

- [데모 데이터](./demo-data.md)를 활성화한 상태로 백엔드가 실행 중이어야 합니다.
- `root` 비밀번호를 알고 있어야 합니다. `ROOT_PASSWORD`이거나, 설정하지 않았다면 시작할 때 백엔드가 로그에 한 번 출력한 줄입니다([초기 사용자](../operations/configuration.md#seeded-users)).
- 제공자에 실제로 접근할 수 있어야 합니다.

<Tabs groupId="provider" queryString>
  <TabItem value="aws" label="AWS">

  `demo-aws-credentials` [시크릿](../guides/secrets.md)에 실제 액세스 키가 들어 있어야 합니다. 최초 시작 전에 `DEMO_AWS_ACCESS_KEY_ID` / `DEMO_AWS_SECRET_ACCESS_KEY`를 설정했거나, **시크릿**에서 해당 시크릿을 편집하면 됩니다. 실행하면 **실제 EC2 인스턴스가 시작되며**, 종료할 때까지 비용이 발생합니다.

  이 키의 IAM 사용자에게는 AMI를 확인하고, 네트워크와 키 페어를 조회하고, 인스턴스를 시작할 수 있는 정책이 필요합니다. 다음 정책이면 충분합니다.

  ```json
  {
    "Version": "2012-10-17",
    "Statement": [
      {
        "Sid": "ResolveAmi",
        "Effect": "Allow",
        "Action": "ssm:GetParameter",
        "Resource": "arn:aws:ssm:*::parameter/aws/service/*"
      },
      {
        "Sid": "LookupAndLaunch",
        "Effect": "Allow",
        "Action": [
          "ec2:DescribeImages",
          "ec2:DescribeVpcs",
          "ec2:DescribeSubnets",
          "ec2:DescribeSecurityGroups",
          "ec2:DescribeKeyPairs",
          "ec2:DescribeInstances",
          "ec2:RunInstances",
          "ec2:CreateTags"
        ],
        "Resource": "*"
      }
    ]
  }
  ```

  첫 번째 명령문은 AWS가 최신 AMI ID를 게시하는 공개 파라미터만 읽으며, 사용자 계정의 파라미터는 읽지 않습니다. 이 정책으로는 키로 인스턴스를 종료할 수 없으므로, 종료는 AWS 콘솔에서 직접 하세요.

  </TabItem>
  <TabItem value="gcp" label="Google Cloud">

  `demo-gcp-credentials` [시크릿](../guides/secrets.md)에 GKE 클러스터에 접근할 수 있는 ID의 Google Cloud 자격 증명이 들어 있어야 합니다. 최초 시작 전에 `DEMO_GCP_CREDENTIALS_JSON`을 설정했거나, **시크릿**에서 해당 시크릿을 편집하면 됩니다. 프로젝트, 클러스터, 클러스터의 리전, 재시작해도 되는 워크로드를 준비해 두세요. 실행하면 **실제로 롤링 재시작이 이루어집니다**.

  </TabItem>
  <TabItem value="azure" label="Azure">

  `demo-azure-credentials` [시크릿](../guides/secrets.md)에 실제 서비스 주체가 들어 있어야 합니다. 최초 시작 전에 `DEMO_AZURE_TENANT_ID` / `DEMO_AZURE_CLIENT_ID` / `DEMO_AZURE_CLIENT_SECRET`을 설정했거나, **시크릿**에서 해당 시크릿을 편집하면 됩니다. 서비스 주체에는 볼트의 시크릿을 나열하고 쓸 수 있는 역할이 필요합니다. 기본 제공 **Key Vault Secrets Officer** 역할은 모든 시크릿의 값까지 읽을 수 있으므로, 이보다는 `Microsoft.KeyVault/vaults/secrets/readMetadata/action` 및 `Microsoft.KeyVault/vaults/secrets/setSecret/action` 데이터 작업만 있는 사용자 지정 역할을 권장합니다. 그러면 에이전트가 설득당해 시도하더라도 값을 읽을 수 없습니다. 액세스 정책을 사용하는 볼트라면 시크릿 권한 중 **List**와 **Set**만 부여하세요. 해당 볼트와 그 안의 교체해도 되는 시크릿을 준비해 두세요. 실행하면 **실제로 시크릿의 새 버전이 쓰이며**, 현재 버전을 읽는 모든 곳이 새 값을 사용하게 됩니다.

  </TabItem>
</Tabs>

쓸 수 있는 계정이 없나요? 미리 등록된 [도구 모의](./demo-data.md#trying-it-out)를 사용하면 제공자에 접속하지 않고도 같은 워크플로를 끝까지 진행할 수 있습니다. 이 경로에서는 워크플로가 아직 `초안`일 때 실행하므로 아래의 게시 단계를 건너뜁니다.

## 등장인물 \{#the-cast\}

| 단계 | AWS | Google Cloud | Azure | 역할 |
|---|---|---|---|---|
| 워크플로 생성 | `demo-aws-developer` | `demo-gcp-developer` | `demo-azure-developer` | 개발자 |
| 게시 | `demo-aws-reviewer` | `demo-gcp-reviewer` | `demo-azure-reviewer` | 검토자 |
| 실행 및 결과 확인 | `demo-aws-requester` | `demo-gcp-requester` | `demo-azure-requester` | 요청자 |
| 요청 승인 | `demo-approver-1` | `demo-approver-1` | `demo-approver-1` | 승인자 |

아래의 각 단계는 **사용자** 목록의 **대리 로그인**으로 시작하여 헤더의 "…(으)로 작업 중" 칩에 있는 **대리 로그인 중지**로 끝납니다. 중지는 생략할 수 없습니다. 이 계정들로 작업하는 동안에는 해당 계정의 역할을 적용받는데, 어느 계정도 대리 로그인 권한이 없으므로 중지할 때까지 **대리 로그인**이 다시 표시되지 않습니다. 채팅 화면에서는 앱 바의 **A2Flow** 로고를 누르면 환영 페이지와 사이드바로 돌아갑니다.

## 1. root로 로그인 \{#1-sign-in-as-root\}

1. 로그인 페이지에서 **사용자 이름**에 `root`를 입력하고, **테넌트**는 비워 둔 채(`root`는 플랫폼 관리자이며 어떤 테넌트에도 속하지 않습니다) 비밀번호를 입력합니다. **로그인**을 누릅니다.
2. 환영 페이지가 열립니다. 앱 바의 테넌트 전환기에 데모 데이터가 있는 테넌트인 **Default**가 표시됩니다. 다른 테넌트가 선택되어 있으면 Default를 선택하세요.

## 2. 개발자로 작업하며 워크플로 생성 \{#2-act-as-the-developer-and-generate-the-workflow\}

1. 관리 사이드바에서 **사용자**를 열고 개발자 행의 **대리 로그인**을 누릅니다. **사용자로 대리 로그인** 대화 상자에서 **대리 로그인**을 눌러 확정합니다. 환영 페이지로 돌아오고, 헤더 칩에 "`demo-…-developer`(으)로 작업 중"이라고 표시됩니다.
2. **에이전트 스킬**을 엽니다. 이 제공자의 스킬만 표시되며, 나머지는 [액세스 제어 태그](../guides/tags.md#access-control-tags) 때문에 숨겨져 있습니다. **상태**가 `준비됨`이 될 때까지 기다리세요. `복제 중`인 동안에는 목록을 새로 고치세요. 그때까지 **워크플로 생성**은 비활성화되어 있습니다.

:::info[AWS: 가격표 먼저 읽기]

**지식 베이스**를 열고 **AWS EC2 Pricing**을 클릭합니다. 소스는 `ec2-on-demand-pricing.pdf` 하나이며 **읽지 않음**으로 표시됩니다. **읽기**를 클릭하고 상태가 **준비됨**이 될 때까지 기다리세요. LLM이 가격표를 페이지로 변환하는 중이며, 변환된 내용은 **페이지**에 나타납니다. 1~2분 걸립니다([지식 베이스](../guides/knowledge-bases.md)). 다음 단계에서는 **워크플로 생성** 대화 상자의 **지식 베이스 선택…** 버튼도 클릭하여 **AWS EC2 Pricing**을 선택하세요. 그러면 실행의 에이전트가 가격을 조회할 수 있습니다.

:::

3. 해당 행의 **워크플로 생성**을 누릅니다. **워크플로 이름**은 그대로 두고, 아래 프롬프트를 **프롬프트**에 붙여 넣은 다음 **생성**을 누릅니다.

<Tabs groupId="provider" queryString>
  <TabItem value="aws" label="AWS">

  ```text
  요청자에게 원하는 파라미터와 시작 날짜 및 시간을 물어보고, Demo Approvers 그룹의 승인을 받은 다음, 해당 시간에 EC2 인스턴스를 시작합니다.
  인스턴스 유형은 다음 중에서 선택하게 합니다.
  - t4g.nano
  - t4g.micro
  - t4g.small
  - t4g.medium
  - t3.micro
  - t3a.micro
  - c6g.medium
  - m6g.medium
  - t2.micro
  - t4g.large

  리전은 다음 중에서 선택하게 합니다.
  - us-east-1
  - us-east-2
  - us-west-2

  AMI는 요청된 리전의 최신 Amazon Linux 2023 이미지를 사용합니다.
  기본 VPC, 서브넷, 보안 그룹을 사용합니다.
  키 페어는 만들지 않습니다.
  승인을 요청하기 전에 AMI, VPC, 서브넷 ID를 확인합니다.
  요청된 시간 전에는 인스턴스를 시작하지 않습니다.
  인스턴스 비용에 관한 질문에는 AWS EC2 Pricing 지식 베이스를 바탕으로 답하고, 승인 요청에는 이 지식 베이스에서 확인한 요청 인스턴스의 월간 비용을 포함합니다.
  ```

  </TabItem>
  <TabItem value="gcp" label="Google Cloud">

  세 자리 표시자를 자신의 프로젝트, 클러스터, 리전으로 바꾸세요.

  ```text
  <your project name> 프로젝트의 <your cluster name> 클러스터에 있는 워크로드를 Demo Approvers의 승인을 받은 후 재시작합니다.
  클러스터 위치는 <cluster region> 리전입니다. 워크로드의 네임스페이스는 실제 클러스터에서 가져온 목록에서 요청자가 선택하게 합니다.
  ```

  </TabItem>
  <TabItem value="azure" label="Azure">

  자리 표시자를 자신의 볼트 이름으로 바꾸세요.

  ```text
  <your vault name> Key Vault의 시크릿을 Demo Approvers의 승인을 받은 후 교체합니다.
  볼트의 시크릿을 나열하고 교체할 시크릿을 요청자가 선택하게 합니다.
  새 값은 Secret Value Generator로 생성하고, 채팅에는 절대 표시하지 않습니다.
  ```

  </TabItem>
</Tabs>

4. 새 워크플로의 상세 페이지가 상태 `생성 중`으로 열립니다. 페이지는 저절로 새로 고쳐지며, 1~2분 후 상태가 `초안`으로 바뀌고 벨에 "워크플로 초안이 준비되었습니다" 알림이 표시됩니다. **작업 템플릿**을 열면 디자인 에이전트가 작성한 단계를 볼 수 있습니다. 파라미터 수집, 승인 요청, 작업 수행, 결과 보고 순서입니다([워크플로 생성](../guides/workflows.md#generating-a-workflow)).
5. "…(으)로 작업 중" 칩의 **대리 로그인 중지**를 누릅니다.

## 3. 검토자로 작업하며 게시 \{#3-act-as-the-reviewer-and-publish\}

1. **사용자**에서 검토자 행의 **대리 로그인**을 누르고 확정합니다.
2. **워크플로**를 열고 워크플로 이름을 클릭합니다. 작업 템플릿을 살펴보세요. 검토자는 **디자인 세션 열기**로 디자인 대화를 읽을 수도 있지만, 대화에 개입할 수는 없습니다.
3. **게시**를 누릅니다. 상태가 `게시됨`으로 바뀝니다. 디자인이 고정되고 이제 요청자가 실행할 수 있습니다([게시](../guides/workflows.md#publishing)).
4. **대리 로그인 중지**를 누릅니다.

## 4. 요청자로 작업하며 실행 \{#4-act-as-the-requester-and-run-it\}

1. **사용자**에서 요청자 행의 **대리 로그인**을 누르고 확정합니다.
2. **워크플로**를 열고 워크플로의 **실행**을 누릅니다. **워크플로 실행** 대화 상자에는 모의 항목이 없습니다. 게시된 워크플로이므로 이것은 실제 요청입니다. **실행**을 누릅니다.
3. 워크플로 세션이 열리고 에이전트가 첫 번째 작업을 시작하여, 프롬프트가 요청자에게 맡긴 내용을 묻습니다. 정해진 답이 있는 질문은 메시지 안의 선택지로 표시되고, 그 외에는 입력란 위에 [추천 답변](../guides/workflow-executions.md#suggested-replies) 행이 나타납니다.

<Tabs groupId="provider" queryString>
  <TabItem value="aws" label="AWS">

  어떤 인스턴스 유형을 고를지 모르겠다면 물어보세요. 예를 들어 "us-east-2에서 t4g.medium의 월 비용은 얼마이고, t3.micro와 비교하면 어떤가요?"라고 묻습니다. 에이전트는 **AWS EC2 Pricing** 지식 베이스에서 가격을 찾아보고 참고한 페이지를 알려 줍니다.

  프롬프트의 10가지 중에서 인스턴스 유형을, 3가지 중에서 리전을 선택합니다. 과정이 지체되지 않도록 시작 시간은 몇 분 뒤로 지정하고, 인스턴스 이름 등 그 밖에 묻는 내용에도 답합니다. 그러면 에이전트가 해당 리전의 최신 Amazon Linux 2023 이미지와 기본 VPC 및 서브넷을 조회하고, 구성과 시작 시간을 요약하여 승인 요청을 보냅니다.

  </TabItem>
  <TabItem value="gcp" label="Google Cloud">

  에이전트가 클러스터에서 가져온 목록에서 네임스페이스를 선택하고, 재시작할 Deployment 또는 StatefulSet의 이름을 알려 줍니다. 에이전트는 워크로드를 조회하여 종류를 확인하고, 대상을 요약하여 승인 요청을 보냅니다.

  </TabItem>
  <TabItem value="azure" label="Azure">

  에이전트가 볼트의 시크릿을 나열하기 전에 실행이 사용자를 기다립니다. 채팅 입력란 위의 안내에 이 작업이 질문을 할 것이라고 표시됩니다. **재개**를 누릅니다. 그러면 Azure MCP Server가 확인을 요청하며, 채팅에 "Azure MCP Server에서 확인을 요청합니다"라는 제목의 카드가 나타납니다. **Approve**를 선택하고 **수락**을 누릅니다([MCP 서버의 확인 요청](../guides/workflow-executions.md#mcp-server-confirmations)). 그런 다음 에이전트가 가져온 목록에서 교체할 시크릿을 선택합니다. 에이전트는 볼트와 시크릿을 요약하여 승인 요청을 보냅니다.

  </TabItem>
</Tabs>

4. 요청은 **Demo Approvers** 그룹으로 전달되고, 그 아래 채팅에 "승인자 그룹의 결정을 기다리는 중입니다."라고 표시됩니다. 요청자는 이 요청을 결정할 수 없습니다. 이제 실행이 대기합니다.
5. **대리 로그인 중지**를 누릅니다.

## 5. 승인자로 작업하며 승인 \{#5-act-as-the-approver-and-approve\}

1. **사용자**에서 `demo-approver-1`의 **대리 로그인**을 누르고 확정합니다. `demo-approver-2`여도 괜찮습니다. 그룹 요청은 첫 번째 결정으로 확정됩니다.
2. 도구 모음의 벨에 읽지 않은 알림 하나, 즉 승인 요청이 표시됩니다. 클릭하면 실행의 채팅이 열립니다. 사이드바의 **승인**에서 해당 행의 **워크플로 세션 열기**를 눌러도 같은 곳으로 이동합니다.
3. 요청을 읽습니다. 에이전트의 요약 아래 **승인 대상**에 이 결정이 허용하게 될 호출과 입력값의 범위가 나열됩니다([요청이 승인하는 대상](../guides/approvals.md#what-a-request-authorizes)).

<Tabs groupId="provider" queryString>
  <TabItem value="aws" label="AWS">

  **AWS MCP Server**에서 인스턴스를 시작하는 호출입니다. 이 호출과 요약의 시작 시간 및 월간 비용을 요청자가 선택한 내용과 대조하세요. 이미지, VPC, 서브넷 조회는 요청 전에 실행되었고 승인이 필요 없었으므로 나열되지 않습니다.

  </TabItem>
  <TabItem value="gcp" label="Google Cloud">

  **GKE MCP Server**의 `patch_k8s_resource` 호출로, 요청자가 선택한 네임스페이스와 워크로드를 가리킵니다.

  </TabItem>
  <TabItem value="azure" label="Azure">

  **Azure MCP Server**의 `keyvault_secret_create` 호출로, 요청자가 선택한 볼트와 시크릿을 가리킵니다. 새 값은 요청에 들어 있지 않습니다. 에이전트는 승인을 받은 뒤에야 값을 생성합니다.

  </TabItem>
</Tabs>

4. 결정하기 전에 더 알고 싶은 것이 있나요? 채팅에 질문을 입력하여 보내세요. 예를 들어 AWS 탭에서는 "이 인스턴스를 평일 업무 시간에만 실행하면 월 비용이 얼마인가요?"라고 묻습니다. 세션이 사용자의 결정을 기다리는 중이므로 **상담** 탭이 열리고, 에이전트가 요청의 맥락과 연결된 지식 베이스를 바탕으로 그 탭에서 답합니다([상담](../guides/workflow-executions.md#consultations)). 요청자도 이 대화에 참여할 수 있습니다. 끝나면 **기본** 탭을 클릭하여 요청으로 돌아갑니다.
5. 필요하면 **댓글**을 남기고 **승인**을 누릅니다. 상담을 열었다면 이 결정으로 상담도 종료됩니다. 같은 채팅에서 실행이 재개되고, 에이전트가 작업을 수행한 다음 요청자에게 결과 확인을 요청합니다. 이 질문에 답하는 것은 요청자입니다. 승인자에게는 입력란이 읽기 전용으로 표시되고, 그 아래에 "시작자의 응답을 기다리는 중입니다."라고 표시됩니다.

<Tabs groupId="provider" queryString>
  <TabItem value="aws" label="AWS">

  시작 시간이 아직 되지 않았다면 에이전트는 시작을 대기 상태로 두고, 언제 계속할지 한 줄로 알린 뒤 일시 중지합니다. 해당 시간이 되면 세션이 저절로 재개되고(채팅을 계속 열어 둘 필요는 없습니다) 에이전트가 인스턴스를 시작합니다([워크플로 세션 화면](../guides/workflow-executions.md#the-workflow-session-screen)).

  </TabItem>
  <TabItem value="gcp" label="Google Cloud">

  에이전트가 바로 워크로드를 재시작합니다.

  </TabItem>
  <TabItem value="azure" label="Azure">

  쓰기 작업은 요청자에게 확인을 요청하므로, 실행은 시작하기 전에 요청자가 채팅으로 돌아오기를 기다립니다. 세션에 **시작자 대기 중**이 표시되고 요청자에게 알림이 갑니다.

  </TabItem>
</Tabs>

6. **대리 로그인 중지**를 누릅니다.

## 6. 다시 요청자로: 결과 확인 \{#6-back-as-the-requester-confirm-the-result\}

1. **사용자**에서 요청자 행의 **대리 로그인**을 다시 누르고 확정합니다.
2. **워크플로 실행**을 열고 해당 실행의 **워크플로 세션 열기**를 누릅니다.
3. 에이전트는 수행한 작업을 보고하고 사용자를 기다리고 있습니다.

<Tabs groupId="provider" queryString>
  <TabItem value="aws" label="AWS">

  지정한 시작 시간이 지나면 인스턴스 ID와 상태가 보고됩니다. 원한다면 AWS 콘솔에서 인스턴스를 확인한 뒤 채팅에서 확인했다고 답하세요.

  </TabItem>
  <TabItem value="gcp" label="Google Cloud">

  에이전트가 지켜본 롤아웃이 끝나면 교체된 Pod 수가 보고됩니다. 채팅에서 확인했다고 답하세요.

  </TabItem>
  <TabItem value="azure" label="Azure">

  먼저 쓰기 전에 실행이 사용자를 기다립니다. 채팅 입력란 위의 안내에서 **재개**를 누릅니다. 에이전트가 새 값을 생성하고 쓰기를 시작하면 Azure MCP Server의 확인 카드가 나타납니다. **Approve**를 선택하고 **수락**을 누릅니다. 그런 다음 에이전트가 새 버전이 만들어진 시점을 보고합니다. 값 자체는 절대 보고하지 않습니다. Azure MCP Server는 버전 ID를 보고하지 않으므로, 필요하면 Azure Portal에서 시크릿의 버전을 확인한 뒤 채팅에서 확인했다고 답하세요.

  </TabItem>
</Tabs>

4. 에이전트가 요약으로 마무리하고, 마지막 작업이 완료되면 실행이 `완료됨`으로 바뀌며, 벨에 완료 알림이 표시됩니다.
5. **대리 로그인 중지**를 누릅니다.

## 마친 후 \{#afterwards\}

<Tabs groupId="provider" queryString>
  <TabItem value="aws" label="AWS">

  인스턴스는 AWS 콘솔에서 종료할 때까지 계속 실행되며 비용이 발생합니다.

  </TabItem>
  <TabItem value="gcp" label="Google Cloud">

  정리할 것이 없습니다. 워크로드는 새 Pod로 원래 레플리카 수를 회복했습니다.

  </TabItem>
  <TabItem value="azure" label="Azure">

  시크릿의 이전 버전은 여전히 활성화되어 있습니다. 이 시크릿을 읽는 모든 곳이 새 값을 사용하게 되면 Azure Portal에서 이전 버전을 비활성화하세요. 새 값은 Key Vault로 가는 과정에서 에이전트의 대화를 거쳤으므로([데모 데이터](./demo-data.md)), 이 실행의 채팅은 시크릿과 동일하게 취급하세요.

  </TabItem>
</Tabs>

이 과정에서 남은 기록 중 살펴볼 만한 것이 두 가지 있습니다.

| 위치 | 보여 주는 내용 |
|---|---|
| **감사 로그** → **대리 로그인** | 방금 연 모든 세션입니다. 누가 누구로서 언제 작업했는지 보여 줍니다. 위의 쓰기 작업은 모두 대리 로그인한 계정의 작업으로 기록되므로, "실제로 누가 했는가"에 답해 주는 것이 바로 이 기록입니다([감사 추적](../concepts/impersonation.md#audit-trail)) |
| 실행의 **도구 호출** 페이지 | 실행이 수행한 각 도구 호출과 제시한 인증서입니다. 작업을 수행한 호출을 풀어 준 것은 사용자가 내린 승인입니다([도구 호출](../guides/workflow-executions.md#tool-invocations)) |
