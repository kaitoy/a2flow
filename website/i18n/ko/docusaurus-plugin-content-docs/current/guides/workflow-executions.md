# 워크플로 실행

워크플로 실행은 [워크플로](./workflows.md)를 한 번 실행한 것입니다. 실행은 워크플로의 이름, 설명, 작업, 태그의 사본을 자체적으로 보관하므로, 원본 워크플로를 나중에 편집하거나 삭제해도 실행 기록은 실제로 실행된 내용 그대로 남습니다.

관리 사이드바에서 **워크플로 실행**을 열어 둘러볼 수 있습니다. 다른 섹션과 달리 실행은 편집할 레코드가 아니라 기록이므로 편집 양식이 없습니다. 실행 화면은 실행 내용을 보여 주거나 실행에 참여하게 해 줄 뿐입니다. **태그** 열과 필드가 읽기 전용인 것도 같은 이유입니다. [워크플로 실행과 승인의 태그](./tags.md#execution-and-approval-tags)를 참조하세요.

| 화면 | 이동 방법 | 표시 내용 |
|---|---|---|
| **워크플로 실행** 목록 | 관리 사이드바 → 워크플로 실행 | 모든 실행과 상태, 행별 동작 |
| **워크플로 세션** | 행의 워크플로 세션 열기 동작 | 실행이 진행되는 채팅. 참여하고, 지켜보고, 응답할 수 있습니다 |
| **워크플로 작업** | 행의 작업 링크 | 실행의 작업과 상태. 읽기 전용이며 표 또는 그래프로 표시됩니다 |
| **도구 호출** | 실행 상세 헤더 | 실행이 수행한 MCP 도구 호출과 각 호출의 판정 결과 |

**모의됨**은 [도구 모의](./tool-mocks.md)로 도구를 하나라도 스텁 처리한 실행을 나타냅니다.

[**열** 메뉴](./admin-ui.md#choosing-columns)에는 처음에 숨겨져 있는 열이 두 개 더 있습니다. **워크플로**는 실행의 상위 워크플로를 현재 이름으로 표시하고 그 워크플로로 연결합니다. 각 행의 이름은 실행이 시작될 때 고정된 스냅샷이므로, 그 워크플로의 현재 이름은 이 열에서 확인합니다. **초안**은 [테스트 실행](./workflows.md#running-a-workflow)에 체크 표시를 합니다. 테스트 실행은 아직 `초안`인 워크플로에서 시작했거나 `수정됨` 워크플로의 [게시되지 않은 편집](./workflows.md#trying-the-edits-out)으로 시작한 실행입니다. 어느 쪽이든 아무도 승인하지 않은 디자인을 실행한 것이므로 [운영 메트릭](../operations/metrics.md)에서 제외됩니다. 이 열은 예/아니요 필터로 사용해 테스트 실행을 숨길 수 있습니다.

실행 상세 페이지에는 **버전**이 표시됩니다. 실행이 작업을 복사해 온 워크플로의 게시된 버전(예: `v3`)이며, 테스트 실행은 어떤 버전에도 기록되지 않은 디자인을 실행했으므로 `—`로 표시됩니다. [버전 기록과 롤백](./workflows.md#version-history)을 참조하세요.

## 실행 상태 {#run-status}

![실행이 실행 중으로 시작하고, 시간만 기다리는 동안 예약됨으로 바뀌었다가 재개되면 돌아오며, 모든 작업이 끝났을 때 실패가 없으면 완료됨, 실패가 하나라도 있으면 실패로 확정되는 것을 보여 주는 상태 전이도.](./img/workflow-executions-status.svg#gh-light-mode-only)
![실행이 실행 중으로 시작하고, 시간만 기다리는 동안 예약됨으로 바뀌었다가 재개되면 돌아오며, 모든 작업이 끝났을 때 실패가 없으면 완료됨, 실패가 하나라도 있으면 실패로 확정되는 것을 보여 주는 상태 전이도.](./img/workflow-executions-status-dark.svg#gh-dark-mode-only)

실행은 `실행 중`으로 시작하며, 작업이 하나 이상 있고 모든 작업이 최종 상태인 `완료됨`, `실패`, `건너뜀` 중 하나에 이르면 확정됩니다. 실패한 작업이 포함된 실행은 `실패`로 끝납니다. 종료 시각은 그 순간 기록되며 이후 편집해도 바뀌지 않습니다. 작업이 전혀 없는 실행은 `실행 중`으로 남습니다. [운영 메트릭](../operations/metrics.md)에서 집계하는 수치가 바로 이 값입니다.

끝나지 않은 실행이 시간을 기다리는 것 말고는 할 일이 없을 때, 즉 작업이 대기를 요청해 해당 세션에 **…까지 예약됨**이 표시되고 다른 모든 세션이 유휴 상태이거나 완료되었을 때는 실행이 `실행 중` 대신 `예약됨`으로 표시됩니다. 시간이 되거나 누군가 메시지를 보내 세션이 재개되면 바로 `실행 중`으로 돌아갑니다. [운영 메트릭](../operations/metrics.md)은 `예약됨` 실행을 `실행 중` 실행과 마찬가지로 활성 상태로 집계합니다.

작업이 실패하면 그 작업을 직접 또는 연쇄적으로 기다리는 모든 작업은 더 이상 실행될 수 없으므로 `건너뜀`으로 설정됩니다. 덕분에 실행은 영영 시작되지 않을 작업에 묶이지 않고 확정될 수 있습니다. 실패한 작업에 종속되지 않은 분기의 작업은 영향을 받지 않으므로, 실패 후에도 이 작업들이 끝날 때까지 실행이 한동안 `실행 중`일 수 있습니다.

## 워크플로 세션 화면 {#the-workflow-session-screen}

워크플로 세션은 한 번의 실행이 진행되는 채팅입니다. 세션을 열면 실행의 시작 메시지가 있고 에이전트는 이미 작업 중입니다. 실행은 만들어지는 즉시 시작되므로, 이 화면을 열든 열지 않든 진행됩니다.

![워크플로 세션 화면 배치를 보여 주는 순서도. 작업 타임라인과 작업별로 묶인 메시지가 나란히 있고, 메시지 다음에 채팅 입력란이 이어진다.](./img/workflow-executions-layout.svg#gh-light-mode-only)
![워크플로 세션 화면 배치를 보여 주는 순서도. 작업 타임라인과 작업별로 묶인 메시지가 나란히 있고, 메시지 다음에 채팅 입력란이 이어진다.](./img/workflow-executions-layout-dark.svg#gh-dark-mode-only)

### 공유 대상 {#who-shares-it}

실행의 채팅은 시작한 사람만의 것이 아니라 **참여자들이 공유**합니다.

| 대상 | 이용 범위 |
|---|---|
| 실행을 시작한 **시작자** | 전체 대화와 채팅 입력란 |
| 해당 실행의 [승인](./approvals.md)에 **지정된 승인자** | 같은 대화와 상태. 승인하면 비어 있는 새 실행이 시작되는 것이 아니라 원래 실행이 재개됩니다. 승인자가 직접 처리할 수 있는 것은 자신의 승인뿐입니다. 에이전트가 다른 단계를 위해 렌더링한 입력 양식이나 [MCP 서버가 요청하는 확인](#mcp-server-confirmations)은 읽기 전용이며, 그 아래에 "시작자의 응답을 기다리는 중입니다."라는 안내가 표시됩니다 |
| 테넌트의 **관리자** | 읽기 전용 열람 |
| 그 밖의 사람 | 액세스 불가 |

승인이 **그룹**에 지정되면 승인자 역할을 가진 모든 구성원이 참여자가 되므로, 채팅의 참여 범위는 그룹의 구성원을 따라갑니다. 승인자 그룹에 사람을 추가하면 그 그룹에 승인이 요청된 모든 실행이 해당 사용자에게 열리고, 제거하면 다시 닫힙니다. 이는 "어느 구성원이든 처리할 수 있다"는 규칙의 직접적인 결과입니다. 채팅 액세스는 결정을 내릴 수 있게 하려고 있는 것입니다. 승인자 역할이 없는 구성원은 그룹에 속해 있어도 아무런 권한을 얻지 못합니다.

### 보낸 사람 아바타 {#sender-avatars}

요청자, 승인자, 에이전트 등 여러 참여자가 한 채팅에 글을 올리므로 모든 메시지에는 **보낸 사람 아바타**가 붙습니다. 아바타에 마우스를 올리면 보낸 사람의 이름이 표시되고, 에이전트 배지에 올리면 워크플로 이름이 표시됩니다. 렌더링된 대화형 화면 안의 버튼을 클릭한 경우도 같은 방식으로 기록되어, 클릭이 처리되면 해당 사용자의 아바타가 그 화면 옆에 표시됩니다.

### 작업 타임라인 {#the-task-timeline}

왼쪽 가장자리에는 접을 수 있는 **작업 타임라인**이 있습니다. 실행의 작업이 순서대로 나열되고, 각 작업에는 상태별 색상의 번호 배지가 붙으며, 진행 중인 작업은 강조됩니다. 채팅에서는 같은 작업에 속하는 연속된 메시지를 **작업 그룹**으로 묶습니다. 작업 그룹에는 상태별 색상의 왼쪽 세로줄과 타임라인 배지와 같은 번호의 제목이 있어 작업의 경계를 한눈에 알 수 있습니다.

둘은 양방향으로 연결되어 있습니다.

- 채팅을 스크롤하면 뷰포트 맨 위에 있는 작업이 타임라인에서 강조됩니다.
- 타임라인 항목이나 채팅 그룹에 마우스를 올리면 대응하는 상대편이 강조됩니다.
- 타임라인 항목을 클릭하면 채팅이 해당 작업의 그룹으로 스크롤됩니다.

### 실시간 업데이트 {#live-updates}

실행을 보고 있는 모든 참여자는 각 답변이 작성되는 과정을 실시간으로 볼 수 있습니다. 누구의 메시지로 시작된 답변이든 마찬가지이며, 시작 메시지, 승인 후 재개, 시간을 기다리던 세션의 재개처럼 A2Flow가 직접 실행하는 턴도 포함됩니다. 답변이 시작되면(직접 보낸 메시지에 대한 답변이면 스크롤 위치와 관계없이, 다른 사람의 메시지에 대한 답변이면 맨 아래 근처에 있을 때) 채팅은 최신 메시지가 화면 맨 위에 오도록 한 번만 스크롤하고, 답변은 그 아래의 빈 공간에 작성됩니다. 작성되는 동안에는 답변이 화면 아래로 넘쳐도 화면이 움직이지 않습니다. 답변 중이 아닐 때는 이미 맨 아래 근처로 스크롤되어 있을 때만 새 메시지를 따라 맨 아래로 이동하며, 위로 스크롤해 이전 메시지를 읽는 동안에는 스크롤되지 않습니다. 화면 아래 보이지 않는 곳에 새 메시지가 도착하거나 답변 작성이 끝나면 채팅 하단에 **아래에 새 메시지가 있습니다** 버튼이 나타납니다. 클릭하면 최신 메시지로 이동하며, 답변이 아직 작성 중이면 작성이 끝날 때까지 화면이 따라갑니다.

보낸 메시지는 에이전트를 기다립니다. 에이전트가 아직 턴을 처리하는 중이면 메시지가 거부되며, 답변이 끝난 후 다시 보낼 수 있습니다. 승인을 기다리는 세션은 메시지를 받지 않습니다. 세션을 다음으로 진행시키는 것은 승인 결정이기 때문입니다. 이때 보낸 질문은 대신 [상담](#consultations)으로 전달됩니다.

[디자인 세션](./workflows.md#adjusting-the-task-templates)도 같은 아바타가 표시되는 공유 채팅입니다. 다만 실행의 참여자가 아니라 테넌트의 개발자들이 공유하며, 다른 사람의 답변이 작성되는 과정을 보여 주는 대신 몇 초마다 자동으로 새로 고쳐집니다.

### 분기 세션 {#branch-sessions}

실행의 작업 그래프가 분기하면 A2Flow는 분기들이 함께 진행되도록 실행을 여러 세션으로 나눌 수 있습니다. [병렬 분기](../architecture/workflow-execution.md#parallel-branches)를 참조하세요. 이 경우 이동 경로 아래에 세션별 탭이 나타나고, 각 탭에는 상태가 표시됩니다.

| 탭 | 설명 |
|---|---|
| **기본** | 실행이 시작된 세션입니다. 합류 지점과 완료된 분기 다음의 작업을 처리합니다 |
| **분기 1**, **분기 2**, … | 분기 세션입니다. 분기가 준비되었을 때 해당 세션이 사용 중이어서 포크된 세션입니다 |
| **상담 1**, … | [상담](#consultations)입니다. 세션이 승인을 기다리는 동안 받은 질문으로 열립니다 |

| 상태 | 의미 |
|---|---|
| 대기열 | 곧 턴이 시작됩니다 |
| 실행 중 | 에이전트가 작업 중입니다 |
| 입력 대기 중 | 입력 양식이 답변을 기다리고 있습니다 |
| 승인 대기 중 | 이 세션이 요청한 승인이 아직 결정되지 않았습니다 |
| 시작자 대기 중 | 다음 작업이 실행 중에 [시작자에게 질문](#mcp-server-confirmations)하므로, 시작자가 채팅에서 재개하기를 기다립니다 |
| …까지 예약됨 | 작업이 시간을 기다려야 합니다. 표시된 시간에 세션이 자동으로 재개되며, 메시지를 보내면 일찍 재개됩니다 |
| 유휴 | 지금은 할 일이 없으며, 세션이 다음 작업을 기다립니다 |
| 완료됨 | 세션이 작업을 마쳤습니다. 완료된 분기는 기본 세션에 요약을 남깁니다 |
| 오류 | 마지막 턴이 실패했습니다 |

탭을 클릭하면 해당 세션의 채팅이 열립니다. 화면은 선택한 세션을 따라가며 URL에도 선택이 유지되므로, 이 페이지로 연결되는 링크를 열면 같은 탭이 열립니다. 분기하지 않고 상담도 없는 실행에는 탭이 표시되지 않습니다.

### 상담 {#consultations}

승인을 기다리는 세션은 메시지를 받지 않지만, 인스턴스 비용은 얼마인지, 왜 이 대상을 선택했는지처럼 요청에 대한 질문이 생길 수 있습니다. 세션이 기다리는 동안 채팅 입력란 위에는 질문이 상담으로 전달된다는 안내가 표시됩니다.

1. 대기 중인 세션의 채팅에 질문을 입력하고 보냅니다.
2. 질문이 담긴 **상담** 탭이 열리고 에이전트가 그곳에서 답합니다. 에이전트는 대기 중인 세션이 승인 요청 시점까지 알고 있던 모든 내용을 바탕으로 시작하며, 워크플로에 연결된 [지식 베이스](./knowledge-bases.md)도 읽을 수 있습니다. MCP 서버의 도구는 사용할 수 없으므로, 대상 시스템을 새로 살펴봐야 하는 질문은 실행이 계속될 때까지 기다려야 합니다.
3. 해당 탭에서 계속 질문하세요. 채팅을 공유하는 사람은 누구나 그곳에 글을 쓸 수 있으므로, 승인자와 실행을 시작한 사람이 요청에 대해 서로 논의할 수도 있습니다. 각 메시지에는 보낸 사람이 표시됩니다.
4. 평소처럼 승인을 결정합니다. 결정하면 상담이 닫히고, 탭은 **완료됨**으로 바뀌며 더 이상 메시지를 받지 않습니다.

| 상담 | |
|---|---|
| 할 수 있는 일 | 요청의 컨텍스트, 연결된 지식 베이스, 실행의 작업과 승인, 세션의 파일을 바탕으로 답변 |
| 할 수 없는 일 | MCP 서버 도구 사용, 작업 변경, 승인 요청, 대기 예약, 파일 추가 |
| 남는 것 | 실행에는 아무것도 남지 않습니다. 대기 중인 세션은 그곳에서 나눈 대화를 보지 못하며, 대화는 탭에서 계속 읽을 수 있습니다 |

같은 승인이 결정되기 전에 한 추가 질문은 같은 상담으로 전달됩니다.

### 추천 답변 {#suggested-replies}

에이전트가 질문을 하거나, 값을 묻거나, 진행 승낙이 필요해 응답을 기다리며 멈추면 채팅 입력란 위에 **추천 답변**이 한 줄로 나타납니다. `네, 진행해 주세요`나 `이 단계는 건너뛰어 주세요`처럼 에이전트가 예상하는 짧은 답변 몇 개입니다.

| | |
|---|---|
| **하나를 클릭하면** | 해당 텍스트가 채팅 입력란에 들어갑니다. 전송되지는 않으므로 편집하거나 그대로 보내면 됩니다 |
| **에이전트가 작업하는 동안** | 줄이 숨겨지며, 에이전트의 다음 질문과 함께 다시 나타납니다 |
| **답변한 후** | 줄이 사라지고, 다음 질문에는 새 추천 답변이 함께 표시됩니다 |
| **새로 고친 후** | 메시지를 보낼 수 있는 모든 참여자에게 같은 줄이 표시됩니다 |

추천 답변은 사용자가 입력할 내용을 에이전트가 짐작한 것이며, 허용되는 답변을 정해 둔 메뉴가 아닙니다. 답이 정해진 질문은 대신 메시지 안의 선택지로 묻습니다. 이 줄은 워크플로 세션의 기능이며 디자인 세션에는 없습니다.

### MCP 서버의 확인 요청 {#mcp-server-confirmations}

일부 MCP 서버는 도구 호출 도중에 멈추고, 계속하기 전에 사람에게 무언가를 묻습니다. 예를 들어 Azure MCP Server는 Key Vault 시크릿에 대한 모든 작업 전에 동의를 구합니다. 이런 도구는 워크플로 디자인에서 **시작자에게 질문하는 도구**로 표시합니다. 워크플로를 생성할 때나 디자인 세션에서 어떤 작업의 도구가 질문하는지 디자인 에이전트에게 알려 주세요. 표시되지 않은 도구는 질문할 수 없으며, 호출은 기다리지 않고 실패합니다.

표시된 도구를 사용하는 작업은 질문이 왔을 때 시작자가 자리에 있도록, 시작하기 전에 실행의 시작자를 기다립니다.

1. 실행이 해당 작업에 이르면 세션에 **시작자 대기 중**이 표시되고 시작자는 입력 요청 [알림](./notifications.md)을 받습니다. 그동안 시간 제한에 걸리는 것은 없습니다.
2. 시작자가 실행의 채팅을 엽니다. 채팅 입력란 위에 작업 이름을 알리는 안내와 **재개** 버튼이 표시됩니다. 다른 사람에게는 실행이 시작자를 기다린다는 것만 표시됩니다.
3. **재개**를 누르면 시작자의 이름으로 메시지가 전송되고 작업이 시작됩니다. 시작자가 직접 메시지를 입력해 보내도 마찬가지입니다.
4. 각 질문은 채팅에 "*서버*에서 확인을 요청합니다"라는 제목의 카드로 나타나며, 응답을 기다리는 도구의 이름과 작은 양식이 함께 표시됩니다.


| | |
|---|---|
| **답변하는 사람** | 실행의 시작자만 답변합니다. 승인자와 관리자에게는 질문과 그 아래의 "시작자의 응답을 기다리는 중입니다."가 표시됩니다 |
| **수락** | 양식의 값을 보냅니다. 값의 의미는 서버가 정합니다. Azure MCP Server의 양식은 **Approve**와 **Reject** 중에서 선택합니다 |
| **거절** | 답변을 거부합니다 |
| **취소** | 선택하지 않고 질문을 닫습니다 |
| **기다리는 동안** | 에이전트의 턴이 아직 실행 중이므로 채팅 입력란은 비활성화된 상태로 유지됩니다 |
| **아무도 답하지 않으면** | 질문이 만료됩니다. 배포에서 [달리 설정하지](../operations/configuration.md#mcp-tools-and-approvals) 않았다면 15분 후에 만료되며, 서버에는 질문이 닫혔다고 전달됩니다 |

카드는 질문한 턴에 속합니다. 그 턴이 끝난 후에는 채팅에 있는 도구 호출 줄이 결과를 기록합니다.

### 세션의 파일 {#files-in-the-session}

워크플로 세션에는 메시지뿐만 아니라 파일도 담을 수 있습니다. 채팅 입력란 옆의 **클립** 버튼으로 첨부하거나 입력란 아무 곳에나 파일을 끌어다 놓으세요. 각 파일은 입력란 위에 칩으로 표시되며, 칩의 ×를 누르면 제거됩니다. 메시지를 보내기 전에는 아무것도 전송되지 않으므로, 칩을 제거하면 해당 파일은 실행에 전달되지 않고 그대로 빠집니다.

보낸 메시지에는 함께 보낸 파일의 이름이 표시되므로, 새로 고친 후에도 대화 기록에서 첨부 파일을 확인할 수 있습니다. 에이전트에게는 서버가 파일을 별도로 알려 주며, 에이전트는 다음과 같은 일을 할 수 있습니다.

| 할 수 있는 일 | 할 수 없는 일 |
|---|---|
| 세션의 파일 나열 | 다른 사람이 첨부한 파일 변경 |
| 텍스트 파일 읽기 | 파일 삭제 |
| 자신의 새 파일 추가 | 다른 실행의 파일에 접근 |

에이전트가 작성한 파일은 채팅에 **다운로드** 버튼이 있는 카드로 나타납니다. 에이전트는 파일을 추가만 할 수 있으므로, 세션에 이미 있는 이름으로 파일을 작성하면 기존 파일을 바꾸지 않고 번호를 붙인 이름(`report (2).csv`)으로 저장되며, 카드에는 실제로 저장된 이름이 표시됩니다.

읽기는 텍스트로 제한됩니다. 스프레드시트, 이미지, 압축 파일은 그대로 저장하고 다운로드할 수 있지만 에이전트가 읽을 수는 없습니다. 내용이 필요하다면 텍스트로 내보낸 파일을 제공하세요.

| | |
|---|---|
| **첨부할 수 있는 사람** | 실행의 시작자와 지정된 승인자로, 실행을 진행할 수 있는 사람과 같습니다. 지켜보기만 하는 관리자는 첨부할 수 없습니다 |
| **다운로드할 수 있는 사람** | 관리자를 포함해 채팅을 읽을 수 있는 모든 사람 |
| **보관 기간** | 실행이 존재하는 동안입니다. 실행을 삭제하면 파일도 삭제됩니다 |
| **크기 제한** | 배포마다 설정합니다. [구성](../operations/configuration.md#session-files)을 참조하세요 |

보낸 파일은 하나씩 제거할 수 없으므로, 세션의 파일은 실행과 함께 사라집니다.

## 워크플로 작업 {#workflow-tasks}

실행의 작업은 여기서 읽기 전용입니다. 템플릿은 [워크플로](./workflows.md#adjusting-the-task-templates)에서 편집하며, 실행의 상태는 실행 에이전트와 승인 흐름이 진행시킵니다.

각 작업에는 상태(`대기 중`, `진행 중`, `완료됨`, `실패`, `건너뜀`)와 종속 관계가 있습니다. **표 / 그래프** 전환으로 목록과 종속성 그래프를 오갈 수 있습니다. 그래프는 작업을 종속 순서에 따라 세로 한 열로 쌓아 선행 작업을 그에 의존하는 작업 위에 놓으며, 각 작업은 오른쪽으로 도구를 연결한 MCP 서버, 이어서 개별 도구로 갈라집니다. 그래프는 이동, 확대/축소, 화면 맞춤이 가능하지만 편집은 할 수 없습니다.

## 도구 호출 {#tool-invocations}

이 페이지에는 실행 중에 이루어진 MCP 도구 호출과 [게이트웨이](../architecture/mcp-gateway-and-proxy.md)가 각 호출을 어떻게 판정했는지가 표시됩니다. 업스트림으로 전달된 `허용됨` 호출과 규칙이 막은 `거부됨` 호출이 있으며, 도구, 서버, 거부 사유, 제시된 [도구 인증서](./approvals.md#human-approval)도 함께 표시됩니다. 인수는 다이제스트로만 표시되며 원래 값은 저장되지 않습니다.

[모의](./tool-mocks.md) 처리된 도구에 대한 호출은 결과와 상관없이 여기에 나타나지 않습니다. 게이트웨이는 모의 호출도 다른 호출과 똑같이 검사하지만, 처음부터 저장된 응답으로 답하게 되어 있는 호출은 어떤 서버에도 도달하지 않으므로 그 허용이나 거부는 이 기록에 속하지 않습니다. 스텁 처리된 호출은 실행의 채팅 기록에서 확인합니다.

## 실행 삭제 {#deleting-a-run}

행의 **삭제** 동작을 누르면 확인 메시지를 거쳐 실행이 제거됩니다. 레코드, 해당 작업, 워크플로 세션이 모두 함께 삭제됩니다.
