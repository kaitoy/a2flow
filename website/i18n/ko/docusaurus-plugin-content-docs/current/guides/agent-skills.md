# 에이전트 스킬

에이전트 스킬은 에이전트가 할 줄 아는 일을 Git 저장소에 담아 둔 것입니다. A2Flow는 이러한 스킬의 카탈로그를 관리합니다. 레코드마다 저장소를 지정하면 A2Flow가 그 저장소를 복제하고 복제본을 최신 상태로 유지합니다.

관리 사이드바에서 **에이전트 스킬**을 열어 카탈로그를 관리합니다.

![에이전트 스킬의 상태 머신. 등록된 스킬은 백그라운드에서 복제되어 준비됨 또는 실패 상태가 되고, 어느 상태에서든 풀로 다시 시도할 수 있으며, 준비됨 상태의 스킬에서 새 워크플로를 생성합니다.](./img/agent-skills-lifecycle.svg#gh-light-mode-only)
![에이전트 스킬의 상태 머신. 등록된 스킬은 백그라운드에서 복제되어 준비됨 또는 실패 상태가 되고, 어느 상태에서든 풀로 다시 시도할 수 있으며, 준비됨 상태의 스킬에서 새 워크플로를 생성합니다.](./img/agent-skills-lifecycle-dark.svg#gh-dark-mode-only)

스킬은 리비전을 게시한 후에야 사용할 수 있습니다. 그 전에는 해당 스킬로 워크플로를 생성하거나 실행하려는 요청이 거부됩니다.

## 스킬 레코드의 내용 {#what-a-skill-record-holds}

| 필드 | 참고 |
|---|---|
| **이름** | 다른 모든 곳에서 이 스킬을 가리키는 이름입니다. |
| **저장소 URL** | 복제할 저장소입니다. |
| **저장소 경로** | 스킬이 저장소 루트에 있지 않을 때 저장소 안에서의 위치입니다. |
| **참조** | 선택 사항입니다. 모든 복제와 풀을 고정할 브랜치 또는 태그 이름입니다. 비워 두면 저장소의 기본 브랜치를 사용합니다. |
| **설명** | 자유 텍스트입니다. |
| **인증 사용자 이름** / **인증 비밀번호** | 비공개 저장소용입니다. 아래를 참조하세요. |
| **태그** | 스킬을 분류하는 [태그](./tags.md)입니다. |

## 상태와 리비전 {#status-and-revision}

목록과 상세 페이지에는 두 가지 상태 정보가 표시되며, 의미는 서로 다릅니다.

| 열 | 알려 주는 내용 |
|---|---|
| **상태** | *마지막* 복제 또는 풀의 결과입니다. `복제 중`, `준비됨`, 또는 사유가 함께 표시되는 `실패`입니다. |
| **리비전** | 현재 게시된 리비전입니다. 이 값이 설정되어야 스킬을 실행할 수 있습니다. |

두 값은 의도적으로 서로 독립적입니다. 풀이 실패해도 게시된 리비전은 **지워지지 않으므로**, 동작하던 스킬은 기존 리비전으로 계속 동작합니다. 바뀌는 것은 상태와 오류뿐입니다.

## 풀 {#pulling}

**풀**은 설정된 **참조**로, 설정되지 않았으면 기본 브랜치로 저장소를 다시 복제합니다. 스킬이 업스트림 변경 사항을 가져오는 방법이자, URL이나 자격 증명을 고친 뒤 실패한 등록을 다시 시도하는 방법입니다. 브랜치 끝이 이동했거나 태그가 다른 커밋을 가리키게 되면 다음에 스킬을 풀할 때 반영됩니다.

트리 어디에든 **심볼릭 링크**가 있는 저장소는 거부됩니다. 복제나 풀이 해당 링크를 명시한 사유와 함께 실패하고, 그 저장소에서는 리비전이 게시되지 않습니다. 링크를 가리키는 파일의 복사본으로 교체하세요.

게시된 각 리비전은 필요로 하는 대상이 있는 동안 보관되며, 워크플로 실행은 시작할 때의 리비전에 고정됩니다. 따라서 풀을 해도 진행 중인 실행이 따르는 내용은 바뀌지 않습니다. 저장 위치와 보관 기간은 [구성 참조](../operations/configuration.md#agent-skill-store)에서 다룹니다.

## 비공개 저장소 {#private-repositories}

자격 증명은 스킬 양식에 직접 입력하지 않습니다. [시크릿](./secrets.md)으로 한 번 등록한 다음, 스킬에서 그 항목 중 하나를 가리키면 됩니다.

1. **인증 사용자 이름**을 설정합니다. 기본값은 `x-access-token`이며 GitHub 개인 액세스 토큰에 적합합니다. 실제 계정 이름이 필요한 호스트에서는 그 이름을 설정합니다.
2. **인증 비밀번호**의 첫 번째 드롭다운에서 **시크릿**을 선택하고, 두 번째 드롭다운에서 그 안의 **항목 키**를 선택합니다. 해당 항목의 값이 저장소를 복제할 때 비밀번호로 사용됩니다.

**인증 비밀번호**를 사용하려면 **저장소 URL**이 `https://`로 시작해야 합니다. `http://`이면 비밀번호가 암호화되지 않은 채 네트워크를 지나게 되므로 저장이 거부됩니다.

두 시크릿 유형 모두 선택할 수 있습니다. Vault 기반 시크릿은 항목 키가 로컬에 저장되지 않으므로 Vault에서 실시간으로 읽어 옵니다.

참조는 이름과 키로 저장되며 복제할 때 확인됩니다. 따라서 나중에 시크릿을 삭제하거나 이름을 바꿔도 그 자리에서 실패하지 않고, 다음 풀이 실패하며 사유가 스킬에 기록됩니다. 상세 페이지는 더 이상 확인되지 않는 참조를 슬그머니 제거하지 않습니다. 참조는 선택된 채로 `(찾을 수 없음)` 표시와 경고가 나타납니다. 지울지는 직접 결정하면 됩니다.

## 스킬에서 워크플로 생성 {#generating-a-workflow-from-a-skill}

각 행의 작업 열에는 **워크플로 생성**이 있고, 스킬 상세 페이지 머리글에도 같은 동작을 하는 아이콘 버튼이 있습니다. 둘 다 같은 대화 상자를 열며, 스킬이 리비전을 게시하기 전에는 둘 다 비활성화됩니다. [워크플로 생성](./workflows.md#generating-a-workflow)을 참조하세요.

## SKILL.md 보기 {#viewing-skillmd}

스킬 상세 페이지 머리글에는 **SKILL.md 보기** 아이콘 버튼이 있습니다. 이 버튼은 저장소에 작성된 그대로 스킬의 지침 파일을 렌더링한 대화 상자를 엽니다. 워크플로 생성과 마찬가지로 스킬이 리비전을 게시하기 전에는 비활성화됩니다. 파일은 복제가 성공한 뒤에야 존재하기 때문입니다. 위의 쓰기 작업과 달리, 개발자 역할이 없는 열람자도 사용할 수 있습니다.
