# 시스템 설정

시스템 설정에서는 [알림 이메일](./notifications.md#email-delivery)을 보내는 메일 서버와 전역 HashiCorp Vault를 구성합니다. 설정 레코드는 배포 전체에 정확히 하나뿐이며, 첫 시작 시 이메일 전송이 **꺼진** 상태로 생성됩니다. 따라서 새로 설치한 환경에서는 운영자가 켜기 전까지 알림이 앱 안에서만 표시됩니다.

관리 사이드바에서 **시스템 설정**을 엽니다. [테넌트](./users-and-groups.md#tenants)와 마찬가지로 이 섹션은 **슈퍼 관리자** 전용입니다. 설정이 테넌트 범위가 아니라 플랫폼 전체에 적용되므로 테넌트 관리자를 위한 예외가 없으며, 다른 사용자는 읽는 것조차 거부됩니다.

## 설정 {#the-settings}

| 필드 | 용도 |
|---|---|
| **애플리케이션 기본 URL** | 알림 이메일의 링크 대상입니다(예: `https://a2flow.example.com`). 비워 두면 링크 없이 메시지를 보냅니다. |
| **이메일로 알림 보내기** | 마스터 스위치입니다. 꺼져 있는 동안 알림은 앱 안에서만 표시되며 아무것도 전송되지 않습니다. |
| **SMTP 호스트** / **SMTP 포트** | 메시지를 넘겨줄 릴레이입니다. |
| **보안** | **STARTTLS**(기본값), **SSL/TLS**(암시적 TLS) 또는 **없음**입니다. |
| **SMTP 사용자 이름** / **SMTP 비밀번호** | SMTP AUTH 자격 증명입니다. 인증이 필요 없는 릴레이는 사용자 이름을 비워 두세요. |
| **보내는 주소** / **보내는 사람 이름** | 발신자 주소와 그 옆에 표시되는 선택적 표시 이름입니다. |

호스트나 발신자 주소 없이 전송을 켜는 것은 거부되므로, 나중에 조용히 실패할 상태로 양식을 저장할 수 없습니다.

이 페이지의 모든 필드는 환경 변수로도 설정할 수 있으므로, 배포에 메일 구성을 포함해 수동 단계로 남겨 두지 않을 수 있습니다. [알림 이메일](../operations/configuration.md#notification-email)을 참고하세요. 이 변수들은 시작할 때마다 다시 적용되므로, 그렇게 설정한 값이 여기에 입력한 값을 덮어씁니다.

비밀번호는 [시크릿](./secrets.md) 및 사용자 비밀번호와 마찬가지로 **쓰기 전용**이며 다시 표시되지 않습니다. 비밀번호가 저장되어 있으면 필드는 비어 있고 "저장됨 — 유지하려면 비워 두세요"라는 자리 표시자가 표시되며, 비워 둔 채 저장하면 지워지지 않고 저장된 비밀번호가 유지됩니다.

## 전역 Vault {#global-vault}

전역 Vault는 **자체 Vault가 없는** 모든 테넌트가 [Vault 유형 시크릿](./secrets.md)을 읽어 오는 HashiCorp Vault(KV v2만 해당)입니다. 테넌트 관리자는 [테넌트 설정](./users-and-groups.md#tenant-vault)에서 테넌트 자체 Vault를 대신 연결할 수 있으며, 이 경우 항상 테넌트 자체 Vault가 우선합니다.

| 필드 | 용도 |
|---|---|
| **전역 Vault 주소** | Vault 주소이며 `http://` 또는 `https://`로 시작합니다. 테넌트 자체 Vault와 달리 사설 네트워크에 있어도 됩니다. 비워 두고 저장하면 전역 Vault 연결이 해제됩니다. |

여기서는 주소만 설정합니다. 공유 자격 증명은 없습니다. 각 테넌트는 **자체 자격 증명**으로 로그인하며, 슈퍼 관리자가 테넌트 페이지에서 이를 등록합니다([전역 Vault 자격 증명](./users-and-groups.md#global-vault-credential) 참고). 자격 증명이 없는 테넌트는 전역 Vault를 전혀 읽을 수 없습니다.

테넌트 간 분리는 **Vault 자체**가 담당합니다. 시크릿은 지정된 **Vault 마운트**와 **Vault 경로**에서 읽으며, 테넌트 자격 증명에 연결된 정책이 그 읽기를 허용할지 결정합니다. 각 테넌트에 해당 테넌트의 데이터만 다루는 정책의 자격 증명을 발급하세요. 예를 들어 테넌트마다 AppRole을 만들고 `acme` 테넌트에는 다음과 같은 정책을 적용합니다.

```hcl
path "secret/data/tenants/acme/*" {
  capabilities = ["read"]
}
```

## 구성 확인 {#checking-the-configuration}

**테스트 이메일 보내기**는 *저장된* 설정을 사용해 고정된 테스트 메시지를 전송하므로, 구성 오류가 다음에 워크플로가 알림을 발생시킬 때가 아니라 즉시 드러납니다.

1. 먼저 설정을 저장합니다. 테스트는 화면의 내용이 아니라 저장된 내용을 사용합니다.
2. **테스트 이메일 보내기**를 클릭합니다.
3. 자신의 받은 편지함을 확인합니다. 받는 사람은 로그인한 슈퍼 관리자 본인의 주소로 고정되어 있으며 다른 곳으로 지정할 수 없습니다.

릴레이 실패는 페이지에 오류로 표시되며, 근본 원인은 서버 측에 기록됩니다.
