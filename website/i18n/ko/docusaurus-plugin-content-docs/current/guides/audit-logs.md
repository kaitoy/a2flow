# 감사 로그

감사 로그는 A2Flow가 사용자를 대신해 수행한 일에 대해 남기는 네 가지 기록을 모아 보여 줍니다. 에이전트가 수행한 도구 호출, 한 사람이 다른 사람으로 작업한 세션, 부여된 각 승인에 담긴 권한, 보낸 메일입니다. 모두 추가만 가능합니다. 이 화면에서는 어떤 기록도 편집하거나 제거할 수 없으며, 바로 그 점이 증거가 되는 이유입니다.

관리 사이드바에서 **감사 로그**를 엽니다. 표 위에 탭 네 개가 있습니다.

| 탭 | 한 행의 의미 |
|---|---|
| **도구 호출** | MCP 게이트웨이가 도구 호출 하나에 대해 내린 결정 하나 |
| **대리 로그인** | 관리자가 다른 사용자로 작업한 세션 하나 |
| **인증서** | 각 작업의 도구 호출을 뒷받침하는 권한 |
| **이메일** | 전송 대기열에 추가된 알림 메시지 하나 |

각 목록은 정렬, 필터링, 열 선택기, 페이징 등 다른 관리 표와 똑같이 동작합니다. [관리 UI](./admin-ui.md#the-list-screen)를 참조하세요. 행의 첫 번째 셀을 클릭하면 표 셀에서 잘리는 긴 값을 보여 주는 읽기 전용 상세 페이지가 열립니다.

## 볼 수 있는 사람 {#who-sees-it}

이 섹션은 **관리자**와 **슈퍼 관리자**에게만 표시됩니다. 그 외 사용자에게는 액세스 거부 화면이 표시되며 사이드바에도 나타나지 않습니다.

이는 로그인한 누구나 읽을 수 있는 대부분의 섹션보다 엄격합니다. 이 목록은 테넌트의 모든 실행, 계정, 메시지를 아우르므로, *자신의* 실행 기록을 볼 수 있게 하는 참여자 수준의 액세스로는 충분하지 않습니다. 범위가 좁은 화면은 그대로 남아 있습니다. 실행의 도구 호출은 여전히 해당 실행의 [도구 호출](./workflow-executions.md#tool-invocations) 페이지에 있고, 승인의 인증서는 여전히 [승인](./approvals.md) 자체에 있습니다. 다만 아무도 승인을 요청받지 않은 작업에 부여된 인증서까지 보여 주는 것은 이 목록뿐입니다.

슈퍼 관리자는 테넌트 전환기에서 선택한 테넌트의 내용을 보며, **모든 테넌트**를 선택하면 모든 테넌트를 한꺼번에 둘러볼 수 있습니다. 이 모드에서는 각 목록의 맨 왼쪽에 **테넌트** 열이 추가됩니다.

## 도구 호출 {#tool-invocations}

MCP 게이트웨이에 도달한 도구 호출과 각 호출에 대해 내린 결정입니다. 업스트림으로 전달된 `허용됨`과 규칙이 거부한 `거부됨`이 있습니다.

| 열 | 참고 |
|---|---|
| **도구** / **서버** | 무엇을 어디에서 호출했는지 |
| **결정** | `허용됨` 또는 `거부됨` |
| **거부 사유** | 거부된 호출이 거부된 이유로, 규칙에 적힌 표현 그대로입니다 |
| **워크플로 실행** | 호출이 속한 실행으로, 해당 실행으로 연결됩니다 |
| **승인** / **인증서** | 호출이 제시한 인증서와, 승인으로 부여된 경우 그 승인 |
| **인수 다이제스트** | 호출이 요청한 내용의 지문 |

인수 자체는 저장하지 않습니다. 제시된 서명이 포함하는 지문만 저장하므로, 전달된 내용을 보관하지 않고도 기록된 호출을 나중에 다시 검증할 수 있습니다. 상세 페이지에는 전체 지문, 서명, 서명된 정확한 시각이 표시됩니다.

[모의](./tool-mocks.md) 도구 호출은 결과와 상관없이 여기에 나타나지 않습니다. 스텁 처리된 호출은 어떤 서버에도 도달하지 않기 때문입니다. 이러한 호출은 실행의 채팅 기록에서 확인합니다.

## 대리 로그인 {#impersonations}

관리자가 다른 사용자로 작업한 세션마다, 시작한 순간부터 중지한 순간까지를 한 행으로 표시합니다. **종료 일시**가 없는 행은 아직 진행 중인 세션으로, **활성**으로 표시됩니다.

| 열 | 참고 |
|---|---|
| **대리 로그인한 사람** | 작업한 사람으로, 해당 계정으로 연결됩니다 |
| **대상 사용자** | 어떤 계정으로 작업했는지를 나타내며, 해당 계정으로 연결됩니다 |
| **상태** | 세션이 열려 있는 동안 **활성**, 닫히면 **종료됨** |
| **시작 일시** / **종료 일시** | 시작하고 끝난 시각 |

행의 범위는 작업한 사람이 아니라 **대리 로그인된** 계정의 테넌트로 정해집니다. 이는 의도된 것입니다. 슈퍼 관리자는 어떤 테넌트에도 속하지 않으므로, 작업한 사람을 기준으로 하면 슈퍼 관리자의 세션이 모든 테넌트에서 숨겨집니다. 관리자가 가장 확인해야 할 바로 그 세션이 보이지 않게 되는 것입니다. [대리 로그인](../concepts/impersonation.md)을 참조하세요.

## 인증서 {#certificates}

각 작업이 실제로 호출하도록 승인받은 내용입니다. 모든 도구 호출은 인증서를 제시하므로, 이 목록은 아무도 승인을 요청받지 않은 작업까지 포함해 부여되고 소진된 도구 권한의 완전한 기록입니다.

작업은 두 시점 중 하나에 인증서를 부여받으며, **권한** 열이 어느 쪽인지 알려 줍니다.

| 권한 | 발급 시점 | 부여자 |
|---|---|---|
| **승인자** | 작업의 [승인](./approvals.md)이 부여되었을 때 | 승인을 부여한 승인자 |
| **실행 시작자** | 승인 요청 없이 작업이 **진행 중**으로 표시되었을 때 | 실행을 시작한 사람 |

| 열 | 참고 |
|---|---|
| **일련번호** | 인증서를 식별합니다. 도구 호출 목록에서 해당 인증서를 제시한 호출에 표시되는 값입니다 |
| **권한** | **승인자** 또는 **실행 시작자**로, 부여의 출처입니다 |
| **부여자** | 부여한 것으로 기록된 사람 |
| **승인** | 인증서가 발급된 근거인 승인과 그 링크입니다. 실행 시작자의 부여는 뒤에 승인이 없으므로 비어 있습니다 |
| **상태** | **진행 중**, 권한이 소진되면 **폐기됨** |
| **허용된 도구** | 이 인증서가 부여하는 도구 |
| **유효 시작** / **유효 종료** | 유효한 기간 |
| **폐기 일시** / **폐기 사유** | 언제, 왜 효력을 잃었는지 |

**허용된 도구**는 별도의 사본이 아니라 발급된 인증서 자체에서 다시 읽어 오므로, 나중에 실행의 작업 연결이 다시 작성되더라도 이 화면에 표시되는 내용은 실제로 승인된 내용과 다를 수 없습니다. 키 자료는 표시되지 않으며 다운로드할 수도 없습니다.

## 이메일 {#emails}

A2Flow가 전송 대기열에 추가한 알림 메시지와 각 메시지의 결과입니다.

| 열 | 참고 |
|---|---|
| **받는 사람** / **제목** | 수신자와 주제 |
| **상태** | `대기 중`, `보내는 중`, `보냄` 또는 `실패` |
| **시도 횟수** | 전송을 시도한 횟수 |
| **보낸 일시** | 발송된 시각 |
| **마지막 오류** | 가장 최근 시도가 실패한 이유 |

전송할 수 없는 메시지는 `실패` 상태가 되며 제거되지 않고 **보관**됩니다. 따라서 도착하지 않은 알림도 사유가 기록된 채 계속 보입니다. 메시지 본문은 보낼 때 작성되는 것이 아니라 알림이 생성될 때 고정되며, 상세 페이지에는 실제 전송된 그대로 전문이 표시됩니다.

슈퍼 관리자는 `보냄` 또는 `실패` 행을 삭제할 수 있지만 관리자는 삭제할 수 없으며, 아직 `대기 중`이거나 `보내는 중`인 행은 메일 워커가 붙잡고 있을 수 있으므로 누구든 거부됩니다. 메시지가 대기열에 추가되는 과정은 [알림](./notifications.md)을, 메시지가 거쳐 가는 메일 서버는 [시스템 설정](./system-settings.md)을 참조하세요.
