# 도구 모의

도구 모의는 **초안** 워크플로 실행을 도구의 부작용 없이 처음부터 끝까지 시험할 수 있게 해 주는 대체물입니다. 모의된 도구는 호출되지 않고 모의에 설정된 결과가 대신 반환되므로, MCP 서버에 요청이 전달되지 않고 승인이 기록되지 않으며 누구에게도 이메일이 전송되지 않습니다.

관리 사이드바에서 **도구 모의**를 열어 관리합니다.

## 사용 방법 {#using-one}

1. 스텁으로 대체할 도구의 모의를 만듭니다.
2. **초안** 워크플로에서 **실행**을 클릭합니다. `수정됨` 워크플로라면 대화 상자에서 **게시되지 않은 편집**을 선택합니다. 대화 상자의 **모의 도구** 아래에는 이 워크플로의 작업이 사용하는 도구를 대신하는 모의와 내장 도구의 모든 모의가 표시됩니다.
3. 이 실행에서 사용할 모의를 선택하고 실행을 시작합니다.

이 워크플로의 어떤 작업도 사용하지 않는 도구의 모의는 목록에 나타나지 않습니다. 먼저 해당 도구를 작업에 연결하세요. 모의는 [테스트 실행](./workflows.md#trying-the-edits-out)에서만 제공됩니다. 게시된 디자인을 실행할 때는 대화 상자에 모의가 표시되지 않으며, 그래도 요청하면 거부됩니다. 실행을 시작하면 선택한 각 모의의 현재 내용이 실행으로 **복사**되므로, 이후에 모의를 편집하거나 삭제해도 이미 진행 중인 실행은 바뀌지 않으며 스텁 처리된 호출이 모르는 사이에 실제 호출로 되돌아갈 수도 없습니다.

모의 여부는 실행 단위가 아니라 **도구 단위**로 선택합니다. 드라이 런은 현실적일 때만 쓸모가 있기 때문입니다. 시스템을 검색한 다음 그 시스템에 쓰는 워크플로는 쓰기만 스텁 처리할 수 있습니다. 읽기는 여전히 실제 서버에 도달하고, 에이전트는 실제 데이터를 바탕으로 판단합니다.

## 모의의 구성 요소 {#what-a-mock-holds}

| 필드 | 참고 |
|---|---|
| **이름** / **설명** | 실행 대화 상자에서 모의를 구분하는 방법입니다. |
| **대상** | [등록된 MCP 서버](./mcp-servers.md)의 도구 하나(**MCP 서버 선택**을 선택하고 서버를 고른 다음, 해당 서버에서 불러온 목록에서 **도구 이름**을 선택) 또는 A2Flow의 **내장** 도구입니다. |
| **응답** | 호출 순서로 색인되는 순서 있는 목록입니다. |

현재 모의할 수 있는 내장 도구는 `request_approval`뿐입니다. 이 도구의 부작용은 원래 사람이 처리해야 실행을 계속할 수 있습니다.

### 도구가 반환하는 내용 {#what-the-tool-returns}

도구를 선택하면 그 아래에 **출력 형식**이 열리고, 도구 자체의 설명과 도구가 반환한다고 밝힌 형태가 표시됩니다. 아래에 작성할 내용의 참고 자료로 사용하세요. 모의는 워크플로가 실제 도구의 결과를 읽듯이 읽을 수 있어야만 쓸모가 있습니다.

모든 도구가 반환 내용을 밝히는 것은 아닙니다. 밝히지 않는 도구는 패널에 그렇게 표시되고 형태는 사용자에게 맡겨집니다.

### 응답 {#responses}

첫 번째 응답은 실행에서 그 도구를 처음 호출할 때, 두 번째 응답은 두 번째로 호출할 때 사용되는 식으로 이어집니다. 목록이 끝나면 마지막 응답이 반복되므로 응답이 하나면 상수처럼 동작합니다. 덕분에 모의 하나로 고정된 값이 아니라 *시나리오*를 표현할 수 있습니다. 예를 들어 첫 번째 요청은 승인하고 두 번째 요청은 반려한 뒤 워크플로가 두 경우를 어떻게 처리하는지 볼 수 있습니다.

| 종류 | 의미 |
|---|---|
| 구조화(JSON 객체) | 결과의 구조화된 콘텐츠에 들어가는 JSON 객체입니다. 호출자가 결과에서 필드를 읽는 도구에 사용합니다 |
| 텍스트 | 결과의 텍스트 콘텐츠에 들어가는 문자열입니다 |
| 오류 | 실패한 호출로 반환되는 메시지입니다. 에이전트에게는 도구가 오류를 보고한 것으로 보입니다 |

도구가 출력 형식을 선언하면 **구조화(JSON 객체)** 응답에 **스키마에서 삽입**이 제공됩니다. 키를 포함한 해당 형태로 입력란을 채워 주므로 구조를 옮겨 적는 대신 값만 편집하면 됩니다. 입력란의 내용은 모두 바뀌며, 이미 작성한 내용이 있으면 먼저 확인을 요청합니다.

## 태그 {#tags}

도구 모의의 만들기 양식과 상세 페이지에는 **태그** 선택기가 있고, 목록에는 필터링할 수 있는 **태그** 열이 있습니다. 태그는 시크릿, MCP 서버 및 태그를 붙일 수 있는 다른 레지스트리가 공유하는 테넌트 전체 어휘입니다. 태그를 붙이고 필터링하는 방법은 [태그](./tags.md)를 참고하세요.

## 모의가 건너뛰지 않는 것 {#what-a-mock-does-not-skip}

모의는 부작용을 건너뛸 뿐 규칙을 건너뛰지 않습니다. 모의된 호출도 실행의 현재 작업이 사용할 수 있는 도구와 그 작업이 기다리는 [승인](./approvals.md)을 기준으로 검사되므로, 프로덕션에서 거부될 워크플로는 드라이 런에서도 거부됩니다. 해당 승인이 허용한 **입력**도 검사하므로, 승인자가 승인하지 않았을 호출을 그냥 통과시키지 않고 드라이 런에서 잡아냅니다. 모의된 승인 요청도 대상과 선언된 호출을 검증하므로, 자격이 없는 승인자를 지정하거나 단계에서 실제로 수행할 호출과 일치하지 않는 호출을 선언한 워크플로는 실제 실행과 똑같이 드라이 런에서 실패합니다.

## 모의된 호출 확인 {#seeing-what-a-mocked-call-did}

스텁 처리된 호출은 실행의 채팅 기록에서 확인합니다. 해당 도구 줄을 펼치면 인수와 결과가 표시되고 **모의됨** 배지가 붙습니다. 이 호출은 실행의 [도구 호출](./workflow-executions.md#tool-invocations) 페이지에는 의도적으로 나타나지 않습니다. 이 페이지는 MCP 게이트웨이가 실제로 내린 결정을 기록하는데, 스텁은 게이트웨이에 도달하지 않기 때문입니다. 실행 자체에는 [실행 목록](./workflow-executions.md)에서 **모의됨** 배지가 붙습니다.
