# 시크릿

시크릿은 **이름이 붙은 키/값 항목의 묶음**입니다. [HashiCorp Vault의 KV 엔진](https://developer.hashicorp.com/vault/docs/secrets/kv/kv-v2)과 같은 형태로, 경로 하나가 키와 값의 맵을 담습니다. AWS 액세스 키 ID와 시크릿 액세스 키처럼 함께 쓰는 자격 증명은 시크릿 두 개로 나누지 않고 시크릿 하나에 항목 두 개로 저장합니다.

관리 사이드바에서 **시크릿**을 열어 관리합니다. 각 레코드에는 **이름**, 선택 사항인 **설명**, [태그](./tags.md), 유형이 있습니다.

## 시크릿이 사용되는 곳 {#where-a-secret-is-used}

![시크릿 항목이 MCP 서버의 헤더와 환경 변수에서 참조되거나 에이전트 스킬 저장소의 인증 비밀번호로 참조되는 것을 보여 주는 순서도.](./img/secrets-usage.svg#gh-light-mode-only)
![시크릿 항목이 MCP 서버의 헤더와 환경 변수에서 참조되거나 에이전트 스킬 저장소의 인증 비밀번호로 참조되는 것을 보여 주는 순서도.](./img/secrets-usage-dark.svg#gh-dark-mode-only)

- **[MCP 서버](./mcp-servers.md)** — 모든 헤더 값과 환경 변수 값에 `${secret:name/key}`를 포함할 수 있으며, 연결할 때 확장됩니다.
- **[에이전트 스킬](./agent-skills.md)** — 스킬의 **인증 비밀번호**는 항목 하나에 대한 참조이며, 직접 입력하지 않고 드롭다운에서 선택합니다.

항목 하나는 항상 **`name/key`** 형식으로 지정합니다. 시크릿에 항목이 하나뿐이어도 키는 필수입니다. 이름만으로는 값이 아니라 맵을 가리키기 때문입니다. 따라서 키가 없는 `${secret:name}`은 리터럴 문자열로 전달되지 않고 확인에 실패합니다.

## 두 가지 유형 {#the-two-types}

| | **로컬(암호화됨)** | **HashiCorp Vault** |
|---|---|---|
| **저장되는 내용** | 항목 자체입니다. 각 값은 암호화됩니다 | KV v2 참조만 저장합니다. **Vault 마운트**와 **Vault 경로**입니다 |
| **값의 출처** | 암호화된 저장소 | 확인할 때마다 Vault에서 실시간으로 읽습니다 |
| **상세 페이지 표시 내용** | 저장된 모든 키와 빈 값 | 마운트와 경로 |
| **항목 편집** | 값을 비워 두면 유지되고, 다시 입력하면 교체되고, 행을 제거하면 항목이 삭제됩니다 | Vault에서 편집합니다 |

값은 어느 유형이든, 평문이든 암호문이든 **반환되지 않습니다**. 그래서 로컬 유형의 상세 페이지에는 키만 표시되고 값은 비어 있습니다. 키는 읽을 수 있으므로 선택기에 나열할 수 있습니다. 로컬 시크릿의 키는 저장된 맵에서 가져오고, Vault 시크릿의 키는 그 시점에 Vault에서 읽어 옵니다.

Vault 시크릿은 **해당 테넌트의** Vault에서 읽으며, 테넌트 관리자가 [테넌트 설정](./users-and-groups.md#tenant-vault)에서 연결합니다. 자체 Vault가 없는 테넌트는 [자체 자격 증명](./users-and-groups.md#global-vault-credential)으로 [전역 Vault](./system-settings.md#global-vault)에서 읽으며, 이 자격 증명의 Vault 정책이 읽을 수 있는 범위를 결정합니다. 둘 다 없으면 Vault 유형 시크릿을 확인할 수 없습니다. 로컬 시크릿을 암호화하는 키는 [구성 참조](../operations/configuration.md#secret-management)에서 한 번만 설정합니다.

## 이름 변경과 삭제 {#renaming-and-deleting}

시크릿은 **이름으로** 참조되며 사용할 때 확인됩니다. 어딘가에서 아직 참조하는 시크릿의 이름을 바꾸거나 삭제해도 편집 시점에는 실패하지 않습니다. 대신 다음에 사용할 때 찾지 못한 시크릿의 이름을 표시하며 실패합니다. 참조가 유효하지 않게 된 [에이전트 스킬](./agent-skills.md)은 다음에 **풀**할 때 그 이유를 자체 레코드에 기록합니다.

다만 참조를 저장할 때는 검사가 이루어집니다. 헤더나 환경 변수에서 시크릿을 지정한 MCP 서버를 저장하거나, 스크립트에서 **테스트 실행**을 실행하거나, 스킬의 **인증 비밀번호**를 저장할 때는 해당 시크릿이 존재하고 자신이 열 수 있는 것이어야 합니다. [액세스 제어 태그](./tags.md#access-control-tags)로 자신에게 숨겨진 시크릿은 존재하지 않는 시크릿과 똑같이 거부됩니다. 이미 그런 시크릿을 참조하는 레코드를 편집할 때도 다른 필드만 변경하더라도 마찬가지입니다.
