# 관리 UI

관리 영역은 A2Flow의 모든 레코드를 만들고, 확인하고, 편집하는 곳입니다. 상단의 앱 바와 왼쪽의 섹션 사이드바로 이루어진 하나의 틀 안에서 모든 섹션이 같은 방식으로 동작하므로, 목록 하나만 익히면 15개 섹션을 모두 다룰 수 있습니다.

## 환영 페이지 {#welcome-page}

환영 페이지는 첫 화면입니다. 로그인한 직후, 사이트 루트를 열 때, 앱 바의 **A2Flow** 로고를 클릭할 때마다 이 페이지로 이동합니다. 사용자의 역할이 허용하는 관리 섹션마다 바로 가기 카드가 하나씩 표시됩니다.

모든 제목 위의 이동 경로는 이 흐름을 그대로 보여 줍니다. `홈 › 워크플로 › my-workflow`처럼 표시되며, 마지막 항목을 제외한 모든 항목은 상위 단계로 돌아가는 링크입니다.

## 섹션 {#the-sections}

| 섹션 | 담고 있는 내용 | 사이드바에 표시되는 대상 |
|---|---|---|
| **테넌트** | 테넌트 조직 | 슈퍼 관리자 |
| **사용자** | 계정과 계정의 역할 | 관리자, 개발자 |
| **사용자 그룹** | 여러 계정에 역할을 한 번에 부여하는 이름 붙은 묶음 | 관리자, 개발자 |
| **태그** | 레코드를 분류하는 레이블 | 관리자, 개발자 |
| **시크릿** | 도구와 저장소에 쓰는 자격 증명 | 관리자, 개발자 |
| **에이전트 스킬** | Git 저장소에서 복제한 에이전트 기능 | 개발자, 관리자 |
| **지식 베이스** | 문서를 바탕으로 LLM이 작성하고 워크플로가 읽는 위키 | 개발자, 관리자, 검토자 |
| **MCP 서버** | 에이전트가 호출할 수 있는 도구 서버 | 개발자, 관리자 |
| **도구 모의** | 초안 워크플로 실행에서 도구를 스텁 처리하는 대역 | 개발자, 관리자 |
| **워크플로** | 여러 단계의 흐름과 작업 템플릿 | 개발자, 요청자, 관리자 |
| **워크플로 실행** | 워크플로 실행과 실행 기록 | 로그인한 모든 사용자 |
| **승인** | 승인 요청과 그 결정 | 로그인한 모든 사용자 |
| **감사 로그** | 도구 호출, 대리 로그인, 부여된 권한, 보낸 메일 | 관리자, 슈퍼 관리자 |
| **테넌트 설정** | 로그인 실패 시 테넌트의 계정을 잠그는 방식과 테넌트 자체 Vault. [로그인 실패](./users-and-groups.md#failed-sign-ins)와 [테넌트의 Vault](./users-and-groups.md#tenant-vault)를 참조하세요 | 관리자 |
| **시스템 설정** | 알림을 보내는 메일 서버와 전역 Vault의 주소 | 슈퍼 관리자 |

사이드바에 없는 섹션은 내 역할로 쓰기 권한이 없는 섹션입니다. 읽기는 열려 있으므로 동료가 그 안의 레코드로 연결되는 직접 링크를 보내 주면 열어 볼 수 있습니다. [역할과 권한 부여](../concepts/authorization.md)를 참조하세요.

[감사 로그](./audit-logs.md)는 예외입니다. 읽기도 제한되어 있어 관리자 역할이 없으면 직접 링크를 열어도 액세스 거부 화면이 표시됩니다. [액세스 제어 태그](./tags.md#access-control-tags)가 붙은 레코드도 예외입니다. 내 그룹에 그 태그가 없으면 링크를 열어도 레코드를 찾을 수 없다고 표시됩니다.

## 목록 화면 {#the-list-screen}

모든 섹션은 표로 시작하며, 모든 표에서 같은 컨트롤을 제공합니다.

| 컨트롤 | 기능 |
|---|---|
| **열 머리글 메뉴** | 그 열을 기준으로 정렬하고 필터링합니다. 둘 다 화면에 보이는 페이지만이 아니라 전체 데이터에 적용됩니다. |
| **열 경계** | 드래그해서 너비를 조절합니다. 너비는 세션 동안만 유지되며 저장되지 않습니다. |
| **셀에 마우스 올리기** | 열 너비 때문에 잘린 내용의 전체 텍스트를 표시합니다. |
| **▥ 열** | 열 선택기를 엽니다(아래 참조). |
| **새로 고침** | 목록을 다시 읽어 옵니다. |
| **+ … 추가** | 만들기 양식을 엽니다. 쓰기 역할이 없으면 숨겨집니다. |
| **작업 열** | 행별 작업입니다. 삭제를 비롯해 레코드 유형이 제공하는 다른 작업이 표시됩니다. 쓰기 역할이 없으면 숨겨집니다. |

작업의 상태, MCP 서버의 전송 방식, 태그의 색상처럼 정해진 값 중 하나만 갖는 열은 알파벳순이 아니라 그 값을 읽도록 의도된 순서로 정렬됩니다. 따라서 작업을 상태로 정렬하면 `대기 중`, `진행 중`, `완료됨`, `실패`, `건너뜀` 순서가 되며, 이는 다른 모든 곳의 상태 점이 따르는 수명 주기 순서와 같습니다.

### 열 선택 {#choosing-columns}

새로 고침 옆의 **▥** 버튼을 누르면 표에 표시할 수 있는 모든 열이 나열됩니다.

- **모두 표시** / **모두 숨기기**는 전체를 한 번에 전환하고, **기본값으로 재설정**은 기본 구성으로 되돌립니다.
- 중요한 열에 너비를 확보하기 위해 처음에는 숨겨져 있는 열도 있습니다. MCP 서버의 전송 방식, 시크릿의 참조, 에이전트 스킬의 참조와 리비전, 사용자의 이메일과 확인 플래그 등이 그렇습니다.
- 식별자 열과 작업 열은 항상 표시되므로 목록에 나오지 않습니다.
- 선택 내용은 표별로 브라우저에 저장되어 새로 고침 후에도 유지됩니다. 기본값과 달라진 부분만 저장하므로, 나중에 표에 추가된 열도 의도된 기본 상태로 나타납니다.
- 정렬이나 필터에 쓰이는 열을 숨기면 해당 정렬이나 필터가 해제됩니다. 따라서 화면에 표시되지 않는 조건 때문에 행이 좁혀지는 일은 없습니다.

이 패널은 항상 화면 안에 들어옵니다. 아래쪽에 공간이 없으면 위쪽으로 열리고, 일괄 전환 버튼은 보이는 상태로 둔 채 목록만 내부에서 스크롤하며, 전환할 수 있는 열이 8개를 넘으면 두 단으로 나뉩니다. 그래서 열이 17개인 에이전트 스킬도 세로가 짧은 노트북 화면에서 모두 선택할 수 있습니다.

## 상세 화면 {#the-detail-screen}

식별자 열에서 레코드 이름을 클릭하면 상세 페이지가 열립니다. 이 페이지가 해당 레코드의 유일한 화면으로, 속성과 함께 레코드가 지원하는 모든 작업을 제공합니다. 편집 내용 저장, 삭제, 그리고 워크플로 게시나 스킬 저장소 풀처럼 유형별로 제공되는 작업이 여기에 있습니다. 페이지 제목은 작업 이름이 아니라 **레코드 자체의 이름**입니다.

쓰기 역할이 없으면 같은 페이지가 읽기 전용으로 표시됩니다. 필드는 입력란 대신 들어가 보이는 값으로 표시되고, **저장**과 **삭제**는 사라지며, **취소**는 **뒤로**로 바뀝니다.

[워크플로 실행](./workflow-executions.md)은 이 모든 것의 예외입니다. 실행은 편집할 레코드가 아니라 기록이므로, 행을 클릭하면 편집 양식 대신 해당 실행의 채팅이나 읽기 전용 작업 목록이 열립니다.
