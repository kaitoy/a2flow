# 작동 방식

A2Flow는 [에이전트 스킬](../guides/agent-skills.md)을 실행 전에 단계가 확정되는 워크플로로 바꾼 다음, 에이전트와 관련자들이 공유하는 채팅 안에서 그 워크플로를 실행합니다. 각 단계는 이전 단계의 결과를 고정된 사본으로 다음 단계에 넘기므로, 디자인이 이후에 바뀌더라도 실행은 게시된 내용을 충실히 따릅니다.

![에이전트 스킬에서 워크플로가 생성되고, 워크플로 세션 안에서 워크플로 실행으로 수행되며, 그 작업이 사람의 승인을 요청하거나 MCP 게이트웨이를 통해 MCP 도구를 호출하여 MCP 서버에 도달하는 과정을 보여 주는 순서도.](./img/overview-lifecycle.svg#gh-light-mode-only)
![에이전트 스킬에서 워크플로가 생성되고, 워크플로 세션 안에서 워크플로 실행으로 수행되며, 그 작업이 사람의 승인을 요청하거나 MCP 게이트웨이를 통해 MCP 도구를 호출하여 MCP 서버에 도달하는 과정을 보여 주는 순서도.](./img/overview-lifecycle-dark.svg#gh-dark-mode-only)

| 단계 | 일어나는 일 | 더 읽어 보기 |
|---|---|---|
| **디자인** | 스킬이 워크플로가 됩니다. AI 디자인 실행이 요청을 단계로 나누고 각 단계에 필요한 도구를 연결합니다. | [워크플로 디자인](./workflow-design.md) |
| **실행** | 워크플로를 실행하면 게시된 디자인이 새 워크플로 실행으로 복사되고 그 채팅이 열립니다. | [워크플로 실행](./workflow-execution.md) |
| **대화** | 에이전트와 여러 사람이 그 채팅을 공유하며, 에이전트는 텍스트만 쓰는 것이 아니라 대화형 화면 요소를 채팅에 그릴 수 있습니다. | [세션](./sessions.md) |
| **승인** | 사람의 결정이 필요한 작업은 누군가 결정할 때까지 동작할 수 없으며, 그 결정은 인증서에 서명됩니다. 그 밖의 모든 작업도 실행을 시작한 사람의 권한으로 인증서를 지닙니다. | [승인 게이트](./approvals.md) |
| **동작** | 모든 도구 호출은 A2Flow를 벗어나기 전에 정책 체인이 허용 여부를 결정하고, 결정된 후에 기록됩니다. | [MCP 게이트웨이와 프록시](./mcp-gateway-and-proxy.md) |

이 모든 것의 뒤에는 두 저장소가 있습니다. 모든 레코드가 저장되는 [데이터베이스](./database.md)와 자격 증명을 확인할 때 사용하는 [시크릿 저장소](./secrets.md)입니다.

## 두 가지 채팅 {#the-two-chats}

A2Flow의 채팅은 정확히 두 종류입니다. 동일한 구조가 서로 다른 에이전트를 향하는 것으로, 둘의 차이는 각 에이전트에게 허용된 일에 있습니다.

| 채팅 | 구동 주체 | 할 수 있는 일 |
|---|---|---|
| **디자인 세션** | 스킬을 따르는 디자인 에이전트 | 워크플로의 작업 템플릿을 작성하고 재배치합니다. 아무것도 실행하지 않습니다. |
| **워크플로 세션** | 실행에 고정된 스킬 리비전을 따르는 실행 에이전트 | 실행의 작업을 처리하고, 승인을 요청하고, MCP 도구를 호출합니다. |

두 채팅 모두 별도의 레코드가 아닙니다. 디자인 세션은 해당 워크플로로, 워크플로 세션은 해당 워크플로 실행으로 식별되며, 그 뒤의 대화는 처음 사용할 때 만들어져 그 ID 아래에 보관됩니다. 그래서 어느 쪽이든 다시 열면 이전에 멈춘 곳에서 이어집니다.
