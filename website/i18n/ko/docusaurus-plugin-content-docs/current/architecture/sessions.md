# 세션

세션은 에이전트, 세션을 연 사람, 그리고 작업 과정에서 합류하는 다른 사람들이 함께 쓰는 채팅입니다. 에이전트가 대화형 화면 요소를 그리는 곳이기도 해서, 문장으로 답하는 대신 양식을 채우는 방식으로 대화가 이루어질 수 있습니다.

## 공유하는 사람 {#who-shares-one}

| 세션 | 공유 대상 | 그 밖의 사람 |
|---|---|---|
| **워크플로 세션** | 실행의 시작자와, 실행에 속한 [승인](./approvals.md)의 지정된 승인자 | 테넌트의 관리자는 읽기 전용으로 볼 수 있으며, 그 외에는 액세스할 수 없습니다 |
| **디자인 세션** | 테넌트의 모든 개발자, 슈퍼 관리자, 워크플로 작성자 | 액세스 불가 |

그룹에 전달된 승인은 승인자 역할을 가진 모든 구성원을 세션에 합류시키므로 채팅은 그룹의 구성원 변화를 따릅니다. 이 액세스는 결정을 내릴 수 있게 하려고 존재합니다. 여러 사람이 하나의 대화에 글을 올리므로 모든 메시지에는 **보낸 사람 아바타**가 표시되며, 각 참여자는 새로 고치지 않아도 모든 답변을 작성되는 대로 볼 수 있습니다.

## 한 턴이 진행되는 방식 {#how-a-turn-runs}

![채팅 한 턴의 시퀀스 다이어그램. 사용자의 메시지가 프런트엔드에서 백엔드를 거쳐 모델로 전달되고, 모델의 스트리밍 응답과 render_a2ui 화면 요소가 돌아오며, 사용자가 채운 화면 요소가 같은 경로를 다시 왕복합니다.](./img/sessions-turn-flow.svg#gh-light-mode-only)
![채팅 한 턴의 시퀀스 다이어그램. 사용자의 메시지가 프런트엔드에서 백엔드를 거쳐 모델로 전달되고, 모델의 스트리밍 응답과 render_a2ui 화면 요소가 돌아오며, 사용자가 채운 화면 요소가 같은 경로를 다시 왕복합니다.](./img/sessions-turn-flow-dark.svg#gh-dark-mode-only)

백엔드는 AG-UI 프로토콜과 에이전트를 연결합니다. 이벤트를 양방향으로 변환하고, 대화 상태를 맞추고, 이벤트가 도착하는 대로 브라우저로 스트리밍하므로 텍스트는 마지막에 한꺼번에 나타나지 않고 점진적으로 나타납니다. 대화 상태는 채팅 ID 아래에 보관되므로 다시 열면 이전에 멈춘 곳에서 이어집니다.

워크플로 세션은 누군가의 채팅이 열려 있지 않아도 됩니다. 모든 턴을 A2Flow가 직접 실행하기 때문입니다. 실행이 생성되자마자 진행되는 실행의 **시작** 턴, [승인](../guides/approvals.md)이 결정되면 실행을 **재개**하는 턴, 작업이 [기다려야 했던](../guides/workflows.md#how-the-agent-works-through-the-tasks) 시간이 되면 실행을 재개하는 턴, 참여자가 보낸 내용에 답하는 턴이 여기에 해당합니다. 채팅은 A2Flow에 메시지를 전달하고, 턴이 어느 서버에서 실행되든 지켜보는 모든 사람에게 그 진행을 보여 줄 뿐입니다. (디자인 세션은 예외로, 턴이 여전히 메시지를 보낸 개발자의 채팅에서 실행됩니다.)

## 대화형 화면 요소 {#interactive-surfaces}

`render_a2ui` 도구는 프런트엔드가 연결하며, A2Flow가 직접 실행하는 턴에서는 백엔드가 똑같은 정의로 연결합니다. 이 도구에는 에이전트가 그릴 수 있는 [A2UI](https://a2ui.org) 컴포넌트 카탈로그의 스키마가 담겨 있습니다. 모델이 이 도구를 호출하면 백엔드는 아무것도 실행하지 않고 호출을 전달하며, 결과는 브라우저가 그립니다.

| 컴포넌트 | 용도 |
|---|---|
| `Text`, `Card`, `Row`, `Column` | 구조와 문구 |
| `TextField` | 자유 입력 |
| 선택 항목 선택기 | 허용된 값 중에서 선택. 옵션이 다섯 개 이상인 단일 선택 선택기는 드롭다운으로 접히므로, 에이전트가 대화를 뒤덮지 않고도 모든 EC2 인스턴스 유형이나 리전을 나열할 수 있습니다 |
| `Button` | 화면 요소 제출 |

버튼을 클릭하면 누른 버튼만이 아니라 입력하거나 선택한 모든 값, 즉 화면 요소의 **전체 데이터 모델**이 다시 전송됩니다. 덕분에 에이전트는 사용자가 실제로 입력한 내용에 응답할 수 있고, 다시 불러온 채팅은 답변이 끝난 화면 요소를 에이전트의 기본값이 아니라 사용자가 입력한 값으로 채워 다시 표시할 수 있습니다.

### 호출 도중 서버의 질문 {#a-servers-question-mid-call}

에이전트가 전혀 그리지 않는 화면 요소가 하나 있습니다. MCP 서버는 도구 호출 도중에 멈춰 사람에게 무언가를 물을 수 있으며(*elicitation*), 기다리는 동안 호출은 열린 상태로 유지됩니다. 워크플로의 디자인에서 질문을 한다고 표시된 도구만 이렇게 할 수 있고, 그런 도구를 사용하는 작업은 실행의 시작자가 채팅에 있어야 시작됩니다. 세션은 **시작자 대기 중**에서 멈추고, 시작자에게 알림이 전송되며, 작업은 시작자의 **재개**로 시작되는 턴에서 시작됩니다. 그런 다음 A2Flow는 질문을 기록하고 실행 중인 턴의 스트림에 별도의 활동으로 추가하므로 모든 시청자가 즉시 볼 수 있습니다. 세션이 아직 턴 진행 중이므로 답변은 채팅 입력이 아니라 전용 경로를 통해 전달되며, 답변을 받는 것은 새 턴이 아니라 대기 중인 도구 호출입니다. 사람에게 무엇이 보이는지는 [MCP 서버의 확인 요청](../guides/workflow-executions.md#mcp-server-confirmations)을 참조하세요.

## 채팅에 표시되는 에이전트 활동 {#agent-activity-in-the-chat}

답변 사이에 에이전트가 무엇을 하는지 볼 수 있도록 중간 작업이 채팅 스트림 안에 표시됩니다.

- **작업 중 표시**: 실행이 진행 중이지만 아직 화면에 아무것도 없을 때 메시지 목록 하단에 은은한 펄스가 나타납니다.
- **도구 호출 줄**: 모든 백엔드 도구 호출(예: `list_workflow_tasks`, `update_workflow_task`)은 스피너(`실행 중…`)에서 체크 표시(`완료`)로 바뀌는 간결한 상태 줄이 됩니다. [MCP 게이트웨이](./mcp-gateway-and-proxy.md)를 통한 호출은 `MCP` 태그와 함께 **실제 MCP 도구 이름**으로 표시됩니다. `render_a2ui` 및 `render_approval` 클라이언트 도구, 세션 파일을 쓰는 도구, [추천 답변](../guides/workflow-executions.md#suggested-replies)을 제안하는 도구는 전용 UI를 유지하며 도구 줄로 표시되지 않습니다.
- **호출 세부 정보**: 인수나 결과가 있는 도구 줄은 **클릭하면 펼쳐져** 둘 다 서식이 적용된 JSON으로 표시되므로, 채팅을 떠나지 않고도 에이전트가 실제로 보내고 받은 내용을 살펴볼 수 있습니다. [도구 모의](./mcp-gateway-and-proxy.md#tool-mocks-and-dry-runs)가 응답한 줄에는 `모의됨` 배지가 붙습니다. 스텁 처리된 호출은 프록시에 도달하지 않아 감사 기록을 남기지 않으므로, 이를 살펴볼 수 있는 곳은 채팅이 *유일*합니다.
- **추론**: 사고 기능이 있는 모델이 추론을 스트리밍하면 그 생각이 흐리게 표시된 "생각 중" 패널에 나타납니다. 사고 요약을 내보내지 않고 내부적으로 추론하는 모델은 패널을 만들지 않습니다.

세션을 재개하면 **MCP 도구 호출**, **파일 카드**, 마지막 턴의 **추천 답변**이 기록에서 재구성됩니다. 그 밖의 A2Flow 내부 도구 호출과 추론은 실시간으로만 표시됩니다. 파일 카드를 다시 만드는 이유는 파일이 그것을 만든 실행보다 오래 남고 다운로드 링크가 나타나는 곳이 채팅뿐이기 때문이며, 추천 답변을 다시 만드는 이유는 그 답변이 다루는 질문이 아직 열려 있기 때문입니다.

## 세션의 파일 {#files-in-a-session}

워크플로 세션에는 메시지뿐 아니라 파일도 있습니다. 참여자가 채팅 입력에서 첨부한 파일과 에이전트가 작업 중에 작성한 파일입니다. 디자인 세션에는 파일이 없습니다.

세 가지 규칙이 파일을 정의합니다.

- **범위.** 파일은 정확히 하나의 실행에 속합니다. 파일이 속한 실행을 지정하지 않고는 파일을 가리킬 수 없으므로, 한 세션의 파일에 다른 세션에서 접근할 수 없습니다.
- **수명.** 파일은 실행과 수명을 같이하며 실행과 함께 제거됩니다. 별도의 정리나 만료는 없습니다.
- **액세스.** 파일 고유의 권한은 없습니다. 첨부하려면 실행을 구동할 자격이, 다운로드하려면 채팅을 읽을 자격이 필요합니다. 이는 채팅 자체에 쓰이는 두 규칙과 같습니다.

에이전트는 파일을 읽고 추가할 수 있지만 교체하거나 제거할 수는 없습니다. 이미 사용 중인 이름으로 쓰면 번호가 붙은 변형 이름으로 저장됩니다. 따라서 참여자가 첨부한 파일은 이후 실행이 무엇을 하든 첨부한 그대로 유지됩니다.

에이전트가 파일에 대해 아는 내용은 브라우저에서 오지 않습니다. 서버가 세션의 파일 목록을 읽어 워크플로 프롬프트와 함께 실행의 컨텍스트에 주입합니다. 방식도 이유도 같습니다. 클라이언트가 제공한 목록은 곧 클라이언트가 제공한 지시이기 때문입니다.

파일은 데이터베이스에 저장되므로 그 내구성과 백업을 그대로 이어받으며, 레플리카 간에 공유 볼륨이 필요 없습니다. 다운로드는 항상 일반 콘텐츠 유형의 첨부 파일로 제공되므로, 참여자나 에이전트가 저장한 어떤 내용도 브라우저에서 렌더링될 수 없습니다.
