# 시크릿 저장소

[시크릿](../guides/secrets.md)은 키/값 항목을 이름을 붙여 묶은 것이며, 모든 참조는 정확히 하나의 항목을 가리킵니다. MCP 서버의 헤더나 환경 변수에서는 `${secret:name/key}`로, 에이전트 스킬에서는 이름과 키로 참조합니다. 참조는 이름으로 보관되고 **사용하는 시점에만 확인**되므로, 자격 증명이 필요한 어떤 항목도 자격 증명 자체를 저장하지 않습니다.

![시크릿 참조가 유형에 따라 갈라지는 것을 보여 주는 순서도. 로컬 유형은 저장된 값을 복호화하고, Vault 유형은 Vault에서 값을 실시간으로 읽으며, 둘 다 MCP 서버 연결이나 스킬 저장소 복제에 사용됩니다.](./img/secrets-resolution.svg#gh-light-mode-only)
![시크릿 참조가 유형에 따라 갈라지는 것을 보여 주는 순서도. 로컬 유형은 저장된 값을 복호화하고, Vault 유형은 Vault에서 값을 실시간으로 읽으며, 둘 다 MCP 서버 연결이나 스킬 저장소 복제에 사용됩니다.](./img/secrets-resolution-dark.svg#gh-dark-mode-only)

| | **로컬** | **HashiCorp Vault** |
|---|---|---|
| 저장되는 내용 | 항목 자체. 각 값은 암호화됨 | KV v2 참조(마운트와 경로)만 |
| 값의 출처 | 암호화된 저장소 | 확인 시점에 읽는 Vault |
| 키를 나열하는 방법 | 저장된 맵에서 나열하며 아무것도 복호화하지 않음 | 그 시점에 Vault에서 읽음 |
| 클라이언트가 다시 읽을 수 있는 것 | 키만. 값은 평문이든 암호문이든 절대 읽을 수 없음 | 키만 |

## 로컬 시크릿 {#local-secrets}

값은 배포마다 하나씩 있는 키로 암호화됩니다. 항목 키는 그 옆에 평문으로 남기 때문에 선택기에서 아무것도 복호화하지 않고 키를 나열할 수 있습니다. 값은 어떤 형태로든 클라이언트에 반환되지 않으며, 그래서 로컬 시크릿의 상세 페이지에는 키만 표시되고 값은 비어 있습니다.

암호화 키는 프로세스당 한 번 확인됩니다. 환경 변수에 설정되어 있으면 그 값을 사용하고, 없으면 키 파일에서 읽으며, 그것도 없으면 처음 사용할 때 생성해 해당 파일에 쓰고 로그에 경고를 남깁니다.

**이 키를 백업하세요.** 키를 잃으면 저장된 로컬 시크릿을 모두 복호화할 수 없게 됩니다. 또한 같은 키가 [도구 인증서](./approvals.md)를 발급하는 기관의 서명 키도 보호하므로 인증서를 발급하거나 검증할 수도 없게 되어, 모든 MCP 도구 호출이 멈춥니다. 두 키 모두 [구성 참조](../operations/configuration.md#secret-management)에서 설명합니다.

## HashiCorp Vault 시크릿 {#hashicorp-vault-secrets}

Vault 기반 시크릿의 경우 A2Flow는 값을 전혀 저장하지 않고, 값을 읽어 올 마운트와 경로만 저장합니다. 값과 키 목록은 모두 필요할 때마다 실시간으로 가져오므로, Vault에서 값을 교체하면 A2Flow를 건드리지 않아도 적용됩니다.

시크릿은 항상 그 시크릿이 속한 테넌트의 Vault를 통해 읽습니다. 관리자가 [테넌트 설정](../guides/users-and-groups.md#tenant-vault)에서 연결한 테넌트 **자체** Vault가 있으면 그것을 사용하고, 없으면 슈퍼 관리자가 구성한 [전역 Vault](../guides/system-settings.md#global-vault)에 테넌트의 [자체 자격 증명](../guides/users-and-groups.md#global-vault-credential)으로 로그인해 사용합니다. 어느 쪽이든 정적 토큰이나 AppRole 자격 증명으로 인증하며, AppRole 토큰은 임대 기간이 거의 끝날 때까지 재사용한 뒤 다시 로그인해 갱신합니다. 전역 Vault에서는 테넌트마다 자체 자격 증명을 가지므로, 그 자격 증명에 연결된 Vault 정책으로 테넌트가 서로 분리됩니다. 둘 다 없으면 테넌트의 `vault` 유형 시크릿은 전혀 확인할 수 없습니다.

## 확인이 일어나는 곳 {#where-resolution-happens}

| 사용처 | 확인 시점 |
|---|---|
| MCP 서버의 헤더 및 환경 변수 값 | [게이트웨이](./mcp-gateway-and-proxy.md)가 MCP 프록시가 해당 서버에 여는 연결을 위해 값을 확장할 때 |
| 에이전트 스킬의 저장소 비밀번호 | 저장소를 복제하거나 풀할 때 |

확인이 지연되어 일어나므로, 무언가가 아직 참조 중인 시크릿의 이름을 바꾸거나 삭제해도 편집 시점에는 실패하지 않습니다. 대신 다음 사용 시 찾지 못한 시크릿의 이름을 알리며 실패합니다. 근본 원인은 호출자에게 전달되지 않고 서버 로그에 남습니다.
