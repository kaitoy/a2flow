# 워크플로 디자인

워크플로는 빈 상태로 만들어지지 않습니다. A2Flow가 복제하여 최신 상태로 유지하는 Git 저장소인 [에이전트 스킬](../guides/agent-skills.md)에서 생성된 다음, 디자인을 고정할 만해질 때까지 다듬어집니다.

게시된 리비전이 없는 스킬에서는 워크플로를 생성할 수도, 실행할 수도 없습니다. 두 에이전트가 따르는 것은 복제본이므로, 복제본이 생기기 전에는 따를 대상이 없습니다.

## 디자인 실행 {#the-design-run}

생성은 워크플로를 즉시 등록하고 디자인 작업은 백그라운드에서 수행합니다. 이는 LLM을 상대로 한 완전한 에이전트 실행이므로, 화면을 붙잡아 두는 대신 작업이 진행되는 동안 레코드가 스스로 새로 고쳐집니다.

1. 생성 대화 상자의 프롬프트가 워크플로 **디자인 세션**의 첫 메시지로 전송됩니다.
2. 디자인 에이전트가 스킬을 읽고, 요청을 단계로 나누어 **작업 템플릿**으로 등록합니다. 이것은 각 단계가 먼저 끝나야 할 단계를 선언하는 종속성 그래프입니다.
3. 도구가 필요한 각 단계에 대해, 해당 단계가 호출할 수 있는 MCP 도구를 연결합니다.
4. 대화가 워크플로의 **생성된 프롬프트**(모든 실행에 컨텍스트로 전달되는 텍스트)와, 실행하는 사람들을 위한 짧은 **설명**으로 요약되고 워크플로는 `초안`이 됩니다.

생성 대화 상자에 입력한 요청은 워크플로의 필드로 보관되지 않습니다. 디자인 대화의 첫 메시지로 남을 뿐이며, 그래서 나중에 같은 채팅을 다시 열어 결과를 다듬을 수 있고, 아무것도 등록하지 못한 실행도 빈 레코드가 아니라 쓸 만한 출발점을 남깁니다.

## 작업 템플릿의 구성 {#what-a-task-template-carries}

| 템플릿의 구성 요소 | 참고 |
|---|---|
| **제목 및 설명** | 실행 에이전트가 읽게 될 단계 내용입니다. 작업 목록에서 칩으로 읽히도록 제목은 짧게 유지합니다. |
| **종속 대상** | 같은 워크플로의 다른 템플릿으로 이어지는 연결입니다. 순환을 만드는 연결은 거부됩니다. |
| **MCP 도구** | 이 단계가 호출할 수 있는 `(서버, 도구)` 쌍으로, 각각 해당 단계를 다루는 [승인](./approvals.md)이 호출 값의 범위를 제한해야 하는지를 나타냅니다. 읽기 전용 도구는 입력 승인이 필요 없는 것으로 표시됩니다. 실행은 자신의 연결을 편집할 수 없으므로 이 선택을 할 수 있는 곳은 여기뿐입니다. |
| *상태 없음* | 수명 주기는 디자인이 아니라 실행에 속합니다. |

템플릿은 디자인 채팅, 관리 양식, 또는 그 둘을 섞어서 다듬습니다. 해당 화면은 [워크플로](../guides/workflows.md#adjusting-the-task-templates)에서 다룹니다. 디자인 에이전트는 템플릿을 직접 편집할 뿐 아무것도 실행하지 않으며, 그래서 디자인 세션을 팀 전체와 안전하게 공유할 수 있습니다.

## 디자인 시점의 도구 연결 {#binding-tools-at-design-time}

도구를 고르는 일과 호출하는 일은 의도적으로 서로 다르게 관리됩니다.

| 작업 | 수행 주체 | 제한 방식 |
|---|---|---|
| 서버가 제공하는 도구 **나열** | 결정 중인 디자인 에이전트 | 제한 없음. 도구를 찾아내는 것이 디자인 실행의 핵심입니다 |
| 도구 **호출** | 실행 중인 실행 에이전트 | 실행에서 현재 진행 중인 작업에 연결된 도구로 제한됩니다. [MCP 게이트웨이와 프록시](./mcp-gateway-and-proxy.md) 참조 |

따라서 여기에 작성한 연결은 모델에 주는 힌트가 아닙니다. 실행 시 [게이트웨이](./mcp-gateway-and-proxy.md)가 강제하는 권한이자, 작업이 시작되는 순간(또는 승인이 필요한 것으로 드러난 경우 승인이 부여되는 순간) 해당 작업의 [인증서](./approvals.md)가 고정하는 집합입니다.

## 게시 {#publishing}

게시는 디자인을 고정합니다. 워크플로의 이름, 설명, 유효 프롬프트, 그리고 종속 연결과 도구 연결을 포함한 전체 템플릿 목록이 번호가 매겨진 새 게시 버전으로 저장되며, 이전 버전은 [버전 기록](../guides/workflows.md#version-history)에 남습니다. 이 시점에는 AI가 실행되지 않습니다. 게시는 스냅샷일 뿐 검토가 아닙니다.

게시 후 편집하면 워크플로는 `수정됨`으로 바뀌지만 실행되는 내용은 달라지지 않습니다. 다시 게시할 때까지 실행은 게시된 버전을 계속 사용합니다. 이미 진행 중인 실행은 어떤 경우에도 영향을 받지 않습니다. 시작하는 순간 자신의 사본을 가져갔기 때문입니다.

또한 게시된 버전은 대부분의 사람이 보게 되는 유일한 버전입니다. 워크플로가 `수정됨`인 동안 게시되지 않은 이름, 설명, 프롬프트, 작업 템플릿은 **개발자**와 **슈퍼 관리자**에게만 표시됩니다. 그 밖의 역할은 내내 게시된 버전을 읽고(이름 검색과 정렬도 게시된 이름을 따르는 워크플로 목록 포함), 상태도 `게시됨`으로 봅니다. 개발자는 어느 쪽 디자인이든 실행할 수 있습니다. 게시된 디자인은 실제 요청으로, 편집 내용은 도구를 스텁으로 대체할 수 있고 운영 메트릭에서 제외되는 [테스트 실행](../guides/workflows.md#trying-the-edits-out)으로 실행합니다.
