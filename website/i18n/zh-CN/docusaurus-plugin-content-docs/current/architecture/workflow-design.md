# 设计工作流

工作流从不是凭空创建的。它由[代理技能](../guides/agent-skills.md)（A2Flow 克隆并保持更新的 Git 仓库）生成，然后不断完善，直到设计值得冻结为止。

没有已发布修订版本的技能，既不能用来生成工作流，也不能用来运行。两个代理遵循的都是克隆下来的内容，所以在克隆存在之前，没有可遵循的东西。

## 设计运行 {#the-design-run}

生成操作会立即注册工作流，并在后台进行设计工作。这是一次针对 LLM 的完整代理运行，因此在工作进行期间，记录会自行刷新，而不会让某个界面一直开着等待。

1. 生成对话框中的提示词作为工作流**设计会话**的第一条消息发送。
2. 设计代理读取技能，把请求拆分为步骤，并将它们注册为**任务模板**。这是一张依赖图，每个步骤都声明哪些步骤必须先完成。
3. 对于需要工具的步骤，它会绑定该步骤允许调用的 MCP 工具。
4. 对话被总结为工作流的**生成提示词**（交给每次运行作为上下文的文本），并为运行它的人生成一段简短的**描述**，然后工作流变为 `草稿`。

在生成对话框中输入的请求不会作为工作流的字段保留，而是作为设计对话的第一条消息继续存在。这就是为什么之后可以重新打开同一个聊天来完善结果，也是为什么即使一次运行什么都没有注册，留下的也是一个可用的起点，而不是一条空记录。

## 任务模板包含什么 {#what-a-task-template-carries}

| 模板包含 | 备注 |
|---|---|
| **标题和描述** | 执行代理将读到的步骤内容。标题保持简短，以便在任务列表中作为胶囊显示。 |
| **依赖于** | 指向同一工作流中其他模板的边。会形成循环的边会被拒绝。 |
| **MCP 工具** | 此步骤允许调用的 `(服务器, 工具)` 对，每一对都说明涵盖此步骤的[审批](./approvals.md)是否必须限定调用所用的值。只读工具被标记为无需输入审批；这是唯一可以作出这一选择的地方，因为运行无法编辑自己的绑定。 |
| *没有状态* | 生命周期属于运行，而不属于设计。 |

模板可以通过设计聊天、管理表单或两者任意结合的方式来完善，这些界面请参阅[工作流](../guides/workflows.md#adjusting-the-task-templates)。设计代理直接编辑模板，不执行任何内容，因此可以放心地与整个团队共享设计会话。

## 在设计时绑定工具 {#binding-tools-at-design-time}

选择工具和调用工具受不同规则约束，这是有意为之。

| 操作 | 由谁执行 | 如何限制 |
|---|---|---|
| **列出**服务器提供的工具 | 设计代理，在作决定时 | 不受限制，因为发现工具正是设计运行的目的所在 |
| **调用**工具 | 执行代理，在运行过程中 | 仅限绑定到该运行当前进行中任务的工具，请参阅 [MCP 网关与代理服务器](./mcp-gateway-and-proxy.md) |

因此，在这里写下的绑定并不是给模型的提示，而是[网关](./mcp-gateway-and-proxy.md)在运行时强制执行的授权，也是任务的[证书](./approvals.md)在任务启动那一刻（如果事后发现任务需要审批，则是审批获得批准那一刻）所冻结的集合。

## 发布 {#publishing}

发布会冻结设计。工作流的名称、描述、生效的提示词以及完整的模板列表（包括依赖边和工具绑定）都会被捕获为一个新的带编号的已发布版本；较早的版本保留在[版本历史记录](../guides/workflows.md#version-history)中。此时不会运行任何 AI；发布是一个快照，而不是一次审查。

之后的编辑会让工作流变为 `已修改`，但不会改变运行的内容：在再次发布之前，运行继续使用已发布版本。已在进行中的运行无论如何都不受影响，因为它在启动的那一刻就取得了自己的副本。

已发布版本也是大多数人唯一能看到的版本。当工作流处于 `已修改` 状态时，其未发布的名称、描述、提示词和任务模板只向**开发人员**或**超级管理员**显示，不向其他任何人显示；其他所有角色自始至终读取的都是已发布版本（包括在工作流列表中，按名称搜索和排序时同样依据已发布的名称），看到的状态也是 `已发布`。开发人员可以运行任一设计：把已发布版本作为真实请求运行，或把编辑内容作为[测试运行](../guides/workflows.md#trying-the-edits-out)来运行；测试运行可以用桩替换工具，并且不计入运维指标。
