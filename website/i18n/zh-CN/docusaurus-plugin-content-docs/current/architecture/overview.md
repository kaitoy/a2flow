# 工作原理

A2Flow 把[代理技能](../guides/agent-skills.md)变成一个在任何运行开始之前步骤就已确定的工作流，然后在代理和相关人员共享的聊天中执行这个工作流。每个阶段都把之前内容的冻结副本交给下一个阶段，因此即使设计后来有了变化，运行也始终忠于当初发布的内容。

![流程图，显示代理技能生成工作流，工作流以工作流执行的形式在工作流会话中运行，其任务请求人工审批，或通过 MCP 网关调用 MCP 工具以访问 MCP 服务器。](./img/overview-lifecycle-dark.svg#gh-dark-mode-only)

| 阶段 | 发生了什么 | 延伸阅读 |
|---|---|---|
| **设计** | 技能变成工作流：一次 AI 设计运行把请求拆分为步骤，并绑定每个步骤所需的工具。 | [设计工作流](./workflow-design.md) |
| **运行** | 运行工作流时，已发布的设计被复制到一个新的工作流执行上，并打开其聊天。 | [运行工作流](./workflow-execution.md) |
| **对话** | 代理和多位相关人员共享这个聊天，代理不只能写文字，还能在其中绘制交互式界面。 | [会话](./sessions.md) |
| **批准** | 需要人工决定的任务在有人作出决定之前无法行动，而这一决定会被签入证书。其他所有任务也都带有证书，依据的是发起运行者的权限。 | [审批门禁](./approvals.md) |
| **行动** | 每次工具调用在离开 A2Flow 之前都由策略链裁决，裁决后还会被记录下来。 | [MCP 网关与代理服务器](./mcp-gateway-and-proxy.md) |

这一切的背后是两个存储：保存所有记录的[数据库](./database.md)，以及用来解析凭据的[密钥存储](./secrets.md)。

## 两种聊天 {#the-two-chats}

A2Flow 只有两种聊天。它们是同一套机制，只是面向不同的代理，区别在于各个代理被允许做什么。

| 聊天 | 驱动者 | 可以做什么 |
|---|---|---|
| **设计会话** | 设计代理，遵循技能 | 编写和重新编排工作流的任务模板。不执行任何内容。 |
| **工作流会话** | 执行代理，遵循该运行所固定的技能修订版本 | 逐一处理运行的任务、请求审批并调用 MCP 工具。 |

两种聊天都不是独立的记录。设计会话通过其工作流定位，工作流会话通过其工作流执行定位，背后的对话在首次使用时创建，并保存在该 ID 之下，所以重新打开任何一个，都会从上次中断的地方继续。
