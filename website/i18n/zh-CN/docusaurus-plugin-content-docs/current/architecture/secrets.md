# 密钥存储

[密钥](../guides/secrets.md)是一组具名的键值条目，每个引用都恰好指向其中一个条目：在 MCP 服务器的标头或环境变量中写作 `${secret:name/key}`，在代理技能、租户单点登录的客户端密钥或其 LLM 的 API 密钥上则是一个名称加一个键。引用按名称保存，**只在使用时才解析**，因此需要凭据的内容从不存储凭据本身。

![流程图，显示密钥引用按类型分支：本地类型解密已存储的值，Vault 类型从 Vault 实时读取，两者都交给使用该引用的一方：MCP 服务器连接、技能仓库克隆、单点登录或租户的 LLM。](./img/secrets-resolution-dark.svg#gh-dark-mode-only)

| | **本地** | **HashiCorp Vault** |
|---|---|---|
| 存储什么 | 条目本身，每个值都已加密 | 只有一个 KV v2 引用，即挂载点和路径 |
| 值从哪里来 | 加密存储 | Vault，在解析的那一刻读取 |
| 如何列出键 | 从已存储的映射中列出，无需解密任何内容 | 在那一刻从 Vault 读取 |
| 客户端能读回什么 | 只有键，绝不返回值，无论明文还是密文 | 只有键 |

## 本地密钥 {#local-secrets}

值分两层加密。部署有一个**主加密密钥**，每个租户还有各自的**数据加密密钥**：它在创建租户时生成，并用主加密密钥加密后存储。租户的值使用该租户自己的数据加密密钥加密，因此即使把某个值复制到另一个租户的密钥中，在那里也无法解密。

| 加密密钥 | 加密的内容 |
|---|---|
| 主加密密钥 | 每个租户的数据加密密钥；平台自身的设置（SMTP 密码和平台的 LLM API 密钥）；签发[工具证书](./approvals.md)的证书颁发机构的签名密钥 |
| 租户的数据加密密钥 | 该租户本地密钥的值；保存在租户上的凭据（Vault 凭据、单点登录的客户端密钥和 LLM API 密钥）；该租户工具证书的私钥 |

条目的键以明文保存在值的旁边，因此选择器无需解密任何内容就能列出它们；而值绝不会以任何形式返回给客户端，这也是本地密钥的详情页只显示键、值留空的原因。

主加密密钥在每个进程中只解析一次：如果环境变量中已设置，就从那里获取；否则从密钥文件读取；再否则在首次使用时生成，写入该文件，并在日志中给出警告。

主加密密钥可以[轮换](../operations/configuration.md#rotating-the-master-key)：在后端于启动时重新加密旧加密密钥所保护的内容之前，旧加密密钥仍可用于解密。各租户的数据加密密钥不会改变，因此租户拥有的内容都无需重新加密。

**请备份这个加密密钥。** 一旦丢失，所有租户的数据加密密钥都将无法解密，所有已存储的本地密钥和凭据也随之无法解密；而且由于同一个加密密钥还保护着证书颁发机构的签名密钥，丢失它也会导致证书无法签发或验证，进而使所有 MCP 工具调用都无法进行。两者都在[配置参考](../operations/configuration.md#secret-management)中说明。

## HashiCorp Vault 密钥 {#hashicorp-vault-secrets}

对于由 Vault 支持的密钥，A2Flow 完全不存储值，只存储读取它们所用的挂载点和路径。值和键列表都在每次需要时实时获取，因此在 Vault 中轮换某个值后，无需改动 A2Flow 即可生效。

密钥始终通过其所属租户的 Vault 读取。如果租户管理员已在[管理员设置](../guides/users-and-groups.md#tenant-vault)下连接了租户**自有**的 Vault，就使用它；否则使用超级管理员设置的[全局 Vault](../guides/system-settings.md#global-vault)，并使用该租户[自有的凭据](../guides/users-and-groups.md#global-vault-credential)登录。两者都可以通过静态令牌或 AppRole 凭据进行认证；AppRole 令牌会一直复用到租约快要到期，然后重新登录以刷新。在全局 Vault 上，每个租户都有自己的凭据，因此租户之间通过附加在这些凭据上的 Vault 策略相互隔离。两者都没有时，租户的 `vault` 类型密钥将完全无法解析。

## 解析发生的位置 {#where-resolution-happens}

| 使用方 | 解析时机 |
|---|---|
| MCP 服务器的标头和环境变量值 | [网关](./mcp-gateway-and-proxy.md)为 MCP 代理服务器与该服务器建立的连接展开这些值时 |
| 代理技能的仓库密码 | 克隆或拉取仓库时 |
| 租户单点登录的客户端密钥 | 有人通过[单点登录](../guides/single-sign-on.md)登录时 |
| 由租户管理员设置的 LLM 的 API 密钥 | 该租户的代理运行时 |

由于解析是延迟进行的，重命名或删除仍被引用的密钥不会在编辑时失败，而是在下次使用时失败，并指出找不到的密钥名称；根本原因则保留在服务器日志中，不会返回给调用方。此时单点登录会以“此租户无法使用单点登录。”结束，代理则会报错停止，而不会改用系统的密钥运行。

只有租户自己的凭据可以引用密钥。[系统设置](../guides/system-settings.md)中的凭据不属于任何租户，因此无法引用租户的密钥；超级管理员为租户设置的 LLM 密钥也不会从密钥中读取，因为该租户的 MCP 服务器可以引用它。
