# 审计日志

审计日志汇集了 A2Flow 代表您所做之事的四类记录：代理发起的工具调用、一个人以另一个人身份操作的会话、每项已批准的审批所带有的权限，以及发送的邮件。每类记录都只能追加，此页面上没有任何操作可以编辑或删除记录，这正是它们能作为证据的原因。

在管理侧边栏中打开**审计日志**。表格上方有四个选项卡：

| 选项卡 | 每行表示 |
|---|---|
| **工具调用** | MCP 网关对一次工具调用作出的一项决定 |
| **代理登录** | 管理员以其他用户身份操作的一个会话 |
| **证书** | 每个任务的工具调用背后的权限 |
| **邮件** | 一封排队等待投递的通知邮件 |

每个列表的行为都与其他管理表格相同，支持排序、筛选、列选择器和分页，参见[管理界面](./admin-ui.md#the-list-screen)。点击行的第一个单元格可打开只读的详情页，其中显示表格单元格中被截断的长值。

## 谁可以查看 {#who-sees-it}

此分区仅向**管理员**和**超级管理员**显示。其他人会看到拒绝访问的页面，侧边栏中也不会出现此分区。

这比大多数分区更严格，后者的读取权限向所有已登录用户开放。这些列表涵盖租户中的每次运行、每个账户和每封邮件，因此让您能看到*自己的*运行记录的参与者级访问权限在这里并不够。范围更窄的视图仍在原处：某次运行自身的工具调用仍在其[工具调用](./workflow-executions.md#tool-invocations)页面上，审批的证书仍在[审批](./approvals.md)本身上。不过，只有此列表还会显示授予那些未请求审批的任务的证书。

超级管理员看到的是租户切换器所选租户的内容，也可以选择**所有租户**同时浏览所有租户。在此模式下，每个列表的最左侧会增加一个**租户**列。

## 工具调用 {#tool-invocations}

到达 MCP 网关的工具调用，以及网关对每次调用的决定：`已允许` 的调用发往上游，`已拒绝` 的调用被规则否决。

| 列 | 说明 |
|---|---|
| **工具** / **服务器** | 调用了什么，在哪里调用 |
| **决定** | `已允许` 或 `已拒绝` |
| **拒绝原因** | 被拒绝的调用为何被拒绝，使用规则本身的措辞 |
| **工作流执行** | 该调用所属的运行，并链接到该运行 |
| **审批** / **证书** | 调用出示的证书，以及授予该证书的审批（如果有） |
| **参数摘要** | 调用所请求内容的指纹 |

参数本身绝不会存储，只保存所出示签名所覆盖的指纹，这样无需保留调用携带的内容，也能在之后重新核验已记录的调用。详情页会显示完整的指纹、签名以及签名的确切时刻。

对[模拟](./tool-mocks.md)工具的调用无论结果如何都不会出现在这里，因为被桩替换的调用不会到达任何服务器。这些调用可在运行的聊天记录中查看。

## 代理登录 {#impersonations}

管理员以其他用户身份操作的每个会话占一行，从开始到停止。没有**结束时间**的行表示会话仍在进行中，标记为**有效**。

| 列 | 说明 |
|---|---|
| **代理登录者** | 谁在操作，并链接到其账户 |
| **目标用户** | 以谁的账户操作，并链接到该账户 |
| **状态** | 会话打开期间为**有效**，关闭后为**已结束** |
| **开始时间** / **结束时间** | 开始和结束的时间 |

行按**被代理登录**账户所属的租户划分，而不是操作者所属的租户。这是有意为之：超级管理员不属于任何租户，因此如果按操作者划分，他们的会话会对所有租户隐藏，而这恰恰是管理员最需要看到的会话。参见[代理登录](../concepts/impersonation.md)。

## 证书 {#certificates}

每个任务实际被授权调用的内容。每次工具调用都要出示证书，因此此列表是已授予和已用尽的工具权限的完整记录，也包括那些未请求审批的任务。

任务在以下两个时刻之一获得证书，**权限**列会说明是哪一个：

| 权限 | 签发时间 | 授予者 |
|---|---|---|
| **审批人** | 任务的[审批](./approvals.md)获得批准时 | 批准该审批的审批人 |
| **运行发起人** | 任务被标记为**进行中**且未请求审批时 | 发起此次运行的人 |

| 列 | 说明 |
|---|---|
| **序列号** | 标识证书，工具调用列表中出示该证书的调用旁显示的就是此值 |
| **权限** | **审批人**或**运行发起人**，表示授权的来源 |
| **授予者** | 授权所归属的人 |
| **审批** | 签发证书所依据的审批及其链接。运行发起人的授权背后没有审批，因此为空 |
| **状态** | **进行中**，权限用尽后变为**已吊销** |
| **允许的工具** | 此证书授予的工具 |
| **有效期开始** / **有效期结束** | 证书的有效时间范围 |
| **吊销时间** / **吊销原因** | 何时以及为何不再有效 |

**允许的工具**是从已签发的证书本身读取的，而不是来自单独的副本，因此即使运行的任务绑定之后被改写，此页面显示的内容也绝不会与实际授权的内容不一致。任何密钥材料都不会显示，也无法下载。

## 邮件 {#emails}

A2Flow 已排队等待投递的通知邮件，以及每封邮件的结果。

| 列 | 说明 |
|---|---|
| **收件人** / **主题** | 发给谁，关于什么 |
| **状态** | `待处理`、`发送中`、`已发送` 或 `失败` |
| **尝试次数** | 已进行的投递尝试次数 |
| **发送时间** | 发出的时间 |
| **最近的错误** | 最近一次尝试失败的原因 |

无法投递的邮件会进入 `失败` 状态并被**保留**，而不是被删除，因此未送达的通知仍然可见，并记录了原因。邮件正文在生成通知时就已固定，而不是在发送时才撰写，详情页会完整显示实际投递的内容。

超级管理员可以删除 `已发送` 或 `失败` 的行；管理员不能删除。仍处于 `待处理` 或 `发送中` 的行，两者都不能删除，因为邮件工作进程可能正在处理它。这些邮件如何进入队列，参见[通知](./notifications.md)；邮件经由的邮件服务器，参见[系统设置](./system-settings.md)。
