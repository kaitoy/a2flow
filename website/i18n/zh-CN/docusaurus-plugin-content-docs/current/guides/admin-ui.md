# 管理界面

A2Flow 中的每条记录都在管理区域创建、查看和编辑。管理区域是一个统一的框架：顶部是应用栏，左侧是分区侧边栏，其中每个分区的用法都相同，因此学会一个列表，就等于学会了全部十五个分区。

## 欢迎页 {#welcome-page}

欢迎页是进入系统后看到的第一个页面：登录后、打开站点根路径时，以及点击应用栏中的 **A2Flow** 徽标时，都会来到这里。页面以快捷操作卡片迎接您，您的角色可以使用的每个管理分区各有一张卡片。

每个标题上方的面包屑导航反映的正是这条路径，例如 `首页 › 工作流 › my-workflow`，除最后一项外，每一项都链接回上一级。

## 各分区 {#the-sections}

| 分区 | 包含的内容 | 在侧边栏中向谁显示 |
|---|---|---|
| **租户** | 租户组织 | 超级管理员 |
| **用户** | 账户及其角色 | 管理员、开发人员 |
| **用户组** | 一次向多个账户授予角色的命名集合 | 管理员、开发人员 |
| **标签** | 用于分类记录的标签 | 管理员、开发人员 |
| **密钥** | 工具和仓库使用的凭据 | 管理员、开发人员 |
| **代理技能** | 从 Git 仓库克隆的代理能力 | 开发人员、管理员 |
| **知识库** | LLM 根据您的文档编写、供工作流读取的 Wiki | 开发人员、管理员、审阅者 |
| **MCP 服务器** | 代理可以调用的工具服务器 | 开发人员、管理员 |
| **工具模拟** | 在草稿工作流运行时替代工具的桩 | 开发人员、管理员 |
| **工作流** | 多步骤流程及其任务模板 | 开发人员、请求者、管理员 |
| **工作流执行** | 工作流的运行及其历史记录 | 所有已登录用户 |
| **审批** | 审批请求及其决定 | 所有已登录用户 |
| **审计日志** | 工具调用、代理登录、已授予的权限和已发送的邮件 | 管理员、超级管理员 |
| **租户设置** | 登录失败时如何锁定您租户的账户，以及您租户自己的 Vault。参见[登录失败](./users-and-groups.md#failed-sign-ins)和[租户的 Vault](./users-and-groups.md#tenant-vault) | 管理员 |
| **系统设置** | 发送通知所用的邮件服务器，以及全局 Vault 的地址 | 超级管理员 |

侧边栏中没有显示的分区，表示您的角色无法写入该分区。读取权限仍然开放，因此同事仍可以把其中某条记录的直接链接发给您。参见[角色与授权](../concepts/authorization.md)。

[审计日志](./audit-logs.md)是例外：它的读取也受到限制，没有管理员角色时，打开直接链接会看到拒绝访问的页面。另一个例外是带有[访问控制标签](./tags.md#access-control-tags)的记录：除非您所在的用户组带有该标签，否则链接会提示找不到该记录。

## 列表页面 {#the-list-screen}

每个分区都以一个表格打开，所有表格都提供相同的控件：

| 控件 | 作用 |
|---|---|
| **列标题菜单** | 按该列排序和筛选。两者都作用于整个数据集，而不只是当前屏幕上的这一页。 |
| **列边缘** | 拖动可调整列宽。宽度仅在当前会话期间保留，不会保存。 |
| **将鼠标悬停在单元格上** | 显示因列宽而被截断的完整文本。 |
| **▥ 列** | 打开列选择器（见下文）。 |
| **刷新** | 重新读取列表。 |
| **+ 添加…** | 打开创建表单。没有写入角色时隐藏。 |
| **操作列** | 每行的操作，包括删除以及该记录类型提供的其他操作。没有写入角色时隐藏。 |

只能取一组固定值的列（例如任务的状态、MCP 服务器的传输方式、标签的颜色）不按字母顺序排序，而是按这些值本来的阅读顺序排序。因此，按状态对任务排序时，顺序是 `待处理`、`进行中`、`已完成`、`失败`、`已跳过`，与其他各处状态圆点遵循的生命周期顺序相同。

### 选择列 {#choosing-columns}

**刷新**旁边的 **▥** 按钮会列出表格可以显示的所有列：

- **全部显示** / **全部隐藏**可一次切换所有列；**恢复默认**则回到预设的列组合。
- 有些列一开始是隐藏的，以便把宽度留给重要的列，例如 MCP 服务器的传输方式、密钥的引用、代理技能的引用和修订版本、用户的电子邮件和验证标志。
- 标识列和操作列始终显示，因此不会列出。
- 您的选择按表格保存在浏览器中，重新加载后依然有效。系统只保存您与默认设置不同的部分，因此以后添加到表格的列仍会按其预定的默认状态出现。
- 隐藏正用于排序或筛选的列时，该排序或筛选会被清除，这样屏幕上的行就绝不会被页面上看不到的条件所限制。

面板始终能完整显示在屏幕内：下方空间不足时向上打开；列表在内部滚动，批量切换按钮始终可见；可切换的列超过八个时分成两栏。因此，即使是有十七列的代理技能，在屏幕较矮的笔记本电脑上也能操作到所有列。

## 详情页面 {#the-detail-screen}

点击标识列中的记录名称可打开其详情页。该页面是这条记录的唯一页面：既显示其属性，也提供它支持的所有操作，包括保存编辑、删除，以及该类型提供的其他操作，例如发布工作流或拉取技能的仓库。页面以**记录自身的名称**而不是操作作为标题。

没有写入角色时，同一页面以只读方式呈现：字段显示为内凹的值而不是输入框，**保存**和**删除**不再出现，**取消**变为**返回**。

[工作流执行](./workflow-executions.md)是以上所有规则的例外。一次运行是历史记录，而不是可编辑的记录，因此点击其行会打开该运行的聊天或只读的任务列表，而不是编辑表单。
