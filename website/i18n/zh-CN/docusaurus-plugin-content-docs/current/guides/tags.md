# 标签

标签是用来分类记录的标记。所有七个可加标签的注册表共用同一套词汇，因此一个 `aws` 标签既能筛选密钥，也能筛选 MCP 服务器。

![流程图：每个租户共用一套标签词汇，应用于七个可加标签的注册表（密钥、MCP 服务器、代理技能、知识库、工作流、工具模拟和用户组）。](./img/tags-vocabulary.svg#gh-light-mode-only)
![流程图：每个租户共用一套标签词汇，应用于七个可加标签的注册表（密钥、MCP 服务器、代理技能、知识库、工作流、工具模拟和用户组）。](./img/tags-vocabulary-dark.svg#gh-dark-mode-only)

在管理侧边栏中打开**标签**即可整理词汇。每个标签都有在租户内唯一的**名称**、可选的**描述**、从固定的八色调色板中选取的**颜色**（任意颜色值会被拒绝），以及默认未勾选的**访问控制**复选框，勾选后标签就从普通标记变成一道门禁（参见[访问控制标签](#access-control-tags)）。

创建或编辑普通标签需要管理员**或**开发人员角色，这与能够写入七种可加标签资源中任意一种的角色并集一致，因此需要标签的人随时都能自己创建。勾选了**访问控制**的标签则不同：只有管理员（或超级管理员）才能创建、编辑其任何字段或删除。开发人员看到的现有访问控制标签完全只读：复选框为固定值，其他字段为纯文本，也没有保存或删除按钮；但仍可以照常创建或编辑普通标签。读取权限与其他所有分区一样保持开放。

## 为记录附加标签 {#attaching-tags-to-a-record}

每条可加标签记录的创建表单和详情页上都有**标签**选择器：当前选择以可移除的彩色胶囊显示在**选择标签…** 按钮上方，因此这个字段的高度取决于所选内容，而不是词汇的多少。

1. 点击**选择标签…**。对话框以自动换行的网格显示全部词汇，每个彩色胶囊都是一个开关。按下的胶囊填充色更深，*并且*前面带有对勾，因此其状态绝不只靠颜色来区分。
2. 如有需要，可缩小网格范围。两种筛选器可以组合使用：名称框，以及一排八个调色板色块，可同时按下任意多个。全部取消按下即为清除状态。
3. 点击**选择**确认，或点击**取消**丢弃这次的选择。选中后又被筛选隐藏的标签仍保持选中。

附加标签由记录自身的写入角色控制，与创建该标签所需的权限无关。

## 按标签筛选 {#filtering-by-tag}

每个可加标签的列表都有**标签**列，显示每条记录的胶囊，其列标题菜单提供多选。此列让每一行都保持一行高：按当前宽度尽量显示胶囊，其余的计入末尾的 `+N` 胶囊。点击它会打开一个对话框，列出该记录的所有标签，悬停在标签上可查看描述。拖动列边缘或隐藏其他列来加宽此列后，被计入的标签会重新显示为胶囊。所选标签之间取**交集**，菜单中也标明为“筛选（全部匹配）”，因此记录必须带有您选择的*每一个*标签，多选一个就会进一步缩小结果。筛选作用于整个数据集，而不只是屏幕上的当前页。

标签与其他列筛选器是相互独立的维度，但在可见性方面遵循同样的规则：通过[列选择器](./admin-ui.md)隐藏**标签**列会清除标签筛选，就像隐藏任何其他列会清除其自身的筛选一样。

## 访问控制标签 {#access-control-tags}

勾选了**访问控制**的标签会限制谁能看到附加了它的记录。它的胶囊在任何地方都带有锁形图标（标签列表的**预览**列、记录的**标签**列以及选择器中），标签列表还会多出一个可供筛选的**访问控制**列。

访问权限取决于您的[用户组](./users-and-groups.md#user-groups)：用户组本身带有标签，您所有用户组的标签会合并计算。

| 记录带有…… | 您能看到它的条件…… |
|---|---|
| 没有访问控制标签（只有普通标签，或没有标签） | 始终可见：普通标签不限制任何内容 |
| 一个或多个访问控制标签 | 您的用户组合起来带有其中**每一个** |

您无权查看的记录就像不存在一样：不会出现在列表中，打开直接链接也会提示找不到。管理员和超级管理员可以看到所有内容：管理员不受任何访问控制标签限制；超级管理员则更进一步，它面向整个平台且不属于任何用户组，因此其他规则也无法约束它。

设置标签时有一条保护规则：**您不能附加您的用户组未带有的访问控制标签。** 保存会被拒绝并报错，因为这样做会让您在下次加载页面时看不到该记录。请先请管理员把您加入带有该标签的用户组。为*用户组*设置标签不受此限，因为管理员正是这样授予访问权限的。

该限制针对的是谁可以打开、编辑、运行或删除记录。记录在幕后使用的内容不受影响：工作流运行时仍会使用生成它的代理技能以及其 MCP 服务器引用的密钥，即使请求者本人无法打开该技能或密钥。

工作流设计是例外：为步骤提供工具，视同您自己使用该 MCP 服务器。无论是在任务模板的 **MCP 工具** 选择器中选择，还是让代表您工作的设计代理操作，您都只能绑定**您自己**能打开的服务器上的工具。带有您的用户组未持有的访问控制标签的服务器不会出现在代理的工具列表中，绑定它也会像服务器不存在一样被拒绝。已由能看到它的人绑定到步骤的工具，在您编辑该步骤时仍会保留，而**放弃更改**会将已发布的绑定恢复原样。

## 工作流执行和审批的标签 {#execution-and-approval-tags}

[工作流执行](./workflow-executions.md)也会显示**标签**列和字段，其所属的[审批](./approvals.md)同样如此，但都是只读的，也不在上述七个可加标签的注册表之内。运行开始时，会复制其工作流当时带有的标签；之后重新设置工作流的标签或删除工作流，都不会改变已开始运行所显示的内容。这两个界面上没有**标签**选择器，其列表也没有标签筛选器，附加和移除标签仍在工作流本身上进行。

以这种方式复制的访问控制标签仍会像限制工作流一样限制运行及其审批：如果您的用户组不再带有运行所复制的某个标签，那么该运行及其下的每个审批都会从您的列表和直接链接中消失，即使运行是您自己发起的，或者您是其指定的审批人。您在运行内能做的所有操作也是如此：在其聊天中发送消息、打开其任务、批准或驳回其下的审批，都会像运行不存在一样失败。与任何访问控制标签一样，只有管理员或超级管理员不受限制。标签必须在工作流运行*之前*附加到工作流上；之后重新设置工作流的标签绝不会影响已开始的运行，因为复制只在运行开始的那一刻发生一次。

复制到运行的访问控制标签还决定了它可以[请求谁审批](./approvals.md#human-approval)：指定某个人时，要求其所在的某个用户组带有运行的所有此类标签；指定[用户组](./users-and-groups.md#user-groups)时，要求该用户组本身带有这些标签。否则请求会被拒绝，因为该人员或用户组根本看不到它，也就无法作出决定。作为个人目标时，管理员不受此限，因为管理员在其他场合也会绕过这些标签；用户组没有这种例外，即使其成员中有管理员也一样。

## 重命名和删除 {#renaming-and-deleting}

**重命名随时都是安全的。** 记录通过身份而不是名称引用标签，因此带有该标签的每条记录都会跟随新名称，无需重新同步。标签之所以要预先注册、而不是在每条记录上自由输入，正是这个原因。

**删除**标签则相反：不会因为有记录带着它而受阻，而是从所有这些记录上移除。确认提示也会说明这一点。删除勾选了**访问控制**的标签需要管理员或超级管理员，与编辑时相同；删除普通标签仍向开发人员开放。
