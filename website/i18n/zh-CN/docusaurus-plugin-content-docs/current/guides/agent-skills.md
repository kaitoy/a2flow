# 代理技能

代理技能是代理掌握的能力，保存在 Git 仓库中。A2Flow 维护一个技能目录：每条记录指定一个仓库，A2Flow 会克隆它并使克隆保持最新。

在管理侧边栏中打开**代理技能**即可管理该目录。

技能只有在发布了修订版本之后才能使用。在此之前，基于它生成或运行工作流的操作都会被拒绝。

## 技能记录包含的内容 {#what-a-skill-record-holds}

| 字段 | 说明 |
|---|---|
| **名称** | 在其他所有地方用来称呼该技能的名称。 |
| **仓库 URL** | 要克隆的仓库。 |
| **仓库路径** | 技能不在仓库根目录时，它在仓库内的位置。 |
| **引用** | 可选。用于固定每次克隆和拉取的分支名或标签名。留空则使用仓库的默认分支。 |
| **描述** | 自由文本。 |
| **认证用户名** / **认证密码** | 用于私有仓库，详见下文。 |
| **标签** | 用于分类该技能的[标签](./tags.md)。 |

## 状态和修订版本 {#status-and-revision}

列表页和详情页显示两项状态，它们的含义不同：

| 列 | 含义 |
|---|---|
| **状态** | *最近一次*克隆或拉取的结果：`克隆中`、`就绪`，或附带原因的 `失败`。 |
| **修订版本** | 当前发布的修订版本。只有设置了此项，技能才能运行。 |

两者有意相互独立：拉取失败**不会**清除已发布的修订版本，因此原本正常工作的技能会继续以原有的修订版本工作。只有状态和错误信息会改变。

## 拉取 {#pulling}

**拉取**会按配置的**引用**重新克隆仓库，未设置时则使用默认分支。技能通过它获取上游的更改；修正 URL 或凭据后，也通过它重试失败的注册。分支尖端移动或标签重新指向后，下次拉取技能时就会获取这些变化。

仓库树中任何位置只要包含**符号链接**，就会被拒绝：克隆或拉取会失败，失败原因中会指出该链接，也不会从中发布任何修订版本。请将链接替换为其所指文件的副本。

每个已发布的修订版本只要仍有需要就会保留，而且工作流执行始终固定在其启动时的修订版本上，因此拉取绝不会改变进行中的运行所遵循的内容。存储位置和保留策略见[配置参考](../operations/configuration.md#agent-skill-store)。

## 私有仓库 {#private-repositories}

凭据不在技能表单中直接输入。请先将其注册为[密钥](./secrets.md)，然后让技能指向其中的一个条目：

1. 设置**认证用户名**。默认值为 `x-access-token`，适用于 GitHub 个人访问令牌；对于需要真实账户名的托管服务，请填写真实账户名。
2. 在**认证密码**的第一个下拉列表中选择**密钥**，然后在第二个下拉列表中选择其中的一个**条目键**。克隆仓库时，该条目的值将用作密码。

使用**认证密码**时，**仓库 URL** 必须以 `https://` 开头。如果是 `http://`，保存会被拒绝，因为密码将以未加密的方式在网络上传输。

两种类型的密钥都可以选择。Vault 密钥的条目键不存储在本地，因此会直接从 Vault 实时读取。

引用以名称和键的形式存储，并在克隆时解析。因此，之后删除或重命名该密钥并不会立即失败，而是会导致下一次拉取失败，并在技能上记录原因。详情页不会悄悄丢弃已无法解析的引用：它仍保持选中状态，标记为 `（未找到）` 并显示警告。是否清除由您决定。

## 基于技能生成工作流 {#generating-a-workflow-from-a-skill}

每行的操作列中都有**生成工作流**，技能详情页的页眉中也以图标按钮的形式提供同一操作。两者打开同一个对话框，并且在技能发布修订版本之前都处于禁用状态。参见[生成工作流](./workflows.md#generating-a-workflow)。

## 查看 SKILL.md {#viewing-skillmd}

技能详情页的页眉中有一个**查看 SKILL.md** 图标按钮。它会打开一个对话框，呈现仓库中写就的技能说明文件。与生成工作流一样，它在技能发布修订版本之前处于禁用状态，因为只有克隆成功后该文件才存在。与上述写入类操作不同，没有开发人员角色的查看者也可以使用它。
