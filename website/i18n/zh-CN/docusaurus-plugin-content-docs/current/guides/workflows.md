# 工作流

工作流是可复用的工作单元：一个[代理技能](./agent-skills.md)加上一份**预先设计的任务列表**，即*任务模板*。模板在任何运行*之前*就已确定，因此执行工作流会立即开始工作，而不必每次都重新设计相同的步骤。

在管理侧边栏中打开**工作流**即可管理。

![流程图：由代理技能生成工作流，经调整形成草稿，发布后作为工作流执行运行。](./img/workflows-lifecycle.svg#gh-light-mode-only)
![流程图：由代理技能生成工作流，经调整形成草稿，发布后作为工作流执行运行。](./img/workflows-lifecycle-dark.svg#gh-dark-mode-only)

无法创建空白工作流：工作流只能从技能生成。

## 状态 {#statuses}

![工作流详细状态的状态机图：生成中变为草稿或失败，失败可重新编写后回到草稿，草稿发布后变为已发布，已发布和已修改随着进一步编辑和发布相互切换，两者都可以停用回到草稿。](./img/workflows-status.svg#gh-light-mode-only)
![工作流详细状态的状态机图：生成中变为草稿或失败，失败可重新编写后回到草稿，草稿发布后变为已发布，已发布和已修改随着进一步编辑和发布相互切换，两者都可以停用回到草稿。](./img/workflows-status-dark.svg#gh-dark-mode-only)

| 状态 | 含义 | 谁可以运行 |
|---|---|---|
| `生成中` | 后台设计运行仍在编写任务模板。 | 无人 |
| `草稿` | 设计已存在，但从未发布过，或已被停用。 | 开发人员和超级管理员，用于发布前测试 |
| `失败` | 设计运行结束但未生成模板。原因显示在详情页和设计聊天中。 | 无人 |
| `已发布` | 设计已冻结，可以执行。 | 持有请求者或更高角色的任何人 |
| `已修改` | 曾经发布，之后被编辑。运行仍使用已发布版本。 | 与 `已发布` 相同 |

只有**开发人员**、**审阅者**或**超级管理员**才会看到 `已修改` 状态。对其他人而言，该工作流显示为 `已发布`，展示最后一次发布时记录的名称、描述和任务模板：未发布的编辑不是他们该看的，而他们*能*看到的设计正是他们的运行将执行的设计。

## 界面 {#the-screens}

| 界面 | 进入方式 | 可执行的操作 |
|---|---|---|
| **工作流**列表 | 管理侧边栏 → 工作流 | 浏览、按[标签](./tags.md)筛选、**运行**工作流 |
| 工作流详情 | 点击工作流名称 | 编辑字段、**放弃更改**、**打开设计会话**（开发人员）；**发布**、**停用**（审阅者） |
| **任务模板** | 工作流详情页上的“任务模板”链接 | 手动添加、编辑和重新排序步骤，可用“表格”或“图表”方式 |
| 设计会话 | 详情页上的**打开设计会话** | 与设计代理对话来完善步骤 |

每条工作流记录都包含**名称**、用于分类的[标签](./tags.md)、遵循的**代理技能**、状态、**描述**和两个提示词字段。

## 生成工作流 {#generating-a-workflow}

可以从两个位置打开**生成工作流**，两者都在不离开页面的情况下打开同一个对话框：[代理技能](./agent-skills.md)列表中的行操作，以及技能详情页页眉中的“生成工作流”图标按钮。在技能发布修订版本之前，两者都处于禁用状态。

1. 填写**工作流名称**（预填技能名称）和描述工作内容的**提示词**。还可以在**知识库**下选择[知识库](./knowledge-bases.md)：它们会立即关联到新工作流，因此设计代理马上就能在其中查找内容。由于生成会跳转页面，详情页会先询问是否保存未保存的编辑；拒绝则页面保持不变，也不会生成。
2. 工作流会立即以 `生成中` 状态注册，您会进入其详情页，该页面在处理期间会自动刷新。
3. 在后台，提示词作为工作流**设计会话**的第一条消息发送。设计代理按照技能将请求拆分为步骤，并将其注册为工作流的任务模板：这是一张依赖图，每个步骤声明哪些步骤必须先于它完成，以及它需要的 [MCP 工具](./workflows.md#mcp-tools-for-tasks)。
4. 运行结束后，设计对话被总结为**生成提示词**，同时为运行工作流的人写一段简短的**描述**，状态变为 `草稿`，并由一条[通知](./notifications.md)直接链接回该工作流。

如果运行失败，或者结束时连一个模板也没有注册，工作流会进入 `失败` 状态并附上原因，同时发出通知。设计聊天仍可使用：从那里或从“任务模板”管理页面编写任务模板，就能将工作流恢复为 `草稿` 并清除失败状态。

您在“生成工作流”对话框中输入的请求不会存储在工作流上。它作为设计对话的第一条消息保留下来，生成的摘要则延续其意图。

## 描述和提示词 {#description-and-prompt}

工作流包含两类文本，其中只有一类会影响运行。

| 字段 | 内容 | 编写者 | 谁可以编辑 | 谁可以查看 |
|---|---|---|---|---|
| **描述** | 对工作流用途的简单说明。任何运行都不会读取。 | 生成工作流时由 AI 编写，之后由人编写 | 任何开发人员 | 能打开该工作流的所有人 |
| **提示词** | 覆盖生成提示词 | 人，通常是手动编辑 AI 的摘要 | 任何开发人员 | 管理员、开发人员、审阅者 |
| **生成提示词** | AI 对设计对话的摘要 | AI | 仅超级管理员 | 管理员、开发人员、审阅者 |

生效的提示词会作为上下文交给每次运行的执行代理：**提示词**非空时优先使用，否则使用**生成提示词**。由于覆盖内容通常最初是摘要的副本，提示词字段提供**显示与生成提示词的差异**操作，可打开两者之间的逐词差异。它读取的是表单中的当前值，因此未保存的编辑也会参与比较。

工作流列表显示的是描述，**运行工作流**对话框也会在确认文字下方显示它，这样启动运行的人就能确认自己选对了。提示词字段对其他所有角色隐藏，包括详情页、列表中可选的**提示词**列，以及运行的详情页。

### 重新生成提示词 {#regenerating-the-prompt}

随着任务模板不断调整，AI 摘要会过时，因此**生成提示词**提供**根据设计对话生成**操作，可按需重新总结设计对话，并立即保存结果。发布时不会进行任何总结：是否刷新以及何时刷新由您决定。

设计会话的聊天输入框的“+”菜单中也提供相同的操作，它会在保存前通过相同的差异对话框预览更改，便于不离开对话就重新生成。任务模板仍在生成时，此菜单会隐藏。

两者都是开发人员的操作。重写 `已发布` 工作流的摘要会使其变为 `已修改`，因为提示词为空的运行会回退到摘要，否则就会与已发布版本产生偏差。

## 调整任务模板 {#adjusting-the-task-templates}

草稿的任务模板可以通过两种方式完善，也可以任意组合。

**通过聊天**。工作流详情页上的**打开设计会话**会打开设计聊天：与运行相同的聊天，左侧边缘是模板列表，由直接编辑模板的设计代理驱动。设计代理从不执行任何操作。该会话由租户中的所有**开发人员**共享，超级管理员和工作流创建者也可参与，因此团队可以一起完善设计，其共享聊天行为与[工作流会话](./workflow-executions.md#the-workflow-session-screen)相同，包括每条消息的发送者头像。**审阅者**可以打开同一聊天，在决定是否发布前阅读其历史记录，但消息框是隐藏的：审阅设计并不包括引导设计。

**手动**。**任务模板**页面提供**表格**和**图表**视图、创建表单，以及每个模板的详情页，其中有**依赖于**和 **MCP 工具**选择器。图表按依赖顺序将模板堆叠成一个垂直列，每个模板向右分支到其绑定工具所属的 MCP 服务器，再分支到各个工具。

模板在结构上与运行的任务相同（标题、描述、依赖边和工具绑定），但**没有状态**：生命周期属于运行，而不属于设计。依赖必须指向同一工作流的模板，会形成循环的依赖边会被拒绝。

## 发布 {#publishing}

工作流详情页上的**发布**使工作流可以执行。这是**审阅者**的操作：开发人员构建和编辑工作流，但不再发布它，因此推广设计的人与编写设计的人不是同一个人。发布要求至少有一个模板，且没有正在进行的生成。

发布会**冻结设计**：工作流的名称、描述、生效的提示词及其完整的模板列表（包括依赖边和工具绑定）被记录为一个新的已发布版本，即 **v1**、**v2**，依此类推。更早的版本保留在[版本历史记录](#version-history)中。此处不运行 AI；刷新摘要是[单独的操作](./workflows.md#regenerating-the-prompt)。您可以随意多次调整并重新发布：已启动的运行不受影响，因为每次运行都有自己的任务副本。

## 编辑已发布的工作流 {#editing-a-published-workflow}

工作流发布后再编辑，不会悄悄改变实际运行的内容。保存详情表单、重新生成 AI 提示词，或者添加、编辑、删除任务模板（包括设计代理在聊天中所做的更改），都会使工作流变为 `已修改`。

| `已修改` 期间 | |
|---|---|
| 运行使用的内容 | **最后发布的版本**：其名称、生效的提示词和模板，而不是编辑内容，除非开发人员主动选择（请参阅[试用编辑内容](#trying-the-edits-out)） |
| 谁可以运行 | 与 `已发布` 时相同；“运行”按钮的限制没有区别 |
| 谁能看到编辑内容 | 仅开发人员、审阅者和超级管理员 |
| **发布**（审阅者） | 将编辑内容推广到今后的运行以及其他所有人看到的内容中 |
| **放弃更改**（开发人员） | 丢弃编辑内容：根据已发布版本重写模板，恢复名称和描述，写回已发布版本的提示词，工作流回到 `已发布` |

**放弃更改**是详情页状态栏中“发布”旁边的撤销图标。对没有未发布更改的工作流执行放弃，除了提示这一点外不会有任何作用。

没有开发人员或审阅者角色的所有人看到的始终是已发布版本：列表和详情页上工作流的名称和描述、其**任务模板**界面，甚至列表中按名称搜索匹配的内容也是如此。其状态显示为 `已发布`，上次发布后添加的任务模板对他们来说根本不存在。因此，尚未完成的重新设计绝不会让只需运行工作流的人感到困惑，他们看到的内容也始终与其运行将执行的内容一致。

## 版本历史记录与回滚 {#version-history}

每次发布都会保留。**版本历史记录**（工作流详情页页眉中的时钟图标）按从新到旧列出各版本，包括版本号、名称、描述，以及发布的时间和发布者。只有**管理员**、**开发人员**、**审阅者**或**超级管理员**可以浏览；请求者或审批人根本看不到时钟图标。

要回滚到早期设计（开发人员）：

1. 打开**版本历史记录**，在所需版本上点击**恢复**。
2. 确认。该版本的模板、名称、描述和提示词会替换工作流的当前设计，然后返回工作流。
3. 检查结果。恢复**不会**发布：在审阅者点击**发布**之前，运行继续使用当前的已发布版本；点击后，恢复的设计会记录为新版本。

| 恢复前的状态 | 恢复后的状态 |
|---|---|
| `已发布` 或 `已修改` | `已修改`；如果恢复的是最新版本，则为 `已发布`，因为此时没有未发布的内容 |
| `草稿` | `草稿` |

发布前改变主意了？**放弃更改**可以恢复当前的已发布版本。如果某个版本绑定的工具所在的 MCP 服务器已被删除，则该版本无法恢复，恢复会被拒绝并显示错误。

### 内部备注 {#internal-notes}

工作流详情页上的**内部备注**可用于记录回滚原因，或运行该工作流的团队应当了解的其他任何事项。

| | |
|---|---|
| 谁可以查看 | 管理员、开发人员和审阅者。对其他人隐藏。 |
| 谁可以编辑 | 同样这三个角色。在字段中输入内容并点击其保存图标。 |
| 对工作流的影响 | 无。保存不会更改状态，运行也不会读取备注。 |
| 版本 | 不做版本管理。发布、恢复版本和**放弃更改**都不会改动备注。 |

## 停用工作流 {#deactivating-a-workflow}

**停用**是工作流处于 `已发布` 或 `已修改` 状态时出现在“发布”旁边的电源图标，与“发布”一样由**审阅者**角色使用，它会将工作流退回 `草稿`。这会撤销请求者角色的执行权限，即从未发布过的工作流一开始就有的同一道限制，而开发人员或超级管理员仍可运行它进行测试。任务模板、两个描述字段和已发布快照都保持原样，因此再次发布可直接恢复。

## 运行工作流 {#running-a-workflow}

在工作流列表中点击**运行**会创建一个**工作流执行**：一条独立的记录，捕获工作流此刻的快照。

![流程图：已发布的工作流及所选工具模拟按值复制到新的工作流执行快照上，该快照打开工作流会话。](./img/workflows-snapshot.svg#gh-light-mode-only)
![流程图：已发布的工作流及所选工具模拟按值复制到新的工作流执行快照上，该快照打开工作流会话。](./img/workflows-snapshot-dark.svg#gh-dark-mode-only)

对于**测试运行**，运行对话框还会在**模拟工具**下列出此工作流的某个任务所用工具的[工具模拟](./tool-mocks.md)，以及内置工具的所有模拟；勾选后，该工具在此次运行中被模拟，因此发布前的测试可以重复进行，而不会产生工具的副作用。测试运行指运行 `草稿` 工作流，或 `已修改` 工作流的未发布的编辑（见下文）。其他情况下对话框不提供模拟，强行要求也会被拒绝：看似真实却悄悄什么都没做的运行，比没有运行更糟。

### 试用编辑内容 {#trying-the-edits-out}

工作流处于 `已修改` 状态时持有两份设计，因此运行对话框会询问**开发人员**要运行哪一份：

| 选项 | 运行的内容 | 记录方式 |
|---|---|---|
| **已发布版本** | 最后一次发布时记录的设计，也就是其他所有人得到的内容 | 真实请求 |
| **未发布的编辑** | 编辑器中当前的设计 | **测试运行**：可以模拟工具，且不计入[运维指标](../operations/metrics.md) |

默认选中已发布版本，因为在这里真实请求指的就是它。选择编辑内容是在正式采用之前对重新设计进行端到端演练的方式，这是开发人员的操作，因为其他人本来就看不到这些编辑。对于 `草稿` 或 `已发布` 工作流不会出现此选项：只有一份设计可以运行。

运行所需的一切都会在启动时复制到执行上，因此之后的编辑绝不会影响到它：

| 复制到运行上的内容 | 来源 |
|---|---|
| 名称和生效的提示词 | 最后发布的版本；对于 `草稿` 工作流，或开发人员选择了未发布的编辑时，则为编辑器的当前状态 |
| 任务模板，作为带有依赖关系和工具绑定的 `待处理` 任务 | 相同的设计 |
| 运行所固定的代理技能修订版本 | 技能的已发布修订版本 |
| 所选的工具模拟，按值复制 | 当时的模拟内容 |

随后您会进入**工作流会话**，即运行所在的聊天。它以固定的启动消息开始，代理立即开始工作：任务已通过发布获得批准，因此无需先行确认。之后，运行的表现与任何聊天一样，包括渲染的交互界面及其中的按钮。[工作流执行](./workflow-executions.md)指南介绍了该界面。

### 代理如何处理任务 {#how-the-agent-works-through-the-tasks}

执行代理列出运行的任务，选择下一个可运行的任务（依赖全部完成的 `待处理` 任务），将其标记为 `进行中`，按照技能的指示完成工作，再将其标记为 `已完成`、`失败` 或 `已跳过`。当所有任务都进入终止状态时，一条[通知](./notifications.md)会告知运行已完成。

您可以在运行的只读**工作流任务**视图中实时查看状态更新，可用表格或图表方式。运行的任务列表是固定的，即发布工作流时冻结的列表，因此代理只会推进每个任务的状态，绝不会添加或移除任务。

**必须等待某个时间的任务**。用直白的文字把要求写进任务的描述，例如“明天 9:00 之后运行”“不早于当月 1 日”。当代理在时间未到时到达该任务，会将任务保留为 `待处理`，在聊天中说明运行何时继续，然后停止。在此之前其会话显示**已计划**，到时 A2Flow 会自动恢复它，无需任何人打开聊天。未写明时区的时间按部署的本地时区解读。一个会话等待时，其他会话处理的分支会继续推进；向等待中的会话发送消息会让它立即恢复。

## 任务的 MCP 工具 {#mcp-tools-for-tasks}

任务可以使用在 [MCP 服务器](./mcp-servers.md)下注册的服务器提供的工具。工具在设计时绑定，在执行时强制检查。

设计时，代理可以列出您可见的服务器所提供的工具（被[访问控制标签](./tags.md)对您隐藏的服务器不在其中），并为步骤分配所需的工具。这些绑定保存在模板上，并在运行启动时复制到运行的任务上。

执行时，每次调用在到达服务器之前都会经过检查：其 `(服务器, 工具)` 组合必须绑定到当前正在进行的任务。对未绑定工具的调用会被拒绝，并附带列出允许工具的消息，因此在多个工作流之间共享的代理绝不可能使用任务未获授予的工具。同时附加了[审批](./approvals.md)的任务还要受审批的限制。

**手动绑定工具**。模板表单提供 **MCP 工具**选择器，分两步操作：通过分页对话框选择服务器，然后从下拉列表中添加其工具，每个添加的工具都会变成可移除的胶囊。只会查询所选的服务器，因此打开表单不会访问所有已注册的服务器；无法访问的服务器会在工具列表的位置给出提示，已绑定的工具无论如何都保留其胶囊。已绑定的工具在任务模板和工作流任务列表的**工具**列中显示为胶囊。

**无需输入审批的工具**。**已选工具**下每个工具的胶囊都在移除按钮旁带有一个小盾牌按钮。点击后，调用该工具所用的值就不再属于涵盖该步骤的[审批](./approvals.md)要求人同意的内容；审批本身仍然适用，步骤仍会等待审批。按钮的图标和颜色会变化以显示工具的当前状态，将鼠标悬停其上会说明当前状态以及点击后的效果。

只对**读取**型工具点击它：列表、查询、状态检查。这一功能的存在有两个原因，都与只读工作有关：

| | |
|---|---|
| 没有什么需要权衡 | 对不做任何更改的查询，无需有人同意其参数 |
| 值尚无法得知 | 步骤可能要先查询才能决定下一步，因此无法预先说明要请求什么 |

对写入、删除、产生费用或发送内容的工具，请保持默认状态。默认为“需要审批”，因此添加后不作改动的工具，其输入仍受限制。切换为“无需审批”的工具，在运行之后请求的审批上会标记为**任意输入**，这样审批人能看到哪些工具未受限制，而不必自行推断。

**询问发起人的工具**。有些工具会在调用中途停下来，向运行工作流的人提问，例如 Azure MCP Server 在每次操作密钥前都会征求同意。在生成工作流时的提示词中或其设计会话中，告诉设计代理哪个任务的工具会这样做，它就会将该工具标记为询问型。带有此类工具的步骤在启动前会等待发起人继续，这样发起人就在聊天中可以回答（[来自 MCP 服务器的确认](./workflow-executions.md#mcp-server-confirmations)）。未这样标记的工具不允许询问。管理表单中没有用于此标记的控件，它会保留设计代理设置的内容。在运行的任务时间线中，**已绑定的工具**对话框将此类工具标记为**在调用过程中询问发起人**。

**任务标题**。上述两个列表都显示所有记录而不分页，这使**依赖于**列可以用作交叉引用：每个依赖项以其标题命名，将鼠标悬停在该胶囊上会高亮显示它指向的行。设计代理必须使用简洁的祈使式标题（2 到 4 个词，50 个字符），这样作为胶囊时清晰易读；过长的标题会被拒绝，并附带提示，让它把细节移到描述中。此限制只约束代理，不约束人：通过管理表单编辑的标题最多可达 200 个字符，超出胶囊的标题会被截断，悬停时显示完整内容。

## 知识库 {#knowledge-bases}

在工作流详情页的**知识库**下选择知识库并点击**保存**，设计代理和执行代理在工作时就会在其中查找内容，详见[知识库](./knowledge-bases.md#linking-a-knowledge-base-to-a-workflow)。此选择不属于已发布的设计，因此更改它绝不会将工作流标记为已修改。

## 删除工作流 {#deleting-a-workflow}

删除工作流也会删除其任务模板、已发布版本和设计会话。现有的[工作流执行](./workflow-executions.md)会保留：每个执行都有自己的快照，因此即使来源工作流已不存在，运行历史仍可阅读。
