# 审批

审批是让运行停下来等待人工的方式。代理在执行途中请求审批，指定的审批人在聊天中作出决定，这一决定将解锁它所涵盖步骤的工具。

## 人工审批 {#human-approval}

当任务需要在代理行动前获得明确许可时（例如破坏性或不可逆的操作），代理会请求审批并暂停。

### 谁会收到请求 {#who-is-asked}

每个请求都只发送给**唯一一个目标**，不会同时发给两者，也不会两者都不发。

| 目标 | 谁会收到通知 | 谁可以作出决定 |
|---|---|---|
| **单个用户** | 仅此人 | 仅此人 |
| **[用户组](./users-and-groups.md#user-groups)** | 拥有审批人角色的每位成员，各自收到通知 | 其中任何一人，以**第一个**决定为准 |

以用户组为目标，审批就不会因某一个人没空而受阻。如果用户组中没有能够审批的成员，请求会被直接拒绝，因为这样的请求永远无法得到决定；如果目标不具备运行本身带有的全部[访问控制标签](./tags.md#execution-and-approval-tags)，请求同样会被拒绝，因为目标永远看不到这个请求，也就无从决定。有人作出决定后，其他成员的通知不会被清除，只是无法再据此操作。实际作出决定的人会被记录下来，因为仅凭用户组名称无法回答“这是谁批准的？”。

代理收到的指示是：只要团队中任何成员都可以决定，就优先指定用户组；技能要求特定人员时，则指定单个人。

### 作出决定 {#deciding}

代理以纯文本说明请求，控件显示在其下方的聊天中，但**仅向指定的审批人显示**。如果目标是用户组，可能有多人同时看到这些控件。其他人看到的是只读的“等待”消息。

作出决定之前，您可以就请求向代理提问。在聊天中输入问题，就会开启一次[咨询](./workflow-executions.md#consultations)，由代理回答，发起此次运行的人也可以加入。作出决定后咨询关闭。

| 决定 | 含义 | 代理的行为 |
|---|---|---|
| **批准** | 可以继续 | 继续执行，所涵盖步骤的工具已解锁 |
| **驳回** | 不要这样做 | 将任务标记为 `失败` 或 `已跳过` |
| **退回** | 修改后再次请求 | 将工作退回，而不是了结该请求 |

无论在何处作出决定（在聊天中，或在[审批](#browsing-approvals)列表中），运行都会立即恢复，即使没有人打开该运行的聊天也是如此。在控件出现之前作出的决定也不会丢失：运行一到达该节点就会获取它。

**退回**是与另外两种决定并列的第三种决定，而不是驳回的变体：退回率高说明上游存在质量问题，而不是说明这些工作根本不该被请求。

每项决定都可以附带一条可选的**评论**。决定本身是**最终的**：审批组的两名成员确实可能互相抢先，因此会改变已记录决定的第二个决定会被拒绝，而不会覆盖原决定。之后仍可以编辑评论，这不会改变已记录的决定人和决定时间，因此从请求到决定的周转时间仍然是审批人的真实用时。

只有指定的审批人才能作出决定，**没有任何例外，即使是超级管理员**，只要不是被指定的对象，也不能决定。同样的规则也适用于任务状态：更改任务状态（无论是手动更改，还是请执行代理更改）仅限于发起此次运行的人，以及**涵盖该任务**的审批的审批人。审批人可以推进其决定所涵盖的步骤（审批指定的任务及其后直到下一个审批之前的所有步骤），审批因此才能恢复运行；但不能推进其被请求审批范围之外的任务，否则此次运行的任何审批人都可以代替被指定的审批对象。

### 请求授权的内容 {#what-a-request-authorizes}

请求不只是一句供您同意的话。在**这将授权**下方，它列出了将会允许的每个调用：工具，以及该工具每个输入允许取的值。您要决定的正是这份列表，之后服务器也据此约束运行。

输入的范围以下列五种方式之一表示：

| 显示为 | 含义 |
|---|---|
| `等于 "ap-northeast-1"` | 恰好是该值，不能是其他值 |
| `为 ["t3.micro", "t3.small"] 之一` | 所列值中的任意一个 |
| `不大于 2` | 不大于该值的数字 |
| `不小于 8` | 不小于该值的数字 |
| `匹配 "^dev-"` | 符合该形式的文本，这里指以 `dev-` 开头的任何文本 |

标记为**可选**的输入可以省略；列出的其他输入都必须提供。**根本未列出的任何内容都会被拒绝**，因此运行无法偷偷加入您从未看到过的输入。

请在决定前阅读这些范围，并把宽泛的范围视为宽泛的决定：工作只需要两台时却批准 `不大于 100`，等于授予了一百台服务器的权限。如果范围超出工作所需，请**退回**请求并说明情况，代理可以用更窄的范围再次请求。

标记为**任意输入**的调用是唯一的例外。工作流的设计说明该工具只读取（例如列出或查询），因此请求不要求您同意调用时使用的值，运行可以按需使用任何值调用它。其他方面都没有变化：它仍在您的决定范围内，在您授予之前不能调用。如果以这种方式显示的工具看起来可能会更改内容，这就是**退回**请求并加以询问的理由。

请注意不要理解反了。列出时下方**没有**任何输入的调用，含义正好相反：该工具可以调用，但不能带任何输入。

完全不授权任何工具调用的请求不会显示这样的列表。这种审批针对的是 A2Flow 本身不执行的操作，例如同意某份通知的措辞。

### 审批解锁的内容 {#what-approval-unlocks}

**审批门禁由服务器强制执行，而不是由代理执行。** 审批涵盖的步骤在获得批准之前，不能调用任何已绑定的 [MCP 工具](./mcp-servers.md)，调用在到达服务器之前就会被拒绝。每个被涵盖的步骤在开始时都会获得一张短期有效的**证书**，此后它的每次工具调用都必须出示该证书。

每个步骤都需要这样的证书，而不只是请求过审批的步骤。任何审批都未涵盖的步骤，会在被标记为**进行中**的那一刻，凭发起此次运行之人的权限获得证书。因此，记录中总能看到工具调用是代表谁发起的，不存在无法归属的工具调用途径。审批只是用审批人自己的权限取而代之。

这带来了几点仅靠对模型下达指令无法实现的保障：

- **提示词注入或缺陷都无法跳过审批。** 门禁是服务器检查的规则，而不是代理指令里的一句话加上一个拒绝恢复运行的前端。
- **授予的工具被冻结。** 证书中包含其步骤开始时绑定的工具，而被涵盖步骤的工具也完全无法再编辑。运行的步骤及其工具来自工作流已发布的设计，代理无法更改，因此决定之后发生的任何事情都无法扩大授权。批准读取文件的步骤，不会变成批准删除文件。
- **批准的参数也被冻结。** 请求还带有它授权的调用（每个工具及其可用值的范围），这正是决定之前请求向您展示的内容。之后的每次调用都要与之核对，因此批准“在东京启动一台小型服务器”绝不会变成批准在别处启动十台大型服务器。参见[请求授权的内容](#what-a-request-authorizes)。

**一项决定涵盖的范围**是请求指定的步骤，**以及其后直到下一个审批之前的每个步骤**。工作流通常把请求显示为单独的一个步骤（“请求审批”之后是“启动实例”），一项决定就能涵盖两者，因此同一项工作的每个步骤都不必再次询问审批人。有两点值得了解：

- 两个已批准的分支汇合时，汇合处的步骤需要**两个**决定都到位后才能行动。
- 请求之前的任何内容都不在其涵盖范围内。审批只对之后的步骤生效。

每个已判定的工具调用，无论允许还是拒绝，都会连同其出示的证书一起记录在运行的[工具调用](./workflow-executions.md#tool-invocations)页面上，因此事后可以回答“谁授权了此操作，依据是什么”。

这些都无需配置；证书的有效期可在[配置参考](../operations/configuration.md#mcp-tools-and-approvals)中调整。

> **保证的范围。** MCP 网关目前运行在后端进程内，因此证书只是向共享该进程的验证方证明持有关系，并不能防御已经控制后端的攻击者。它提供的是单一的失败即关闭（fail-closed）强制执行点、事后无法扩大的授权，以及可验证的记录。

## 浏览审批 {#browsing-approvals}

在管理侧边栏中打开**审批**可浏览所有审批请求。此视图仅供查看：决定要通过聊天中的**批准** / **驳回** / **退回**控件作出。

| 列 | 默认显示 |
|---|---|
| 标题、状态（`待处理` / `已批准` / `已驳回` / `已退回`）、描述、创建时间 | 是 |
| 工作流执行：指向其来源运行的链接 | 是 |
| 标签：只读，所属工作流执行的标签（参见[工作流执行和审批的标签](./tags.md#execution-and-approval-tags)） | 是 |
| 决定人：用户或审批组的名称，链接到其页面 | 通过列选择器 |
| 审批人的评论和决定时间 | 通过列选择器 |

每行还带有**打开工作流会话**操作，可直接跳转到该运行的聊天，与[工作流执行](./workflow-executions.md)列表上的操作相同。

已批准审批的详情页还会在**已授权的 MCP 工具**下显示它授权的内容：每个已开始的被涵盖步骤一个条目，各自列出授予的工具、有效期，以及证书是否已被吊销。该面板逐步填充是正常现象：步骤在开始时才获得证书，因此刚批准的审批可能还没有任何内容。工具列表为空的条目也不是故障，它表示该步骤不调用任何 MCP 工具就能完成工作。

**已授权的调用**显示的是审批人在决定前阅读的同一份列表，即请求允许的调用及其输入范围。与上面的面板不同，它在发出请求时就已填充，而不是随步骤开始而填充，之后也不会改变：它记录了这项决定实际针对的内容。在 A2Flow 开始记录这些范围之前作出的审批，此处显示为短横线。

**生效起点**字段指明审批开始生效的步骤。其后直到下一个审批之前的所有步骤也在涵盖范围内。
