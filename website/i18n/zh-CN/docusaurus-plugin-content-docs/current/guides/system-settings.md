# 系统设置

在系统设置中，可以配置发送[通知邮件](./notifications.md#email-delivery)所用的邮件服务器以及全局 HashiCorp Vault。整个部署只有一条设置记录，首次启动时写入，邮件投递为**关闭**状态，因此全新安装在运维人员开启之前，通知只留在应用内。用户打开 A2Flow 的地址不在这里配置，而是由运维人员在部署时设置，请参阅[服务器设置](../operations/configuration.md#server-settings)。

在管理侧边栏中打开**系统设置**。与[租户](./users-and-groups.md#tenants)一样，此分区仅限**超级管理员**使用：这些设置面向整个平台，而不是单个租户，因此没有为租户管理员留出例外，其他任何人甚至连读取都会被拒绝。

## 设置项 {#the-settings}

| 字段 | 用途 |
|---|---|
| **通过电子邮件发送通知** | 总开关。关闭时，通知只留在应用内，不发送任何内容。 |
| **SMTP 主机** / **SMTP 端口** | 用于转交邮件的中继。 |
| **安全性** | **STARTTLS**（默认）、**SSL/TLS**（隐式 TLS）或**无**。 |
| **SMTP 用户名** / **SMTP 密码** | SMTP AUTH 凭据。如果中继不需要认证，请将用户名留空。 |
| **发件人地址** / **发件人名称** | 发件人地址，以及显示在其旁边的可选显示名称。 |

如果没有填写主机或发件人地址，就无法开启投递，因此表单不可能被保存成日后会悄无声息失败的状态。

这里的每个字段也都可以通过环境变量设置，这样部署时就能直接带上邮件配置，而不必留作手动步骤，详见[通知邮件](../operations/configuration.md#notification-email)。这些变量会在每次启动时重新应用，因此以这种方式设置的值会覆盖在此处输入的值。

密码是**只写**的，与[密钥](./secrets.md)和用户密码的处理方式相同：绝不会再显示出来。已存储密码后，该字段显示为空白，并带有“已保存 — 留空则保留”占位提示；留空保存时会保留已存储的密码，而不是清除它。

## 全局 Vault {#global-vault}

全局 Vault 是一个 HashiCorp Vault（仅支持 KV v2），所有**没有自有 Vault** 的租户都从中读取 [Vault 类型的密钥](./secrets.md)。租户管理员可以改在[租户设置](./users-and-groups.md#tenant-vault)中连接租户自有的 Vault，此时始终优先使用后者。

| 字段 | 用途 |
|---|---|
| **全局 Vault 地址** | Vault 的地址，以 `http://` 或 `https://` 开头。与租户自有的 Vault 不同，它可以位于私有网络中。留空并保存即可断开全局 Vault。 |

这里只设置地址，没有共享凭据：每个租户使用**各自的凭据**登录，由超级管理员在租户页面上注册（参见[全局 Vault 凭据](./users-and-groups.md#global-vault-credential)）。没有凭据的租户完全无法读取全局 Vault。

租户之间的隔离**由 Vault 本身**实现：密钥从其指定的 **Vault 挂载点**和 **Vault 路径**读取，而租户凭据所附的策略决定是否允许该读取。请为每个租户签发策略仅覆盖该租户数据的凭据，例如为每个租户创建一个 AppRole，并为 `acme` 租户设置如下策略：

```hcl
path "secret/data/tenants/acme/*" {
  capabilities = ["read"]
}
```

## 检查配置 {#checking-the-configuration}

**发送测试邮件**会使用*已保存*的设置发送一封固定的测试邮件，这样配置错误会立即暴露，而不是等到下次工作流发出通知时才发现。

1. 先保存设置。测试使用的是已存储的内容，而不是屏幕上的内容。
2. 点击**发送测试邮件**。
3. 查看您自己的收件箱。收件人固定为当前登录的超级管理员本人的地址，无法指向其他地址。

中继失败时，页面上会显示错误；根本原因记录在服务器端日志中。
